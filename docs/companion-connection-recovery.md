# 동반 앱 주소 탐색과 재접속

## 사용 조건

PC ENE와 Android 앱을 모두 연결 복구 지원 버전으로 맞춘다. 기존 등록·Core·모델·사용자 설정은 그대로 사용하며 앱 데이터를 지우거나 새 QR로 등록하는 것부터 시작하지 않는다. APK는 사용자 로컬 빌드용이며 공개 배포하지 않는다.

처음 연결하거나 PC 인증서를 명시적으로 초기화한 경우에는 QR 스캔과 PC 승인이 필요하다. 같은 등록을 유지한 PC의 일반적인 재시작이나 IP 변경은 새 QR 없이 복구를 시도한다. 테스트용 `companion_smoke`는 임시 등록을 쓰므로 실제 ENE의 영구 등록 재시작 시험을 대신하지 않는다.

PC 실행 환경에 `requirements.txt`의 `zeroconf==0.151.3`이 필요하다. 기존 환경에 아직 없다면 사용자가 변경본을 반영한 뒤 해당 가상환경에서 설치한다. 개발 검증용 별도 환경을 실행 환경으로 옮기지는 않는다.

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 연결 순서와 안전 경계

1. 앱이 전경에 있고 등록되어 있으면 저장된 주소를 차례로 확인한다.
2. HTTPS 정보 조회뿐 아니라 WSS 연결·서버 준비·최초 전체 대화 동기화가 끝나야 성공으로 처리한다. 도중에 끊긴 후보에 고착되지 않고 다음 주소로 넘어간다.
3. 저장된 주소로 연결되지 않으면 같은 LAN에서 `_ene-companion._tcp` 서비스를 탐색한다. 휴대폰의 현재 비 VPN Wi-Fi와 직접 연결된 IPv4 범위만 후보로 받는다. 서브넷 포트 스캔이나 외부 서버 조회는 하지 않는다.
4. 발견 결과는 주소 단서일 뿐이다. 기존에 등록한 CA·고정 TLS 이름·PC 식별자를 확인하고 나서만 인증 토큰을 보낸다. 다른 기기의 광고나 미확인 인증 거절은 등록을 지우지 않는다.
5. 전체 대화 동기화에 성공한 주소만 저장 목록 맨 앞에 추가한다. 후보는 최대 8개이며 인증 정보는 교체하지 않는다. 주소 저장 실패가 현재 채팅 연결을 끊지는 않는다.

앱의 자동 탐색은 회당 최대 8초, 시작 간격 최소 30초, 결과 최대 8개다. 서비스 해석은 직렬로 최대 2초씩 기다린다. 백그라운드 전환·등록 변경·취소 시 결과 반영을 중단한다. 취소 API가 없는 구형 Android의 진행 중 OS 요청은 늦은 응답을 버리며 중복 요청을 쌓지 않는다.

PC는 TLS 서버가 실행 중이고 휴대폰 등록이 있을 때만 광고한다. 이름은 매 실행 생성한 무작위 값이고 PC 이름·사용자 이름·등록 ID·인증서 지문·토큰·QR 내용은 싣지 않는다. TXT 정보는 `v=1`, `transport=tls_v1`뿐이다. PC 주소는 Qt 스레드에서 15초마다 확인하고, 등록 해제나 서버 종료 시 광고를 회수한다. 광고 실패만으로 TLS/채팅 서버를 종료하지 않는다.

## 연결되지 않을 때

- PC는 유선 LAN이어도 된다. 휴대폰과 같은 개인 LAN에 있고 기기 간 통신이 가능해야 한다.
- 공유기 게스트 Wi-Fi·기기 격리·멀티캐스트 차단은 자동 탐색을 막을 수 있다. UDP 5353과 기존 ENE TLS 포트의 로컬 도달성을 확인한다. 이 기능은 방화벽이나 공유기 설정을 자동 변경하지 않는다.
- VPN·서로 다른 네트워크·IPv6 전용 환경은 이번 자동 탐색 범위가 아니다. 기존 수동 주소 연결은 유지한다. LTE/5G·Tailscale 검증도 별도다.
- 먼저 앱의 `주소 수정`으로 현재 PC 주소를 넣어 본다. 이 작업은 신뢰 인증서를 바꾸지 않는다. 등록 삭제·재설치는 기본 복구 절차가 아니다.
- `연결 진단`에서 현재 단계, 마지막 실패 단계·고정 코드, 탐색/저장 알림을 확인한다. 진단에 실제 대화·QR·토큰을 첨부하지 않는다.

## 이전 앱 종료 진단

Android 11(API 30) 이상에서는 OS가 보관한 자체 메인 프로세스의 이전 종료 사유와 시각만 확인한다. 외부 WebView 프로세스, 현재 실행 중 기록은 제외한다. 상세 설명·스택 추적·로그 파일은 수집하지 않으며 진단을 파일로 저장하거나 전송하지 않는다.

미지원·기록 없음·조회 실패는 서로 구분한다. OS 종료 기록은 충돌 원인을 확정하는 증거가 아니며, 페어링 직후 홈 화면으로 나가는 현상은 실제 기록과 재현 확인 전까지 원인 미확정이다.

## 의존성과 미검증 항목

`zeroconf 0.151.3`의 설치 메타데이터와 `COPYING`은 LGPL-2.1-or-later를 명시한다. 원본 [프로젝트](https://github.com/python-zeroconf/python-zeroconf), [해당 버전 배포 정보](https://pypi.org/project/zeroconf/0.151.3/), [현재 라이선스](https://github.com/python-zeroconf/python-zeroconf/blob/master/COPYING)를 함께 확인한다. 정확한 버전의 조건은 설치한 배포물의 `COPYING`을 기준으로 확인한다. 이 안내만으로 바이너리 재배포 의무나 Live2D 출시 허가를 충족했다고 판단하지 않는다.

자동 검사와 APK 컴파일은 실제 Android NSD·공유기 멀티캐스트·WebView·OS 종료 기록·설치 시험을 대신하지 않는다. 실제 기기 인수와 Live2D 출시 허가 확인은 별도다. API 근거는 [Android NSD](https://developer.android.com/reference/android/net/nsd/NsdManager)와 [zeroconf 비동기 API](https://python-zeroconf.readthedocs.io/en/latest/api.html)를 따른다.
