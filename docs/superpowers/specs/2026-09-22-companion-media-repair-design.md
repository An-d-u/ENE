# 동반 앱 캐릭터 초기화·음성 출력 보완 설계

작성일: 2026-09-22

상태: 사용자에게 제시한 동작 설계가 확정되었고 내부 명세 검토를 완료했다. 구현 계획 작성 전 문서 확인을 기다린다. 이 문서는 구현 전 명세이며, 코드 수정·APK 재빌드·실기기 검증 완료를 뜻하지 않는다.

기준: [기존 캐릭터·음성 확장 설계](2026-09-16-ene-companion-media-design.md), [TLS 설계](2026-09-08-ene-companion-tls-design.md).

## 1. 목표와 범위

1. 모바일 캐릭터의 확인된 Pixi/CSP 초기화 충돌을 수정한다.
2. GPT-SoVITS 스트리밍에서 메시지가 공개되기 전에 출력 경로를 결정해 PC로 고정되는 문제를 수정한다.
3. PC TTS 설정에 `자동 / PC / 휴대폰` 선택을 추가한다. 기본값은 자동이며, 수동 휴대폰 선택에서는 어떤 실패에도 PC로 대체하지 않는다.
4. 선택한 기기와 현재 출력 상태, 재생이 불가능한 이유를 구분해 표시한다.
5. 관련 자동 검증 후 로컬 개발 APK를 재빌드한다.

기존 채팅·TLS·인증·대화 수명·Live2D 상호작용 계약은 유지한다. 캐릭터 표시 실패는 지원되는 음성이나 채팅을 차단하지 않는다. 외부망, 새 코덱, 과거 음성 재생, 여러 휴대폰 동시 출력, Android 내부 오디오 장치 선택은 추가하지 않는다.

기존 Core·모델·설정·사용자 데이터와 APK를 보존한다. Core·모델을 다시 내려받거나 Git에 추가하지 않는다. 새 APK·ZIP·릴리스 공개, 원격 push, 실제 기기 설치·시험, Live2D 출시 허가 확인은 이번 구현 완료 조건에 포함하지 않는다.

## 2. 확인된 원인과 선택한 접근

### 2.1 캐릭터 초기화

모바일 HTML의 CSP는 JavaScript 문자열 코드 생성을 허용하지 않는다. 현재 Pixi 7.3.0의 초기화 검사는 `new Function`을 사용하므로 이 경계에서 실패한다. 실제 번들로 문자열 코드 생성을 금지한 실행 환경에서 해당 실패가 확인되었다. 이는 단말에서 발생할 수 있는 모든 WebGL·모델 오류를 설명한다는 뜻은 아니다.

Pixi 버전과 일치하는 공식 `@pixi/unsafe-eval` 호환 모듈을 Pixi 다음, 렌더러 생성 전에 로드한다. 이름과 달리 이 모듈은 `new Function`을 금지한 환경을 지원하기 위한 것이다. [Pixi 공식 안내](https://api.pixijs.io/@pixi/unsafe-eval.html)

`script-src`에 `'unsafe-eval'`을 추가하는 대안은 채택하지 않는다. 기존 Pixi·Cubism Core·모델을 다른 버전으로 바꾸는 방식도 이번 범위에서 사용하지 않는다.

### 2.2 스트리밍 출력

현재 일반 답변은 TTS 준비 중 `pending_response`에 있다. 음성 형식 신호가 먼저 도착하면 `public_assistant_ids`에 메시지 ID가 없어 휴대폰 출력을 포기하고 PC 재생기를 시작한다. 이후 첫 PCM을 처리하며 메시지가 공개돼도 해당 발화는 PC로 남는다. 기존 테스트 중 하나도 이 동작을 정상으로 기대한다.

형식 신호에서는 발화 소유권·형식·출력 정책을 보관하고, 첫 유효 PCM이 준비되면 메시지 공개와 휴대폰 제안을 순서대로 처리한다. 임의의 공개 ID를 만들거나 형식 신호만으로 답변을 먼저 표시하지 않는다.

완성 음성을 모두 모아 전송하면 순서 처리는 단순해지지만 스트리밍 지연의 이점을 잃는다. 기존 스트리밍과 버퍼 상한을 유지하는 순서 수정을 채택한다.

## 3. 출력 정책

설정 키는 `tts_output_target`, 허용 값은 `auto / pc / phone`으로 둔다. 누락되거나 유효하지 않은 값은 `auto`로 정규화한다. 기존 PC 사운드 장치 설정 `tts_output_device_id`와는 별개다.

| 선택 | 시작 전 동작 | 실패 처리 |
| --- | --- | --- |
| 자동 | 전경·인증·동기화·음성 기능이 준비된 휴대폰에 우선 제안 | 휴대폰 시작 확정 전에는 같은 음성을 PC로 대체할 수 있음 |
| PC | 휴대폰에 제안하지 않고 기존 PC 재생 경로 사용 | 기존 PC 오류 처리 유지, 휴대폰으로 역전환하지 않음 |
| 휴대폰 | 지원되는 공개 답변만 휴대폰에 제안 | 연결 없음·준비 실패·지원 불가이면 음성을 중단하고 사유 표시, PC 재생 금지 |

모든 선택에서 TTS 사용 해제와 기존 사용자 중단·PTT·대화 초기화·작업 대체·서버 종료가 우선한다. 휴대폰 시작을 확정한 발화는 자동 모드에서도 PC로 되돌리지 않는다. 시작 명령의 송신 성공 여부가 불명확한 경우도 이미 확정된 것으로 취급한다.

브라우저 TTS처럼 PC에서만 재생할 수 있는 방식, 모바일 미지원 형식, 비공개 파일 결과는 자동/PC에서 기존 PC 경로를 유지한다. 수동 휴대폰에서는 이 경로도 재생하지 않고 지원 불가 사유를 표시한다. 비공개 결과를 공개 메시지로 바꾸거나 음성을 휴대폰에 노출하지 않는다. 브라우저 재생 명령은 실행하기 전에 정책으로 차단해야 한다.

선택은 설정 저장/적용 후 시작하는 다음 TTS 발화부터 적용한다. 단순한 설정 미리보기나 취소는 적용된 출력 정책을 바꾸지 않는다. 발화 시작 시 정책을 캡처하며 형식·첫 PCM·완료 WAV 도착 사이에 설정이 바뀌어도 그 발화의 정책은 바뀌지 않는다. 재생 중인 음성을 이동시키지 않는다. 기존 공급자 변경·TTS 해제에 따른 명시적 취소 동작은 별개로 유지한다.

준비 실패 뒤 재연결되거나 앱이 다시 전경이 되어도 중단한 음성을 다시 생성·재생하지 않는다. 다음 발화에서만 다시 판단한다. 음성을 중단해도 답변 텍스트는 기존 표시 정책에 따라 제공하고 입력 게이트를 정상 해제한다.

## 4. 스트리밍과 완료 수명

발화별 정책은 Qt 쪽 TTS 브리지에서 캡처하고, 휴대폰 조정기·출력 상태기에 대체 허용 여부를 명시적으로 전달한다. 조정기의 PC 대체 진입점 전체가 이 정책을 준수하도록 한다. UI 문구나 Android 상태만 바꿔 PC 대체를 막는 방식은 사용하지 않는다.

일반 공개 답변의 처리 순서는 다음과 같다.

1. TTS 작업을 현재 요청·작업 ID에 결합하고 출력 정책을 캡처한다.
2. 형식을 검사한다. 휴대폰 후보는 형식을 보관하되 메시지 ID 부재만으로 PC 재생기를 시작하지 않는다.
3. 첫 유효 PCM에서 현재 작업·연결 세대·공개 가능 여부를 다시 확인한다. 메시지 공개 과정에서 논리적 완료가 먼저 발생하지 않도록 완료 소유권을 확보한다.
4. 기존 답변 공개 함수를 통해 메시지를 한 번 등록하고 실제 공개 ID를 얻는다. 대화 이벤트가 음성 제안보다 먼저 발행되도록 한다.
5. 첫 PCM을 잃지 않고 조정기에 전달한다. 준비 응답 후 시작 허가, 진행 보고, 원본 종료와 소비 프레임 일치 확인을 거친다.
6. 완료·취소·PC 대체 결과에 따라 소유권과 버퍼를 정리한다. 논리적 완료는 한 번만 발생한다.

이미 공개된 메시지의 재생 경로도 동일한 정책을 따른다. 대화 초기화·요청 교체로 사라진 참조는 새 메시지로 임의 승격하지 않는다.

형식만 오고 PCM 없이 종료하는 경우, 생성 오류, 유효하지 않은 PCM, 준비 제한 초과, 전송 실패, 큐 포화, 포커스 거절, 앱 비활성화, 단절을 각각 종료 가능한 상태로 처리한다. 형식·프레임 검증과 기존 자원 상한을 약화하지 않는다. 잘못된 PCM을 PC로 보내 검사를 우회하지 않는다. 정상 PCM의 자동 대체에서는 보관한 첫 조각부터 이후 조각까지 같은 바이트를 한 번만 소비하며 LLM/TTS를 재호출하지 않는다.

취소 뒤 늦은 형식·PCM·완료 콜백이 PC 재생기로 빠지지 않아야 한다. 연결 세대가 바뀐 오래된 응답도 무시한다. 수동 휴대폰에서 대체가 금지되어 종료하는 경우에도 worker 정리와 입력 게이트 해제를 보장한다.

준비 제한 2초, 진행 정지 감시 5초, PCM 형식·발화 길이·크기·큐 제한 등 기존 계약은 유지한다. 새 무제한 대기열이나 전체 발화의 추가 복사본을 만들지 않는다.

## 5. 설정과 진단 표시

### 5.1 PC 설정

기존 TTS 탭의 재생 그룹에서 오디오 장치 선택 위에 `재생 기기`를 추가한다. 선택 항목은 `자동 / PC / 휴대폰`이며, 기존 장치는 PC 출력 장치임을 구분한다. 휴대폰 내부 스피커·이어폰·Bluetooth 선택은 Android가 담당한다.

다음 발화부터 적용된다는 설명과 수동 휴대폰에서는 PC로 대체하지 않는다는 설명을 제공한다. 저장·재시작·설정 취소·구형 설정 로드 및 기존 한국어/영어/일본어 번역 체계를 함께 검증한다.

PC 재생 그룹의 상태 표시와 휴대폰 연결 상태 영역에서 적용된 선택, 현재 목적지·준비/재생/중단 상태, 사유를 구분한다. 연결이 없는 경우에도 PC 쪽에서 원인을 볼 수 있어야 한다. 단순히 휴대폰이 재생 중이 아니라는 이유로 PC에서 소리가 난다고 표시하지 않는다.

### 5.2 상태 계약과 구형 호환

기존 `audio_status.mode`의 `disabled / pc_only / auto` 및 프로토콜 버전 1은 유지한다. 새 `phone_only` 값을 보내 구형 APK의 엄격한 검증을 깨지 않는다. 다음 선택 필드를 추가하고 양쪽 정규화기에서 검증한다.

| 선택 필드 | 값 | 의미 |
| --- | --- | --- |
| `preference` | `auto / pc / phone` | 저장되어 다음 발화에 적용될 선택 |
| `output` | `none / pc / phone` | 현재 발화에서 확정한 목적지, 없거나 중단되면 `none` |
| `state` | `idle / preparing / playing / stopped` | 현재 준비·재생 수명 |

`reason`은 기존의 제한된 코드 형식을 유지한다. 새 필드가 없는 구형 PC 메시지는 상세 정보 미제공으로 취급하며, 실제 선택이나 실패 원인을 추측해 표시하지 않는다. 구형 APK는 선택 필드를 무시하고 기존 음성 계약으로 동작할 수 있어야 한다.

진행 중인 휴대폰 발화에 대해서는 선택을 PC로 저장하더라도 수신 허용 모드 `auto`를 유지한다. 새 선택은 `preference`로 알리고 발화 종료 후 차기 허용 모드로 전환한다. 구형 APK가 설정 변경 통지만으로 진행 중인 음성을 취소하지 않도록 한다. 수동 휴대폰에서 PC 전용 공급자를 사용하는 등 출력 자체가 차단된 유휴 상태는 `disabled`와 해당 사유로 표시한다.

대표 사유는 수동 PC 선택, TTS 사용 해제, 휴대폰 미연결/비활성/동기화 중/음성 기능 미협상, 공급자 또는 형식 미지원, 비공개 결과, 준비 중/준비 제한 초과, 포커스 거절, 음성 전송 실패, 재생 정지 등으로 구분한다. 기존 Android 거절·취소 코드와 가용성 사유를 PC에서 버리지 않는다. 코드별 사용자 문구는 양쪽 표시 계층에서 관리한다.

상태는 현재 발화·연결 세대에 결합한다. 오래된 응답이 새 발화의 상태를 덮어쓰지 않는다. 마지막 중단 사유는 다음 발화 시작이나 관련 연결/설정 상태 변경까지 유지하며 주기적 일반 상태 갱신으로 즉시 지우지 않는다. 연결을 잃으면 연결 해제 상태를 우선 표시하고 이전 재생 중 표시를 남기지 않는다.

진단에는 대화 원문·음성 바이트·API 키·토큰·사용자 경로·임의 예외 문자열을 넣지 않는다. 재생 시작 보고는 소프트웨어 상태이며 실제 스피커에서 소리가 들렸다는 하드웨어 검증으로 표현하지 않는다. 별도의 영구 진단 로그나 수집 서버는 추가하지 않는다.

## 6. 캐릭터 자산과 보안 경계

공식 호환 모듈 7.3.0의 출처·버전·SHA-256·MIT 고지를 확인해 기존 허용 목록과 해시 manifest에 추가한다. PC 저장소의 공유 소스를 기준으로 Android 자산을 내보내며, Android 복사본만 손으로 고쳐 두 실행부가 달라지게 하지 않는다. 내보내기 도구와 라이브러리 개수를 고정한 검증도 새 목록에 맞게 갱신한다.

CSP, 앱 내부 HTTPS 출처, 외부 탐색·파일 접근 차단, 모델 검증, Core 로컬 전용 규칙은 유지한다. 내보내기는 기존 로컬 Core를 보존하고 추적 대상에 포함하지 않는다. 실행 초기화 오류는 캐릭터 실패 상태로 끝나며 음성 가용성 판단의 조건이 되지 않는다.

## 8. 검증과 인수 기준

각 수정은 실패를 먼저 보여 주는 집중 테스트를 작성한 뒤 최소 수정으로 통과시킨다. 기존의 잘못된 PC 고정 기대는 새 공개 순서 테스트로 대체하고, 비공개 결과의 전송 금지 테스트는 유지한다.

| 대상 | 필요한 검증 |
| --- | --- |
| CSP 초기화 | 실제 Pixi 번들에서 문자열 코드 생성을 금지한 조건으로 실패 재현, 공식 모듈 적용 후 동일 검사 통과. CSP 완화 없음 |
| 일반 스트리밍 | 공개 ID를 미리 주입하지 않은 실제 답변 대기 흐름에서 첫 PCM → 공개 대화 이벤트 → 음성 제안 순서. 휴대폰 성공 시 PC 재생기 호출 0회 |
| 자동 대체 | 준비 거절/제한 초과/확정 전 단절 시 정상 PCM 전체가 PC에서 한 번만 소비됨. 확정 후 실패는 PC 호출 0회 |
| 수동 선택 | WAV·스트리밍·브라우저·미지원 형식·비공개 결과에 대해 PC/휴대폰 정책 검증. 수동 휴대폰의 모든 실패 경로에서 PC 호출 0회 |
| 수명·동시성 | 형식만 온 종료, 생성 오류, 중단, PTT, 초기화, 작업 교체, 세대 변경, 늦은 콜백, 완료 중복에서 게이트·worker·버퍼 정리 |
| 설정 | 기본/잘못된 값 정규화, 저장·복원·취소, 재시작 유지, 발화 도중 변경은 다음 발화부터 적용, 진행 중 음성 강제 이동 없음 |
| 진단·호환 | 실패 사유 전달, 미연결 PC 표시, 오래된 상태 무시, 구형 PC/새 APK 및 새 PC/구형 APK 계약, 선택 필드 누락·잘못된 값 처리 |
| 기능 독립 | 캐릭터 초기화 실패 중에도 채팅과 음성 가용성·재생 수명이 유지됨 |
| 자산·빌드 | 내보내기 허용 목록·해시·라이선스 고지 일치, 기존 Core 보존·Git 제외, APK 내부에 개인 설정·개인키·모델 혼입 없음 |

집중 테스트 후 통합 시점에 ENE 전체 테스트와 기존 정적 검사를 실행한다. Android 단위 테스트를 실제 재실행하고 Lint·개발 APK·계측 APK 컴파일을 확인한다. 테스트를 건너뛰거나 검증 기준을 낮춰 통과시키지 않는다. 컴파일한 계측 APK를 단말에서 실행했다고 보고하지 않는다.

기존 개발 APK를 덮어쓰기 전에 Git 제외된 비공개 로컬 위치에 원본을 복사하고 해시를 대조한다. 신규 APK에는 빌드 시각·커밋 상태·SHA-256을 기록해 기존 파일과 구분한다. 산출물과 기록에 개인 데이터가 포함되지 않는지 확인하며 공개 저장소에는 업로드하지 않는다.

자동 검증으로 확인한 항목과 실제 단말에서 남은 캐릭터 표시·스피커 출력·백그라운드/회전·체감 지연 시험을 분리해 보고한다. 실제 기기 성공이나 출시 허가는 자동 테스트와 빌드 성공만으로 단정하지 않는다.

## 9. 기존 문서와의 관계

이 설계는 기존 미디어 설계의 다음 정책을 구현 시 대체한다.

- 메시지가 아직 공개되지 않은 스트리밍 발화를 PC로 고정하는 규칙: 첫 유효 PCM에서 기존 공개 절차를 거친 뒤 휴대폰 후보로 처리한다.
- 모든 준비 실패·미지원 공급자/형식이 PC로 가는 규칙: 자동/PC에서는 유지하되, 수동 휴대폰에서는 재생하지 않는다.
- 자동 출력만 제공하는 규칙: 기본 자동을 유지하면서 수동 선택을 추가한다.

기존의 원문 비공개, 시작 확정 후 PC 재생 금지, 자원 한도, TLS·출처 검증은 그대로 적용한다. 구현 문서에는 변경된 현재 사용법을 반영하되 과거 검증 기록을 새 기능의 검증 결과로 바꾸어 쓰지 않는다.
