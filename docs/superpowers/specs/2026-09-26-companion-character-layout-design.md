# 휴대폰 캐릭터 배치 저장과 표시 수명 설계

작성일: 2026-09-26. 상태: 설계 승인 및 구현 계획 검토 완료, 구현 전.

## 1. 목표와 범위

휴대폰의 Live2D 크기와 위치는 휴대폰에서 독립적으로 조절하고 자동 저장한다. 재접속, 앱 재실행, 화면 재생성 후에도 마지막으로 저장한 배치를 복원한다. 움직임 설정은 기존 PC 확정값 전달 경로를 사용한다. 채팅 입력 중 키보드가 열리고 닫혔다는 이유로 캐릭터를 파괴하고 다시 만들지 않는다.

이번 변경은 휴대폰 캐릭터 표시라는 한 기능으로 묶는다. 새 TTS 기능, 채팅 프로토콜 변경, PC 화면 배치 변경, 실제 기기 설치, 공개 바이너리 배포, 출시 허가 판단은 포함하지 않는다. 기존 Core·모델·APK·인증 정보·사용자 데이터는 보존한다.

## 2. 현재 코드에서 확인한 사실

설계 기준은 ENE `954f037`과 ENE_APP `ad1de52`이다. ENE_APP의 기존 로컬 커밋 9개는 보존한다. 오래된 후속 수정 작업 폴더를 새 ENE 변경의 기준으로 사용하지 않는다.

- ENE_APP `ui/CharacterPanel.kt`: 키보드, 작은 화면, 큰 글자 조건에서 높이를 0으로 계산한다. 이때 `AndroidView`를 구성에서 제거하며 `onRelease`가 렌더러를 분리하고 WebView를 종료한다. 복귀하면 새 WebView가 만들어진다.
- ENE_APP `connection/ConnectionRepository.kt`: 정상 메시지 전송은 캐릭터 재로딩을 직접 요청하지 않는다.
- ENE_APP `ui/ConnectionScreen.kt`: `CONNECTED` 이외에는 캐릭터 패널을 구성에서 제거한다. 따라서 같은 연결의 일시적인 대화 재동기화도 별도로 검사해야 한다.
- ENE `assets/web/runtime_character_host.js`: 휴대폰 스냅샷 적용 때 배치를 `scale: 1`, `xPercent: 50`, `yPercent: 50`으로 전달한다. 저장값을 추가하기만 하면 이후 스냅샷이 덮어쓸 수 있다.
- 같은 모델에 대한 `applyENEModelSettings` 호출은 모델 경로가 같으면 배치를 갱신할 뿐 SDK 모델을 다시 생성하지 않는다. 스냅샷 수신 자체를 무조건 전체 모델 재로딩으로 간주하지 않는다.
- PC는 허용된 움직임 관련 설정 20개와 장식 매개변수를 확정 스냅샷으로 내보내며, 휴대폰 공유 실행부가 이를 적용한다. 새 설정 동기화 체계를 중복 구현하지 않는다.

키보드에 따른 파괴 경로는 코드로 확인했다. 실제 단말의 모든 깜빡임이 이 경로 때문인지는 아직 검증하지 않았다. 회귀 검사는 파괴·생성·모델 로딩 횟수를 구분해 확인한다.

## 3. 사용자 동작과 저장 정책

### 3.1 휴대폰 표시 설정

기존 PC 공통 설정과 구분되는 `휴대폰 표시 설정`을 제공한다. 안내에는 이 값이 휴대폰에만 저장되며 PC 배치를 바꾸지 않는다는 점을 명시한다.

| 항목 | 의미 | 기본값과 범위 |
| --- | --- | --- |
| 크기 | 표시 영역에 맞춘 기준 크기에 대한 배율 | 100%, 50–200% |
| 가로 위치 | 표시 영역 안에서 모델 중심의 상대 위치 | 50%, 0–100% |
| 세로 위치 | 표시 영역 안에서 모델 중심의 상대 위치 | 50%, 0–100% |
| 기본 배치로 복원 | 위 세 값을 함께 기본값으로 변경 | 즉시 반영 후 자동 저장 |

위치는 화면 전체나 채팅 목록이 아니라 캐릭터 표시 영역을 기준으로 한다. 이동 범위와 확대 때문에 모델 일부가 잘릴 수 있으며 복원 버튼은 모델의 위치와 무관하게 접근할 수 있어야 한다. 이번에는 슬라이더를 사용한다. 직접 드래그·핀치 확대는 기존 쓰다듬기 입력과의 충돌을 피하기 위해 추가하지 않는다.

저장 범위는 **휴대폰 앱 전체에 마지막 배치 한 세트**다. 모델별·서버별 설정 목록은 만들지 않는다. 다른 모델로 바꿔도 같은 비율을 적용하며 필요하면 복원 버튼으로 조정한다.

### 3.2 기준 크기와 화면 변화

- 새 모델을 정상적으로 읽은 뒤 원래 모델 경계와 캐릭터 표시 영역으로 기준 배율을 계산한다. 기본 상태에서는 가로·세로 모두 표시 영역 안에 들어오도록 맞추고 약간의 여백을 둔다.
- 저장하는 것은 배율과 상대 좌표다. 화면 회전이나 화면 크기 변화에서는 같은 저장값으로 새 영역에 맞춰 계산한다. 물리 픽셀 수를 고정한다는 뜻은 아니다.
- 모션에 따른 일시적인 크기·위치 변화는 기본 배치 위에 합성한다. 애니메이션 중의 변형값을 새 기준 크기나 저장값으로 사용하지 않는다.
- 높이 또는 너비가 0인 숨김 상태에서는 새 기준 크기를 계산하거나 저장값을 변경하지 않는다. 다시 표시할 때 유효한 영역으로 재계산한다.
- 최초 표시부터 저장값을 적용한다. 중앙 기본값이 잠시 나타났다가 저장 위치로 이동하는 순서는 피한다.

### 3.3 자동 저장과 복원

저장 담당은 연결 세션보다 오래 사는 앱 수명의 로컬 객체다. 저장 자료는 형식 버전과 크기·가로·세로 값뿐이며 PC 주소·모델 경로·토큰·대화는 포함하지 않는다.

- 앱 전용 `noBackupFilesDir` 아래에 배치 전용 파일을 둔다. 모델 캐시와 등록 정보의 정리 대상 폴더와 분리한다. 기존 `AtomicFile` 기반 읽기·쓰기 패턴을 재사용한다.
- 슬라이더 조작은 즉시 미리 반영한다. 연속 변경은 짧게 합쳐 자동 저장하고, 손을 떼면 마지막 값의 저장을 바로 요청한다. 저장 버튼은 두지 않는다.
- 쓰기는 별도 작업 흐름에서 순서대로 처리하며 세 값의 한 묶음을 원자적으로 저장한다. 이전 쓰기가 늦게 끝나 최신 설정을 되돌리지 않게 한다.
- 화면 회전이나 채팅 재접속은 대기 중인 저장을 취소하지 않는다. 앱이 갑자기 종료되더라도 마지막으로 **저장 완료된 값**은 복원한다. 아직 저장 완료 전인 마지막 입력까지 강제 종료 후 보장한다고 표시하지 않는다.
- 저장 완료가 확인된 경우에만 저장 상태를 완료로 표시한다. 저장 실패 시 현재 미리보기와 마지막 정상 파일을 유지하고, 고정 문구와 명시적인 저장 재시도를 제공한다. 연결·TTS·채팅은 중단하지 않는다.
- 처음 설치해 파일이 없으면 기본값으로 시작한다. 손상된 형식·비유한 숫자·허용 범위 밖의 값은 적용하지 않고 기본값과 안내를 사용한다. 읽기 실패만으로 정상 파일을 덮어쓰지 않는다. 이후 사용자가 변경하거나 복원하면 정상 값으로 다시 저장할 수 있다.
- 재접속, 앱 재실행, 화면 재생성, 모델 캐시 정리, 등록 해제는 이 앱 공통 배치를 초기화하지 않는다. 초기화는 배치 복원 또는 앱 데이터 삭제로 한정한다.

## 4. 구현 경계

### 4.1 로컬 배치와 PC 공통 설정 분리

ENE_APP에 배치 값의 검증, 로컬 저장소, 앱 수명의 배치 상태 관리 책임을 둔다. 설정 UI는 이 상태를 읽고 조절하며 네트워크 설정 저장 요청을 보내지 않는다.

네이티브에서 WebView로 전달하는 내부 명령에 로컬 배치와 표시 여부를 추가한다. 기존 고정 출처·주 프레임·문서 세대 검증과 크기 제한을 유지하고, 배치 명령의 숫자도 네이티브와 실행부에서 검증한다. JavaScript 웹 저장소, 외부 URL, 임의 코드 실행 통로는 열지 않는다. HTTPS/WSS 공개 프로토콜과 PC 설정 허용 목록에는 이 세 배치 값을 추가하지 않는다.

ENE의 공유 실행부 원본에 휴대폰 호스트 전용 배치 적용을 추가한다. PC 호스트의 기존 배치·루트 모션 동작은 유지한다. 새 뷰를 만들거나 내부 문서 준비가 늦어져도 최신 배치와 표시 여부를 준비 시점에 전달한다. 오래된 뷰의 지연 콜백은 새 뷰의 배치를 덮어쓰지 못한다.

PC 스냅샷, 공통 설정 미리보기·저장, 표정·음성 이벤트는 로컬 배치 상태를 수정하지 않는다. 같은 모델에 대해서는 현재 SDK 모델을 유지한 채 필요한 값만 적용한다.

### 4.2 움직임 자동 반영

기본 모션, 자동 눈 깜빡임, 보조·표현 모션, 강도·속도, 발화 가중치, 포즈 전환, 합성 제스처 크기와 대기 빈도, 쓰다듬기 설정은 기존 PC 확정값을 따른다. 최초 연결, PC 저장, 재접속, 모델 교체 시 최신 값이 실제 실행부까지 적용되는지 검사한다.

기존 휴대폰 공통 설정 편집 기능은 제거하지 않는다. 그 화면의 변경은 지금처럼 PC에 저장하고 확정값을 다시 받는다. `휴대폰 표시 설정`의 변경만 로컬 저장으로 끝난다. PC에서 저장하지 않은 미리보기 값을 새로 자동 전송하지 않는다.

대화에 따른 합성 제스처 사용 여부는 기존 PC 이벤트 생성 판단을 따른다. PC 마우스 좌표·창 좌표는 휴대폰으로 복제하지 않는다. 같은 움직임 설정의 적용을 목표로 하며 무작위 눈 깜빡임이나 모션 위상을 프레임 단위로 일치시키지는 않는다.

### 4.3 캐릭터 수명과 숨김

- Compose 재구성, 정상 메시지 송수신, 키보드에 따른 접힘, 작은 화면·큰 글자에 따른 접힘은 뷰나 모델의 재생성 이유가 아니다.
- 같은 인증 연결 내 대화 동기화 동안에도 뷰 소유권은 유지할 수 있지만, 동기화가 불완전한 동안 입력을 허용하지 않는다. 새 연결의 확인 전에는 이전 캐시만으로 캐릭터를 표시하지 않는 기존 규칙을 유지한다.
- 접힌 동안 캐릭터는 표시·터치·접근성 포커스 대상에서 제외한다. 그래픽 객체와 캐시 핀은 유지하되 불필요한 그리기·동작 갱신은 중지하고, 쓰다듬기는 취소한다. 숨김 유지가 정상 쓰다듬기 완료나 횟수 증가로 해석되지 않아야 한다.
- 접힘 중 받은 일회성 동작은 복귀 후 몰아서 재생하지 않는다. 복귀 시 최신 설정·표정 현재값을 사용하고, 입 모양은 현재 재생 상태에서 복원하며 음성 시작을 재요청하지 않는다.
- 같은 모델의 설정 갱신은 SDK 모델을 다시 읽지 않는다. 모델 버전 변경은 모델 자원 교체를 허용한다.
- 명시적 다시 불러오기, 렌더러 오류 복구, Activity 재생성은 새 WebView가 필요할 수 있다. 이때도 배치 값은 복원한다. 실패한 렌더러는 자동 무한 재시작하지 않는다.
- 실제 연결 종료·등록 해제·앱 백그라운드 전환에서는 기존 인증·전송·음성 정리 정책을 유지한다. 수명 종료에 필요한 `close`, 스트림 정리, 캐시 핀 반환을 단순히 삭제해 문제를 숨기지 않는다.

## 5. 영향 파일과 작업 순서

파일 경로는 각각 ENE 또는 ENE_APP 저장소 루트 기준이다.

1. ENE_APP 로컬 배치 값·저장소·상태 관리와 단위 검사 → 검증: 자동 저장, 새 객체에서 복원, 범위 검사, 손상·저장 실패, 쓰기 순서.
2. ENE `assets/web/runtime_character_host.js`, `runtime_live2d_model.js`, `character/entry.js`와 캐릭터 검사 → 검증: 화면 맞춤, 독립 배치, 동일 모델 유지, PC 호스트 불변.
3. ENE_APP `character/CharacterBridge.kt`, `CharacterWebView.kt`, `CharacterSession.kt`, `connection/ConnectionRepository.kt`, `EneApplication.kt` 연결 → 검증: 준비 전 배치 보관, 세대 격리, 설정 수신과 로컬 값 분리.
4. ENE_APP `ui/CharacterPanel.kt`, `ConnectionScreen.kt`, 휴대폰 표시 설정 UI → 검증: 접힘과 동기화 시 수명 유지, 쓰다듬기 취소, 설정 조절과 기본 복원.
5. 기존 내보내기 도구로 공유 실행부를 Android에 반영하고 출처 manifest 갱신 → 검증: 경로 목록·해시, Core 불변, 금지 파일 미포함.
6. 통합 검사와 로컬 APK 재빌드 → 검증: 아래 수용 조건과 빌드 결과. 기존 APK는 보존하며 업로드하지 않는다.

구현은 순차적으로 직접 진행한다. 서로 다른 작업이 같은 캐릭터 수명과 상태를 공유하므로 구현 자체를 여러 에이전트로 나누지 않는다. 주요 설계·통합 검토만 현재 변경 범위에 한정한다.

## 6. 수용 조건과 검증

- [ ] 배치 조절 후 저장 완료를 확인하고 저장 담당 객체·연결·화면을 다시 만들어도 같은 세 값이 복원된다.
- [ ] PC 크기·위치와 설정 저장 요청에는 변화가 없다. 공통 움직임 설정만 PC 확정값을 자동 반영한다.
- [ ] 기본 크기에서 합성 모델이 표시 영역 안에 들어오며 배율과 상대 위치 계산이 정확하다. 화면 변화와 0 크기 숨김을 구분한다.
- [ ] PC 설정 스냅샷, 재접속, 모델 교체가 저장된 로컬 배치를 초기화하지 않는다.
- [ ] 정상 송수신과 키보드 열기·닫기를 반복해도 WebView 생성, 모델 생성, 전체 자산 읽기 횟수가 불필요하게 증가하지 않는다.
- [ ] 대화 재동기화 중 입력이 차단되고, 새로운 인증 연결 확인 전에는 이전 캐릭터가 노출되지 않는다.
- [ ] 접힘·복귀 때 쓰다듬기, 일회성 동작, 입 모양, 백그라운드 자원 정리에 회귀가 없다.
- [ ] 이전 문서의 배치 명령, 잘못된 숫자, 비허용 메시지는 차단한다. WebView 보안 정책을 완화하지 않는다.
- [ ] ENE 집중 검사와 통합 시 전체 검사, Android 단위 검사·Lint·개발 APK·계측 APK 빌드, 공유 파일 목록·해시 검사를 수행한다.
- [ ] Compose/WebView 계측 코드는 실제 실행 여부를 별도로 보고한다. 컴파일 성공을 실제 기기 재현 해결로 보고하지 않는다.
- [ ] Core·모델·설정·인증·이전 APK를 보존한다. 새로 추적할 파일은 합성 예시만 사용하며 커밋 전 개인정보 후보와 금지 파일을 검사한다.

설계 준비 단계에서 기존 공유 실행부·내부 문서 검사 20개가 통과했다. 이는 변경 전 기준선이며 새 기능 구현이나 단말 문제 해결 결과가 아니다. 실제 기기에서의 크기·위치 조절, 키보드 전환, 그래픽 호환성, Live2D 출시 허가 확인은 별도 미확인 사항으로 남긴다.

설계의 범위·저장·연결 수명 조건을 별도 읽기 전용 검토했으며 계획 수립을 막는 문제는 발견되지 않았다. 구현 계획에서는 모델 원래 경계와 화면 맞춤 여백을 구체적인 수식으로 정의하고 합성 모델의 기대 배율·좌표를 검사한다.
