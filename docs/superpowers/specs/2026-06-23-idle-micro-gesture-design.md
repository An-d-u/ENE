# 유휴 마이크로 제스처 V1 설계

## 목표

ENE가 대화하지 않고 가만히 있을 때도 아주 가끔 작은 제스처를 실행해, Live2D 모델이 더 살아 있는 것처럼 보이게 한다.

V1은 과한 자동 행동을 피하는 것을 우선한다. 기존 응답 제스처 엔진을 재사용하고, 사용자가 조절해야 하는 설정은 최소화한다.

## 범위

포함한다.

- 설정 > 동작 설정 > 응답 제스처 영역에 `유휴 제스처 사용` 체크박스를 추가한다.
- 같은 영역에 `유휴 제스처 빈도` 설정을 추가한다.
- 기존 `동작 배율`은 응답 제스처와 유휴 제스처가 함께 사용한다.
- 유휴 상태에서만 작은 제스처 후보를 랜덤으로 실행한다.
- TTS, 응답 제스처, 쓰다듬, 모델 준비 중에는 유휴 제스처를 실행하지 않는다.

포함하지 않는다.

- 감정 상태별 유휴 제스처 후보 분기.
- 유휴 제스처 전용 배율.
- 사용자가 제스처 후보 목록을 직접 편집하는 기능.
- 장시간 부재 상태와 연결된 별도 행동.

## 설정 모델

새 설정값은 다음을 기준으로 한다.

- `enable_idle_synthetic_gestures`: 기본값 `false` 또는 `true` 중 구현 직전 결정. 보수적으로는 `false`가 안전하다.
- `idle_synthetic_gesture_frequency`: 기본값 `normal`.

빈도 프리셋은 다음 의미를 가진다.

- `low`: 약 20~45초마다 후보 확인.
- `normal`: 약 12~28초마다 후보 확인.
- `high`: 약 7~16초마다 후보 확인.

이 값은 “실행 간격”이 아니라 “후보 확인 간격”이다. 후보 확인 시점에 차단 조건이 있으면 제스처를 실행하지 않고 다음 랜덤 대기로 넘어간다.

## 런타임 동작

유휴 제스처 스케줄러는 WebView 안의 제스처 런타임에 둔다.

1. `enable_idle_synthetic_gestures`가 꺼져 있으면 타이머를 모두 정리한다.
2. 켜져 있으면 빈도 프리셋에 따라 다음 후보 확인 시간을 랜덤으로 예약한다.
3. 예약 시간이 되면 차단 조건을 검사한다.
4. 차단 조건이 없으면 작은 유휴 제스처 후보 중 하나를 랜덤 실행한다.
5. 실행 여부와 무관하게 다음 후보 확인을 다시 예약한다.

추천 후보는 V1에서 작고 짧은 동작만 사용한다.

- `soft-look-around`: 시선과 고개를 좌우로 살짝 이동.
- `tiny-nod`: 아주 작은 끄덕임.
- `cute-tilt`: 짧고 부드러운 갸웃.
- `settle-breath`: 몸이 살짝 정리되는 느낌의 미세 움직임.

후보 동작은 기존 응답 제스처와 같은 파라미터 매핑, 같은 모델별 파라미터 자동 감지, 같은 `synthetic_gesture_scale`을 사용한다.

## 차단 조건

아래 상황에서는 유휴 제스처를 실행하지 않는다.

- TTS가 재생 중이거나 응답 제스처가 TTS 구간 안에 예약되어 있을 때.
- 응답 제스처가 현재 재생 중일 때.
- 쓰다듬 동작이 활성 상태이거나 쓰다듬 종료 페이드가 진행 중일 때.
- Live2D 모델이 아직 로드되지 않았거나 제스처 오프셋 적용 함수가 준비되지 않았을 때.
- 직전 유휴 제스처 실행 후 최소 쿨다운이 지나지 않았을 때.

차단 조건은 실패가 아니라 정상적인 스킵으로 취급한다.

## UI

기존 동작 설정의 `응답 제스처` 그룹 안에 다음 항목을 둔다.

- `응답 제스처 사용`
- `동작 배율`
- `유휴 제스처 사용`
- `유휴 제스처 빈도`
- 시험 기능 안내 문구

안내 문구는 기존 응답 제스처 안내를 확장해 사용한다.

> 아직 시험 기능입니다. 모델에 따라 어색하거나 제대로 작동하지 않을 수 있습니다.

## 데이터 흐름

설정 저장 흐름은 기존 설정 다이얼로그 패턴을 따른다.

1. 설정 다이얼로그가 `enable_idle_synthetic_gestures`, `idle_synthetic_gesture_frequency`를 읽고 표시한다.
2. 사용자가 값을 바꾸면 기존 설정 저장 흐름에 포함된다.
3. `OverlayWindow`가 설정 변경 시 WebView로 유휴 제스처 설정을 전달한다.
4. WebView 런타임은 전달받은 값으로 유휴 제스처 스케줄러를 시작하거나 정지한다.

## 실패 처리

- 빈도 값이 알 수 없는 문자열이면 `normal`로 처리한다.
- 배율 값이 비정상이면 기존 제스처 배율 기본값 `1.0`을 사용한다.
- 모델이 제스처 파라미터를 거의 받지 않는 경우에도 예외를 내지 않고 동작을 스킵하거나 미세하게만 보이게 둔다.
- 페이지 전환, 모델 재로드, 설정 비활성화 시 예약 타이머와 진행 중인 유휴 제스처를 정리한다.

## 테스트 계획

- 기본 설정 로드 시 새 설정값이 존재하는지 확인한다.
- 설정 다이얼로그에서 유휴 제스처 사용 여부와 빈도를 로드하고 저장하는지 확인한다.
- `OverlayWindow`가 WebView에 유휴 제스처 설정을 전달하는지 확인한다.
- Web runtime asset에 유휴 제스처 스케줄러 API가 노출되는지 확인한다.
- 런타임 단위 검증은 문자열 스모크 테스트부터 시작하고, 필요하면 브라우저 목업에서 수동 확인한다.

## 구현 순서

1. 설정 기본값과 저장/로드 테스트를 추가한다.
2. 설정 UI와 i18n 키를 추가한다.
3. `OverlayWindow`에서 WebView 동기화 코드를 추가한다.
4. `runtime_gesture_engine.js`에 유휴 제스처 스케줄러를 추가한다.
5. 기존 제스처 배율과 차단 조건을 연결한다.
6. 타겟 테스트와 JS 문법 검사를 실행한다.
