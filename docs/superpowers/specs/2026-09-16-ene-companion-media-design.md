# ENE 동반 앱 캐릭터·음성 확장 설계

작성일: 2026-09-16

상태: 사용자와 합의한 방향을 구체화하고 내부 명세 검토를 통과한 문서. 사용자 문서 검토 대기 중이며, 구현·단말 검증 완료를 뜻하지 않는다.

기준: [LAN V1 설계](2026-09-07-ene-companion-lan-v1-design.md), [TLS 설계](2026-09-08-ene-companion-tls-design.md), [기존 구현 계획](../plans/2026-09-08-ene-companion-lan-v1.md). 텍스트·인증 계약은 유지하며, 아래 범위와 진행 순서만 확장한다.

## 1. 확정 범위와 현재 위치

PC가 AI·TTS 생성, 현재 대화, 캐릭터 상태와 공통 설정을 관리한다. Android는 기존 Compose 연결·채팅 화면을 유지하고 캐릭터 전용 WebView와 네이티브 음성 재생을 추가한다. 같은 개인 LAN과 기존 HTTPS/WSS 신뢰 체계를 사용한다.

- PC에서 생성한 음성을 전달한다. 폰에서 AI/TTS를 다시 호출하지 않는다.
- 전경의 폰이 해당 음성을 재생할 준비를 마치면 폰에서만 출력한다. 그렇지 않으면 PC에서 출력한다.
- 시작한 음성을 기기 사이에서 옮기거나 처음부터 다시 읽지 않는다. 수동 출력 선택은 이번 범위에서 제외한다.
- PC와 같은 모델·표정·공통 움직임 설정을 사용하고, 쓰다듬기 결과를 PC에 반영한다. 모든 물리·눈깜빡임 프레임까지 같다는 보장은 하지 않는다.
- 실제 ENE의 대화·요청·수명 연결을 먼저 완성한 다음 음성·캐릭터 표시, 마지막으로 쓰다듬기·설정 변경을 연결한다.
- 사용자의 결정에 따라 설치·실기기 시험은 나중에 한다. 이는 검증 면제가 아니라 일정 변경이다. 가상 서버와 자동 테스트 성공만으로 실제 ENE↔단말 연동 완료를 선언하지 않는다.

현재 PC 작업 기준은 `codex/companion-lan-v1`의 `dfda5c45`, Android 기준은 별도 `ENE_APP` 저장소 `codex/companion-tls-v1`의 `d6671e8`이다. PC 원본 `main`을 수정하지 않는다. 기존 계획 Task 7~10의 실제 대화·수락·앱 수명 통합은 아직 선행 작업으로 남아 있다.

제외: 음성 입력, 백그라운드 재생 서비스, 통화, 첨부, 모바일 전체 PC 설정 창, 임의 모델 업로드, 기분 전용 화면, 화면 영상 전송, Tailscale 통합, 외부 공개, APK 배포. 기존 PC의 TTS 비활성 설정은 그대로 존중한다.

## 2. 선택한 방식과 책임

캐릭터 전용 WebView는 기존 표정·움직임 코드를 재사용할 수 있지만 Qt 연결부와 화면 전역 의존성을 분리해야 한다. Android 네이티브 Cubism 재구현은 같은 동작을 두 번 유지해야 하고, PC 화면 영상 전송은 채팅·터치·대역폭 처리가 별도로 필요하다. 이번에는 WebView 재사용을 선택한다.

| 구성 요소 | 책임과 경계 |
| --- | --- |
| PC 대화 어댑터 | 기존 공개 기록·수락 원장과 실제 ENE 작업을 연결한다. 내부 프롬프트·생각·개인 설정을 내보내지 않는다. |
| PC 음성 조정기 | 한 음성의 출력 대상·준비·시작·종료를 관리한다. 공급자 생성 코드와 출력 정책을 분리한다. |
| PC 캐릭터 상태 어댑터 | 현재 모델 식별자·표정·허용된 설정과 상호작용을 검증하고 게시한다. |
| 기존 TLS 게이트웨이 | 인증된 제어 메시지, 제한된 모델 자산, 해당 음성의 바이트를 전달한다. Qt 객체를 직접 조작하지 않는다. |
| Android 음성 재생기 | 네이티브 TLS 클라이언트로 받고, 오디오 포커스·PCM 재생·실제 재생 위치를 관리한다. |
| 공유 캐릭터 실행부 | 모델·표정·움직임·입 모양을 그린다. Qt/Android 호스트 연결은 별도 어댑터가 맡는다. |
| Android 캐릭터 호스트 | 검증된 로컬 자산만 WebView에 제공한다. JS에 토큰·PC 주소·전체 대화를 전달하지 않는다. |

PC의 `bridge_mixins/tts.py`에서 현재 직접 호출하는 `audio_player.play/start_stream/append_stream_pcm` 앞에 출력 경계를 둔다. 기존 작업 소유권·늦은 콜백 거절·중단 규칙을 유지한다. 단순히 PC 볼륨을 0으로 만들지 않는다. 논리적 재생 완료가 PC 플레이어의 완료 신호에만 종속되지 않도록 한다.

공유 JS는 PC 저장소에서 관리하고 검증된 파일 목록·버전·해시로 Android에 동기화한다. Android 빌드가 형제 저장소를 요구하지 않도록 복사된 소스와 필요한 고지를 자체 저장소에 보관한다. 실행 중 PC로부터 JS를 다운로드하여 실행하는 방식은 쓰지 않는다. 캐릭터와 관계없는 PC 채팅·일정·기억 UI를 분리 대상으로 확대하지 않는다.

## 3. 연결 계약과 보안

`audio_pcm_v1`, `character_v1`, `character_controls_v1` 능력을 각각 협상한다. 교집합에 없는 메시지는 보내지 않는다. 구형 앱은 기존 텍스트만 사용하고 PC 음성 출력을 유지한다. 확장 사건은 기존 대화의 `event_seq`를 증가시키지 않는다.

각 확장 메시지는 등록 세대·서버 실행·현재 연결 세대에 묶인다. 음성은 추가로 대화 ID·공개 메시지 ID·작업 ID·`utterance_id`, 캐릭터는 모델 버전·상태 revision을 가진다. 재연결하면 새 캐릭터 스냅샷만 받는다. 과거 음성·쓰다듬기·미확정 설정 명령은 재생하거나 자동 재전송하지 않는다.

제어는 기존 WSS를 사용한다. 큰 데이터는 아래 HTTPS 경로로 분리하여 대화 큐에 음성의 base64나 모델 파일을 넣지 않는다.

- `/companion/v1/audio/{utterance_id}`: 현재 연결에 제안된 음성의 PCM 스트림.
- `/companion/v1/character/manifest`: 현재 모델의 허용 자산 목록·공개 설정·지원 정보.
- `/companion/v1/character/assets/{asset_id}`: 현재 모델 목록에 있는 단일 자산.

각 요청은 기존 등록 토큰과 현재 WSS 연결에 결합된 연결 식별자를 헤더로 검증한다. 식별자만으로 인증하지 않는다. 불투명 ID는 파일 경로나 접근 권한을 대신하지 않는다. QR로 등록한 CA·고정 서버 이름 검증을 그대로 사용하고, 토큰의 URL/JS 삽입·리다이렉트·인증서 예외 허용은 금지한다. Origin·query 거절도 유지한다.

인증된 자산 요청은 기존 사전 인증 제한과 분리한 유량 제한을 둔다. 기기 교체·등록 해제·서버 종료·주 WSS 교체 시 하위 다운로드와 음성을 취소한다. 인증 전에 큰 파일을 열지 않으며 응답에 민감한 경로를 넣지 않는다. 스레드 간에는 크기가 제한된 불변 데이터/명령을 교환한다.

## 4. 자동 음성 출력

### 4.1 기기 선택과 시작 허가

출력 정책은 작은 독립 함수/상태 기계로 유지한다. 수동 선택 설정이나 범용 출력 플러그인 구조는 지금 만들지 않는다.

| 상황 | 동작 |
| --- | --- |
| 연결된 폰 없음, 백그라운드, 능력 미지원 | PC 출력 |
| 전경·인증·현재 대화 동기화 완료, 음성 기능 지원 | 해당 음성을 폰에 제안한 뒤 준비 결과로 결정 |
| 폰이 버퍼·플레이어·오디오 포커스 준비 완료 | PC가 폰 출력을 확정하고 시작 허가, PC 출력 없음 |
| 시작 허가 전 거절·준비 시간 초과 | 제안을 폐기하고 같은 생성 음성을 PC에서 출력 |
| 시작 허가 후 단절·백그라운드·재생 실패 | 해당 음성 종료, 다른 기기에서 재생하지 않음 |
| PC 재생 도중 폰 연결 | 현재 음성은 PC에서 끝내고 다음 음성부터 다시 판단 |

흐름은 `제안 → 준비 응답 → 출력 확정/시작 허가 → 재생 → 종료`다. 폰은 다운로드나 준비 응답만으로 재생하지 않는다. PC는 시작 허가를 보내기 전에 폰 출력을 되돌릴 수 없도록 확정한다. 허가 전에는 PC 대체 재생이 가능하지만, 허가 전송 결과나 재생 시작 응답이 불명확해진 뒤에는 같은 음성을 PC에서 재생하지 않는다. 간헐적인 무음 가능성보다 두 기기의 중복 발화를 막는 것을 우선한다.

제안은 첫 재생 가능한 데이터가 생겼을 때 시작하고 준비 제한은 2초다. 폰은 200ms의 PCM 또는 그보다 짧은 완성 음성 전체를 준비한 뒤 오디오 포커스를 요청한다. 지연된 포커스 획득을 기다렸다가 갑자기 읽지 않는다. 거절·만료된 제안과 이전 연결의 시작 허가는 무시한다. 폰은 준비 응답 후 3초 안에 시작 허가가 없으면 자원을 반납한다. 이때 PC가 이미 허가했다면 PC 대체 재생 없이 종료한다.

Android는 발화 직전에 포커스를 얻고 종료 시 반환한다. 포커스 상실·이어폰 분리로 인한 출력 변경 통지·앱 비활성화 시 중단하며 자동 재개하지 않는다. 포커스를 얻지 못하면 PC가 시작 전에 대체할 수 있도록 준비 거절을 보낸다. 음성 용도 속성을 사용한다. 이는 최신 target에서 전경 재생이라는 앱 수명 정책과도 맞는다. [Android 오디오 포커스 안내](https://developer.android.com/media/optimize/audio-focus)

### 4.2 중단·단절·대화 수명

음성 조정기는 TTS 작업의 실제 소유권을 사용한다. 최신 전역 요청을 추측하여 늦은 결과를 새 답변에 붙이지 않는다. 아직 공개되지 않은 메시지의 음성은 시작할 수 없으며, TTS 준비/실패에 따른 기존 공개 시점을 유지한다.

폰은 실제 활성 화면 수명과 주 연결에 재생을 묶는다. 비활성화 통지 후에도 남아 있는 다운로드·콜백이 재생을 다시 시작할 수 없다. PC도 연결 세대가 바뀌면 이전 완료·진행 응답을 폐기한다. 회전으로 화면을 다시 만들 때 오디오를 두 번 시작하지 않으며, WebView만 재생 위치와 현재 상태를 다시 받는다.

기존 사용자 중단·대화 초기화·작업 대체·서버 종료는 현재 음성을 취소한다. 재생 종료 응답이 유실되어도 입력 게이트가 영구히 잠기지 않도록 진행 응답이 5초 동안 없으면 취소하고 논리적 완료를 한 번 처리한다. 지연 도착한 종료는 무시한다. 단절을 아직 감지하지 못했더라도 다음 제안이 준비 제한을 넘으면 그 다음 음성은 PC로 간다.

재생 중에는 최소 500ms마다 진행 상태를 보고한다. 정상 제어 응답이 있더라도 소비한 프레임 위치가 5초 동안 증가하지 않으면 재생 정지로 취급하여 취소한다. 단방향 제어 단절·오디오만 남은 연결·보고만 정상인 멈춘 플레이어를 각각 시험하며, 취소된 음성은 나중에 데이터가 도착해도 재개하지 않는다.

### 4.3 형식·전달·자원 한도

최초 모바일 전송 형식은 16비트 리틀엔디언 PCM, 모노/스테레오, 8~48kHz다. 완성된 PCM WAV는 PC에서 헤더·길이·프레임 정렬을 검사한 뒤 PCM으로 전달하고, 기존 스트리밍 PCM도 같은 출력 경계에 연결한다. 공급자·API 키·음성 설정은 폰에 전달하지 않는다.

PC의 브라우저 음성 방식은 PCM 바이트를 제공하지 않으므로 PC 전용으로 유지하고 폰에 지원 상태를 표시한다. MP3 등 이번 PCM/WAV 경로에 해당하지 않는 응답 형식도 PC 재생을 유지한다. 이를 위해 공급자 설정을 몰래 바꾸거나 다시 생성하지 않는다. 다른 코덱 변환과 브라우저 음성 캡처는 별도 확장이다.

HTTPS 음성 응답은 검증된 형식 메타데이터와 원시 PCM으로 구성한다. EOF만으로 성공 처리하지 않고 WSS 완료 정보의 전체 프레임 수와 대조한다. 음성마다 HTTP 소비자는 하나이며 Range·재접속 재생은 지원하지 않는다. PC 대체 가능 구간에서는 처음부터의 PCM을 보관하고, 폰 출력 확정 후에는 보낸 구간을 버린다.

전송 큐는 기기별 4초 분량 이내·1MiB 이하, 단일 조각은 32KiB 이하로 제한한다. 느린 소비자 때문에 Qt 주 스레드나 TTS worker를 무기한 막지 않는다. 포화가 시작 허가 전이면 폰 제안을 취소하고 PC로 전환하고, 이후이면 현재 음성을 취소한다. 폰 음성 한도는 180초·36MiB다. 완성 음성이 한도를 넘으면 시작 전에 PC로 보내며, 이미 시작한 스트림이 한도에 도달하면 종료하고 텍스트는 유지한다. 음성과 재생 이력은 디스크에 보관하지 않는다.

### 4.4 립싱크

폰은 수신 시각이나 PC 타이머가 아니라 AudioTrack이 실제 소비한 프레임 위치를 기준으로 PCM 입 벌림 값을 적용한다. 첫 범위는 음량 기반 입 벌림이며, PC의 모음별 입 모양 분석 전체를 Android에 새로 구현하지 않는다. 기존 PC 출력의 분석·립싱크는 보존한다.

소리가 나지 않는 다른 화면도 말하는 상태를 알 수 있도록 출력 기기가 `utterance_id`·재생 위치·정규화한 입 벌림을 최대 초당 10회 보고하고 PC가 전달한다. 이 값은 대화 이벤트가 아니며 최신 값만 보관한다. 출력 기기의 립싱크는 로컬 시계를 사용하고, 반대편의 표시에는 통신 지연이 있을 수 있다. 중단·종료·오래된 갱신 시 입을 닫고 발화 움직임을 해제한다.

## 5. Live2D 실행과 모델 전달

`assets/web`의 모델·표정·움직임·쓰다듬기·립싱크 코드를 캐릭터 실행부와 호스트 어댑터로 최소 분리한다. 현재 classic script의 공유 전역 의존성을 테스트하며, PC `index.html`이나 전체 Qt WebChannel을 폰에 복사하지 않는다. 런타임 버전과 지원 모델 규격이 맞지 않으면 캐릭터만 비활성화하고 채팅·지원되는 음성은 유지한다.

초기 지원은 현재 웹 실행부가 처리하는 Cubism `.model3.json` 모델이다. 모델 manifest에는 불투명 모델 ID·내용 해시·실행부 호환 버전·자산별 ID/길이/해시·표정 ID·매개변수 범위를 담는다. PC 절대 경로·사용자별 모델 디렉터리 이름은 보내지 않는다. 모델 선택·교체는 PC에서만 하며 앱은 변경된 모델을 받는다.

PC는 선택된 모델 폴더 안에서 선언적으로 참조한 모델·텍스처·표정·모션·물리·포즈 데이터만 내보낸다. 파일 확장자만 믿지 않고 모델 참조를 검증한다. 절대 경로, 외부 URL, 상위 경로, 이중 인코딩, 심볼릭 링크/정션을 통한 경계 이탈을 거절한다. 모델의 임의 HTML·JS·오디오와 모션 내 Sound 참조를 실행하지 않는다. 이런 부가 음향은 이번 연동 범위가 아니다.

모델당 파일 256개·합계 128MiB·단일 파일 32MiB, manifest 256KiB, 텍스처 각 변 8192px를 상한으로 삼는다. 초과 모델은 조용히 자르지 않고 지원 불가로 표시한다. 네이티브 클라이언트가 다운로드 크기·해시를 확인한 후에만 전체 모델을 활성화한다. 다운로드 중 변경된 모델은 취소하며 서로 다른 버전의 파일을 섞지 않는다.

Android 자산 캐시는 앱 전용·백업 제외 영역에 최대 두 모델 버전·256MiB로 제한한다. 캐시는 서버 신원별로 격리하고 등록 해제/교체 때 해당 자산을 지운다. 캐릭터 상태·대화는 캐시에 넣지 않는다. 재연결 전에는 이전 개인 캐릭터를 임의로 표시하지 않고, 현재 모델이 확인된 뒤 캐시를 재사용한다.

WebView는 APK의 신뢰된 코드와 검증된 모델 데이터를 앱 내부 HTTPS 출처로만 로드한다. `WebViewAssetLoader` 계열 경로 매핑을 사용하고 파일/콘텐츠 URL 접근, 외부 탐색·팝업·다운로드·혼합 콘텐츠를 차단한다. 허용 경로 밖 요청은 네트워크로 흘려보내지 않는다. JS 메시지는 제한된 타입·크기·출처만 허용하고, 토큰을 가진 네이티브 네트워크 함수를 임의 호출할 수 없게 한다. 운영 빌드 디버깅은 끈다. [Android 앱 내부 콘텐츠 로드 안내](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)

SDK·PIXI·표시 라이브러리의 버전·출처·라이선스 고지를 확인한 뒤 Android에 포함한다. PC에 존재한다는 사실만으로 APK 재배포 권리를 가정하지 않는다. 모델 자체의 사용·기기 간 전송·배포 권한도 별도다. 확인되지 않은 유료/개인 모델은 저장소·테스트·APK에 복사하지 않는다. 필요한 권리가 불명확하면 해당 자산 포함을 중단하고 사용자에게 확인하며, 권한 있는 합성 시험 자산으로 나머지를 진행한다. [Live2D SDK 라이선스 안내](https://www.live2d.com/en/sdk/license/)

## 6. 상태·쓰다듬기·공통 설정

### 6.1 상태 동기화

PC의 공개 캐릭터 스냅샷은 모델 버전, 현재 기본 표정, 공유 움직임 설정, 모델 매개변수 보정값, 상태 revision을 포함한다. 일회성 표정/제스처는 별도 ID로 중복을 제거하며 재접속 때 과거 제스처를 재실행하지 않는다. 동기화 공백은 새 스냅샷으로 복구한다. 메시지 본문을 다시 해석하여 별도 감정 AI를 호출하지 않는다.

마우스/터치 위치·카메라 이동·확대·레이아웃·매개변수 즐겨찾기는 기기별 UI 상태다. 같은 설정을 공유해도 독립된 물리 계산, 시선 입력과 프레임 시간은 다를 수 있다. PC의 캐릭터 렌더러가 아직 준비되지 않아 매개변수 범위를 확인할 수 없으면 원격 설정 쓰기를 거절한다.

### 6.2 쓰다듬기

폰의 포인터 입력은 먼저 로컬 반응을 보여주되, PC가 수락한 세션만 실제 상호작용으로 반영한다. `interaction_id`, 모델 버전, 증가하는 순서 번호로 시작·갱신·종료를 표현한다. 갱신은 초당 10회 이하로 합치고, 절대 화면 좌표 대신 정규화한 영역/강도만 보낸다. PC는 활성화 여부·모델 일치·수치 범위를 검사한다.

PC와 폰의 쓰다듬기는 같은 조정 경계를 사용한다. 동시에 하나만 수락하고 먼저 수락된 세션 동안 반대편 시작은 busy로 거절한다. 같은 세션의 되돌아온 사건은 시각 효과를 두 번 시작하거나 새 입력으로 보내지 않는다. 수락된 정상 종료에서만 기존 PC 쓰다듬기 계수를 한 번 증가시키며 폰이 숫자를 직접 지정할 수 없다.

중복 종료를 무시하고, 완료 ID는 현재 연결에 대해 최대 256개까지 보관한다. 연결 재생성 전 오래된 ID를 재사용할 수 없도록 세대와 단조 증가 번호를 함께 검사한다. 갱신 없이 2초가 지나거나 모델 교체·단절·취소되면 효과를 정리하고 계수를 올리지 않는다. 오프라인 입력을 재연결 뒤 몰아서 반영하지 않는다. 기존 기분·기억 반영 경로를 재사용하며 새로운 AI 호출을 추가하지 않는다.

### 6.3 공통 설정

원격으로 수정할 수 있는 것은 현재 PC 캐릭터 동작에 이미 있는 아래 항목뿐이다. API 키·프롬프트·TTS 공급자·파일 경로·전체 설정 JSON은 이 경로로 읽거나 쓰지 못한다.

- 기본 제공 Idle 모션, ENE 자동 눈깜빡임, ENE 유휴 움직임 켜기/끄기와 강도·속도.
- 표현 움직임 켜기/끄기, 강도·속도·발화 강조·포즈 전환.
- 합성 제스처 크기와 유휴 합성 제스처 활성·빈도.
- 쓰다듬기 활성·강도·전환 시간·허용 표정 ID·종료 표정 유지 시간.
- 현재 모델의 알려진 매개변수 보정값. 기존 PC 모델 키 대신 공개 모델 ID에 대응시킨다.

PC가 허용 키·타입·유한 수치·기존 UI 범위·모델 매개변수 min/max를 검증한다. 폰은 `command_id`와 기준 revision을 포함한 변경분만 보낸다. 오래된 revision은 덮어쓰지 않고 최신 값과 충돌 결과를 반환한다. 슬라이더 미리보기는 로컬에서 하고 손을 놓을 때 저장한다. 알 수 없는 키를 무시한 부분 저장은 하지 않는다.

PC 설정 창과 매개변수 패널에서 저장한 변경도 같은 revision 경계를 통과해 앱에 전달한다. PC 설정 창을 연 뒤 폰이 값을 바꾼 경우, 오래된 창 전체가 공유 키를 덮어쓰지 않도록 변경 키 단위의 revision 검증과 새 값 반영을 한다. 저장 실패는 수락으로 알리지 않으며, 성공 후 한 번만 revision을 올리고 양쪽에 확정값을 보낸다. 응답 유실 시에는 스냅샷으로 실제 값을 확인하고 자동 재시도하지 않는다.

## 7. 검증과 작업 순서

현재 의존성은 순차적이므로 직접 구현한다. 원인 분석·구현·시험을 별도 에이전트로 쪼개지 않고, 의미 있는 통합 체크포인트에서만 명세·품질 리뷰를 한다.

1. 실제 ENE 대화·수락·요청 ID·앱 수명 연결 → 검증: 기존 계획 Task 7~10, 전체 현재 대화/요약/초기화, 중복 요청과 늦은 TTS 콜백, GUI 스레드 소유권.
2. 음성 출력 조정기와 계약 → 검증: 준비 전/후 단절, 허가·완료 유실, 시간 초과, 포커스 거절, 오래된 세대, PC/폰 동시 재생 횟수 0, AI/TTS 생성 횟수 증가 없음.
3. Android PCM 재생과 공유 캐릭터 실행부 → 검증: PCM/WAV 경계, 큐/길이 상한, 재생 위치 립싱크, 상태 재주입, 모델 경로 이탈/해시/버전/용량, 외부 WebView 접근 차단. PC 기존 캐릭터 회귀도 확인한다.
4. 쓰다듬기·공통 설정 → 검증: 중복/순서 역전/동시 입력/유실 종료, 계수 한 번 증가, 잘못된 범위 거절, PC 창과 폰 간 충돌, 저장 실패·모델 교체·연결 종료.
5. 통합 인계 → 검증: PC 전체 자동 테스트, Android 단위 테스트·lint·앱 및 instrumentation APK 빌드, 텍스트 전용 구버전 호환. 실기기 항목은 별도로 남긴다.

테스트는 합성 문장·직접 생성한 PCM·권한을 확인한 시험 모델을 사용한다. 실제 대화·사용자 모델·키 파일을 읽거나 fixture로 복사하지 않는다. 유료 AI/TTS 호출, 방화벽 변경, 단말 설치, 외부 push·릴리스는 이 설계 작업의 검증에 포함하지 않는다.

나중의 실기기 인수에는 QR/TLS 왕복, Android 버전별 오디오 포커스, 홈 이동/잠금/회전/프로세스 종료, 이어폰·블루투스·통화 중단, 느린 LAN/단절, WebGL·메모리·발열·모델 렌더링과 터치 좌표를 포함한다. 이 결과가 없으면 표현은 “소스 구현 및 자동 검증 완료, 단말 인수 미실시”로 제한한다.

## 8. 완료 경계와 다음 문서

이번 문서 검토 뒤 파일별 구현 계획에서 정확한 메시지 스키마·범위 상수·집중 시험 명령·체크포인트를 고정한다. 기존 LAN 계획은 선행 통합을 재사용하고, 미완료 체크를 임의로 완료로 바꾸지 않는다. Android 인계 문서에는 지원 음성 형식·PC 전용 음성 예외·자동 전환 조건·모델 제한·실기기 미검증을 함께 기록한다.

향후 수동 출력 선택은 동일한 출력 정책 입력에 추가할 수 있다. 새로운 PC 기분 로직처럼 공개 텍스트/현재 캐릭터 계약 안에서 표현되는 변화는 앱 재구현 없이 전달할 수 있지만, 새로운 코덱·렌더러·상호작용·설정 UI는 추가 계약과 APK 작업이 필요하다.
