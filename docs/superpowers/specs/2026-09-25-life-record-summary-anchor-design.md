# 생활 기록 요약 기준점 전환 설계

> **대체 결정:** 이 문서의 “요약 저장 시각을 생활 기록 시작 시각으로 사용”하는 결정은 [2026-09-27 세션 종료 기준점 설계](2026-09-27-life-record-session-end-anchor-design.md)로 대체됐다. 현재 동작은 승인·저장된 요약이 있는 세션의 종료 시각부터 임계값과 기록 구간을 계산한다. 이 문서는 변경 이전 설계 기록으로 남긴다.

## 1. 목표

생활 기록의 시작 기준을 모든 ENE 프로세스 종료 시각에서 사용자가 확인하고 저장한 대화 요약의 저장 시각으로 바꾼다. 요약이 없는 테스트 실행과 종료는 기존 기준점을 움직이거나 소비하지 않아야 한다.

자동 요약도 수동 요약과 같은 확인창을 거치게 해, 사용자가 승인한 요약만 장기 기억과 생활 기록 기준점에 반영한다. 생활 기록은 새 실행의 대화 버퍼가 비어 있을 때 받은 첫 일반 메시지 앞에서만 생성한다.

## 2. 문제와 성공 기준

현재 생활 기록은 정상 종료의 `stopped_at`, 비정상 종료의 `last_seen_at`을 시작점으로 사용한다. 이 때문에 기능 점검을 위해 ENE를 잠깐 실행했다가 종료해도 실제 대화와 무관하게 다음 생활 기록의 시작점이 늦춰진다.

변경 후 다음 조건을 만족해야 한다.

- 확인창에서 저장을 승인한 요약만 기준점 후보가 된다.
- 요약을 저장한 실행이 끝난 뒤에만 그 후보를 생활 기록에 사용할 수 있다.
- 생활 기록의 시작 시각은 실행 종료 시각이 아니라 요약 저장 시각이다.
- 요약 없는 실행, 메시지 전송과 종료는 기존 미사용 기준점을 변경하거나 소비하지 않는다.
- 설정한 시간이 되기 전에 메시지를 보내도 기준점을 소비하지 않는다.
- 현재 실행의 대화 버퍼가 비어 있을 때 받은 첫 일반 메시지에서만 자동 생성을 시도한다.
- 한 요약 기준점은 성공한 생활 기록 하나에만 사용한다.
- 자동 요약, 수동 요약과 대화 초기화 전 요약은 같은 확인·저장 경계를 사용한다.
- 생성 또는 저장 실패가 일반 답변을 막지 않으며, 미사용 기준점은 다음 빈 실행까지 보존한다.

## 3. 용어

- **승인 요약**: 자동 또는 수동으로 생성한 후보를 사용자가 확인창에서 승인하고 `memory.json`에 저장까지 완료한 요약이다.
- **세션 요약 후보**: 현재 ENE 프로세스 실행에서 가장 최근에 저장한 승인 요약이다. 같은 실행이 끝나기 전에는 생활 기록을 만들 수 없다.
- **활성 기준점**: 이전 실행에서 확정된 세션 요약 후보다. 요약 ID와 요약 저장 시각을 가진다.
- **사용 완료**: 활성 기준점으로 만든 생활 기록이 권위 저장소에 저장되고 기준점 소비 상태도 확정된 상태다.
- **빈 실행**: 프로세스 시작 시 `conversation_buffer`가 비어 있고 실행 단위 `life_gate_open`이 아직 true인 실행이다. 일반 메시지 commit 또는 비어 있지 않은 대화 버퍼의 요약·초기화가 한 번이라도 완료되면 이 값은 false가 되며 같은 프로세스에서 다시 true가 되지 않는다. 도구 명령과 부수효과 전에 거부된 요청은 이 상태를 소비하지 않는다.

## 4. 확정한 제품 동작

### 4.1 기준점 생성과 활성화

1. 사용자가 요약 확인창에서 저장을 승인한다.
2. 요약이 `memory.json`에 저장된 뒤 현재 세션의 최신 요약 ID와 저장 시각을 세션 상태에 원자 저장한다.
3. 같은 실행에서 다른 요약을 다시 승인하면 최신 승인 요약이 세션 요약 후보를 교체한다.
4. 정상 종료가 완료되면 세션 요약 후보를 활성 기준점으로 승격한다.
5. 비정상 종료에서는 다음 시작 시 이전 `running` 상태와 마지막 heartbeat를 확인한다. 이전 실행에 승인 요약이 있으면 그 요약을 활성 기준점으로 승격하고 복구 출처를 기록한다.
6. 승격할 세션 요약 후보가 없으면 기존 활성 기준점을 그대로 보존한다.
7. 기존 활성 기준점이 사용되지 않았더라도 더 최신 승인 요약이 있는 실행이 끝나면 새 기준점으로 교체한다.

이전 실행에 미완료 claim A와 새 세션 요약 후보 B가 함께 남은 비정상 종료를 복구할 때는 다음 순서를 고정한다.

1. `life_records.json`을 읽고 검증해 claim A의 예상 기록 ID가 존재하는지 확인한다.
2. 기록이 있으면 A를 사용 완료 처리하고, 없으면 claim만 해제해 A를 미사용 기준점으로 되돌린다.
3. 메모리에서 A 조정 결과를 계산한 뒤 B를 활성 기준점으로 승격해 A를 교체한다.
4. A 조정, B 승격과 새 `running` 세션을 포함한 최종 V2 payload를 한 번만 원자 저장한다.

권위 기록을 읽거나 검증할 수 없거나 최종 단일 commit이 실패하면 디스크의 A claim과 B를 원본 상태 그대로 보존하고 생활 기록 쓰기를 읽기 전용으로 닫는다. 중간 payload를 저장하거나 조정하지 못한 상태에서 B를 먼저 승격하거나 A로 생성을 재시도하지 않는다.

종료는 기준점을 활성화하는 경계일 뿐 시작 시각은 아니다. 생활 기록의 `inactive_started_at`은 승인 요약의 실제 저장 시각을 사용한다. 기존 저장 형식과 API 호환을 위해 필드명은 유지하지만 문서와 프롬프트에서는 이를 `요약 기준 생활 구간 시작`으로 설명한다.

새 기록의 `inactive_start_source`는 `summary_graceful_exit` 또는 `summary_heartbeat_recovery`를 사용한다. 기존 기록의 `graceful_exit`와 `heartbeat_recovery` 값은 계속 읽고 재생성할 수 있어야 한다.

### 4.2 자동 생성 게이트

일반 텍스트 또는 첨부 메시지를 실제 대화 버퍼에 반영하기 직전 다음 조건을 모두 검사한다.

- 생활 기록 기능이 켜져 있다.
- 생활 기록 저장소와 세션 상태가 쓰기 가능하다.
- 생활 환경 Markdown이 비어 있지 않다.
- 활성 기준점이 존재하고 아직 사용되지 않았다.
- 활성 기준점을 만든 프로세스 실행이 이미 끝났다.
- 요약 저장 시각부터 현재 요청 수신 시각까지의 절대 시간이 설정값 이상이다.
- 현재 실행의 `conversation_buffer`가 비어 있다.
- 생활 기록 또는 다른 생성 작업과 충돌하지 않는다.

도구 명령, 리롤, 메시지 수정과 수동 생활 기록 재생성은 자동 생성 게이트를 소비하지 않는다. 일반 메시지는 게이트 판정 뒤에 대화 버퍼에 반영되므로 빈 실행의 첫 메시지 자체는 생성 조건을 만족할 수 있다.

임계값 미만, 빈 생활 환경, 기능 비활성화 또는 기타 안전한 생략 조건에서는 일반 대화만 계속하고 활성 기준점을 유지한다. 첫 일반 메시지를 이미 처리한 현재 실행에서는 다시 자동 생성하지 않는다. 다음 프로세스 실행에서 버퍼가 다시 비었을 때 같은 활성 기준점을 재평가한다.

### 4.3 생활 기록의 의미

생활 기록은 더 이상 오직 ENE 프로세스가 꺼져 있던 시간만 표현하지 않는다. 승인 요약 저장 시각부터 복귀 메시지 수신 직전까지 이어진 ENE의 가상 생활을 표현한다. 요약 저장 뒤 같은 실행에서 사용자와 추가 대화를 나눈 시간과 가상 생활은 병행될 수 있다.

생성 프롬프트는 사용자가 전체 구간 동안 돌아오지 않았다고 단정하지 않는다. 첫 복귀 메시지 원문과 요약·대화 원문은 계속 제외하며, 모델에는 요약 기준 시각과 기록 종료 시각, 가상 생활이 대화와 병행될 수 있다는 시간 계약만 전달한다.

### 4.4 기준점 소비와 재시도

- 생성 요청을 시작하기 전에 활성 기준점 ID, 요청 수신 시각과 예상 생활 기록 ID를 포함한 durable claim을 저장한다.
- claim 저장에 실패하면 생활 기록을 호출하지 않고 일반 대화를 계속한다.
- 생성·검증·기록 저장이 실패하면 claim을 해제하고 활성 기준점은 유지한다.
- 실패한 현재 실행에서는 다시 자동 생성하지 않는다. 다음 빈 실행에서 재시도한다.
- 기록 저장이 성공하면 활성 기준점과 claim을 사용 완료 상태로 원자 전환한다.
- 기록 저장 뒤 소비 상태 저장 전에 프로세스가 중단되면 다음 시작에서 예상 기록 ID를 권위 `life_records.json`과 대조한다. 기록이 있으면 생성 없이 소비를 완료하고, 없으면 claim만 해제해 기준점을 다시 사용할 수 있게 한다.
- 시작 시 권위 기록 읽기·검증이 실패하거나 claim 해제·소비 commit이 실패하면 claim을 그대로 보존하고 생활 기록 쓰기를 읽기 전용으로 닫는다. 같은 실행에서 생성 또는 조정을 재시도하지 않는다.

이 복구 방식은 생성 실패 때 기준점을 잃지 않으면서, 저장 성공 직후 중단됐을 때 같은 요약으로 기록을 중복 생성하지 않는다.

## 5. 요약 확인 흐름 통일

### 5.1 수동 요약

현재 흐름을 유지한다. 요약 후보를 만든 뒤 확인창을 표시하며 사용자가 승인한 경우에만 저장한다. 저장 성공 뒤 세션 요약 후보를 갱신한다. 후보 생성, 검토 또는 저장 실패는 기준점을 만들지 않는다.

### 5.2 메시지 수 기반 자동 요약

자동 요약은 더 이상 `_auto_summarize()`에서 곧바로 `add_summary()`를 호출하지 않는다. 수동 요약과 같은 review worker와 승인 저장 경로를 사용한다.

- 최초 자동 제안 기준은 현재 `summarize_threshold`다.
- 임계값에 도달하면 해당 시점까지의 대화 스냅샷으로 확인창을 한 번 표시한다.
- 승인하면 검토 대상 메시지만 저장·제거하고, 검토 중 추가된 메시지는 버퍼에 보존한다.
- 취소하면 저장하지 않고 버퍼를 유지한다.
- 자동 제안을 취소하면 `다음 자동 제안 메시지 수 = 취소 당시 버퍼 길이 + summarize_threshold`로 보류한다.
- 보류 중에도 사용자가 수동 요약을 요청할 수 있다.
- 자동 제안을 승인해 버퍼 일부를 제거하면 남은 버퍼를 기준으로 다음 임계값을 다시 계산한다.
- `summarize_threshold == 0`이면 자동 제안은 비활성화하되 수동 요약은 유지한다.

watermark는 현재 버퍼 좌표계의 절대 메시지 수로 관리한다. 버퍼를 줄이는 동작 뒤에는 다음 규칙으로 다시 계산한다.

- 자동·수동 요약 승인: 검토 대상 prefix를 제거한 직후 `next_count = summarize_threshold`로 재설정한다. 검토 중 보존된 나머지 메시지가 이미 임계값 이상이면 다음 안전한 자동 검사에서 다시 제안할 수 있다.
- 자동 요약 취소: `next_count = 현재 버퍼 길이 + summarize_threshold`로 이동한다.
- 수동 요약 취소: 현재 버퍼가 기존 watermark 이상이면 자동 확인창이 다음 메시지에 즉시 이어지지 않도록 자동 취소와 같은 방식으로 이동하고, 미만이면 기존 watermark를 유지한다.
- 대화 초기화 완료: 버퍼를 비운 뒤 `next_count = summarize_threshold`로 재설정한다.
- 런타임 임계값 변경: 현재 버퍼 길이를 기준으로 새 임계값을 적용하고 이미 열린 review의 대상 스냅샷에는 영향을 주지 않는다.

자동·수동 review에는 내부 origin을 보관한다. 사용자가 보는 요약 내용과 저장 형식은 같지만 취소 origin과 현재 버퍼 길이에 따라 위 규칙대로 watermark를 이동한다.

### 5.3 대화 내역 초기화

대화 초기화 시 남은 메시지가 요약 대상이면 즉시 저장하지 않고 같은 확인창을 표시한다.

- 승인: 요약 저장과 세션 요약 후보 갱신을 완료한 뒤 대상 메시지를 초기화한다.
- 취소: 요약을 저장하지 않고 대상 메시지만 초기화한다.
- 검토 중 새 메시지는 허용하지 않는 기존 생성 잠금을 사용하거나, 허용되는 경로가 있다면 초기화 대상 스냅샷과 새 메시지를 분리해 새 메시지를 보존한다.
- 요약할 메시지가 없으면 확인창 없이 기존 초기화를 수행한다.

초기화용 요약 후보 생성 또는 `memory.json` 저장이 실패하면 초기화를 실행하지 않고 원래 버퍼를 보존한다. 기억 저장은 성공했지만 tracker 등록만 실패했다면 승인 요약 자체는 이미 durable하므로 검토 대상 메시지를 초기화하되 생활 기록 쓰기를 읽기 전용으로 전환하고 오류를 알린다.

종료 전 요약 검토도 같은 승인 저장 경계를 사용한다. 종료는 요약 저장과 세션 상태 commit이 완료된 뒤 진행한다. 사용자가 최초 종료 확인에서 요약 없이 종료를 선택한 경우에만 바로 종료한다. 요약 후보 생성 실패, `memory.json` 저장 실패 또는 review 취소는 종료를 중단하고 앱과 버퍼를 유지한다. 기억 저장 뒤 tracker 등록이 실패하면 생활 기록을 읽기 전용으로 전환하고 종료를 중단해 오류를 사용자에게 보여준다. 사용자는 다시 종료해 요약 없이 종료를 명시적으로 선택할 수 있다.

`memory.json` 저장 성공 뒤 tracker 등록만 실패한 경우, 요약 자체는 이미 durable하므로 모든 review origin에서 검토 대상 prefix를 요약 완료 처리해 버퍼에서 제거한다. 일반 수동·자동 review는 오류를 알리고 계속하며, 초기화 review는 나머지 초기화를 완료한다. 종료 review는 prefix를 제거하되 종료는 중단한다. 이 규칙은 같은 원문이 다음 review에서 중복 저장되는 것을 막으며, tracker 등록에 실패한 요약은 생활 기록 기준점으로 사용하지 않는다.

## 6. 세션 상태 V2

`life_session_state.json`을 버전 2로 올리고 기존 세션 생존 정보에 다음 논리 상태를 추가한다.

- 현재 세션의 최신 승인 요약: `summary_id`, `saved_at`
- 이전 실행에서 활성화된 미사용 기준점: `summary_id`, `saved_at`, `activation_source`, `origin_session_started_at`, `origin_session_ended_at`
- 진행 중 생성 claim: `summary_id`, `returned_at`, `expected_record_id`

실제 JSON 키와 중첩 구조는 구현 계획에서 현재 strict parser 스타일에 맞춰 확정한다. 다음 불변조건을 지켜야 한다.

- 모든 시각은 timezone-aware ISO 8601이며 정수 초로 canonicalize한다.
- 현재 세션 요약과 활성 기준점의 `summary_id`는 비어 있지 않은 문자열이다.
- claim의 요약 ID는 활성 기준점과 같아야 한다.
- claim의 예상 기록 ID는 기존 안정 ID 함수의 결과와 같아야 한다.
- `running`과 `stopped`의 기존 시간 순서, UUIDv4와 단일 프로세스 lease 규칙을 유지한다.
- heartbeat는 생존 시각만 갱신하고 요약·기준점·claim 상태를 보존한다.
- 요약 등록, 정상 종료 승격, 비정상 종료 복구, claim 시작·해제·완료는 모두 현재 세션 소유권을 다시 확인한 뒤 원자 저장한다.

새 시각에는 다음 순서 불변조건을 적용한다.

- 승인 요약 등록 시 tracker의 canonical clock을 다시 읽고 `summary_saved_at = max(now, persisted_last_seen_at, 이전 세션 요약 saved_at)`으로 정규화한다. 같은 commit에서 `last_seen_at`도 이 값 이상으로 올린다. `memory.json`의 표시 timestamp와 별개로 이 canonical 시각이 생활 기록 기준의 권위값이다.
- 현재 세션 요약은 `started_at <= summary_saved_at <= last_seen_at`을 만족한다.
- 활성 기준점은 자체 보관한 원본 세션 경계에 대해 `origin_session_started_at <= saved_at <= origin_session_ended_at`을 만족해야 한다. 정상 종료 승격은 현재 `started_at`과 `stopped_at`, heartbeat recovery는 이전 `started_at`과 `last_seen_at`을 이 두 필드로 저장한다. V2 strict parser는 활성 기준점을 읽을 때마다 이 순서를 검증한다.
- claim의 `returned_at`은 `max(request_received_at, current.started_at, current.last_seen_at, active.saved_at)`으로 정규화하며, 같은 commit에서 현재 `last_seen_at`도 후퇴하지 않는다.
- 시스템 clock이 후퇴하면 위 `max` 규칙으로 단조 증가시킨다. overflow, timezone 해석 실패 또는 순서 불변조건을 만족할 수 없는 값은 clamp하지 않고 fail-closed로 거부한다.

### 6.1 V1 마이그레이션

- 정확한 V1 키와 불변조건을 만족하는 파일만 V2로 마이그레이션한다.
- V1의 종료 시각은 승인 요약 기준점으로 변환하지 않는다.
- V2의 요약·활성 기준점·claim 필드는 모두 빈 상태로 시작한다.
- 마이그레이션 뒤 현재 `running` 상태 commit이 성공한 경우에만 생활 기록 쓰기를 허용한다.
- 기존 `memory.json`의 과거 요약을 검색해 소급 기준점을 만들지 않는다.
- 손상되거나 알 수 없는 버전은 현재 fail-closed 복구 원칙을 유지한다.

따라서 업데이트 직후에는 새 승인 요약을 저장하고 해당 실행을 종료한 뒤부터 새 자동 생활 기록을 만들 수 있다. 기존 `life_records.json`의 기록은 계속 조회하고 최신 기록 맥락으로 사용할 수 있다.

## 7. 구성 요소 변경

### 7.1 `MemorySummaryBridgeMixin`

- 모든 자동 저장 경로를 review worker로 통일한다.
- pending review에 `origin`과 완료 후 행동을 저장한다.
- 승인 저장 성공 후 tracker에 요약 ID와 실제 저장 시각을 등록한다.
- 자동 취소 watermark와 대화 초기화 승인·취소 후속 동작을 관리한다.
- 요약 저장과 tracker 등록 중 하나만 성공하는 경우를 안전하게 처리한다. 요약은 이미 권위 메모리에 저장됐더라도 tracker 등록 실패 시 생활 기록 기준점으로 사용하지 않고 생활 기록 쓰기를 읽기 전용으로 전환한다. 저장된 review prefix는 모든 origin에서 요약 완료 처리하되 종료 origin만 실제 종료를 중단한다.

### 7.2 `AppSessionTracker`

- V1/V2 parser와 V2 writer를 제공한다.
- 승인 요약 등록, 활성 기준점 조회, generation claim, claim 해제·완료 API를 소유한다.
- 정상 종료에서 현재 세션 요약을 활성 기준점으로 승격한다.
- 비정상 종료 복구에서 이전 실행에 승인 요약이 있을 때만 활성화한다.
- 요약 없는 실행의 시작·heartbeat·종료에서도 기존 활성 기준점을 보존한다.

### 7.3 `LifeRecordBridgeMixin`

- 프로세스 시작 시 버퍼가 비어 있을 때만 `life_gate_open=true`로 두고, 버퍼가 비어 있으며 이 값이 true인 일반 요청만 활성 기준점을 평가한다.
- 일반 요청이 보류 요청으로 안전하게 접수되어 생활 기록 생성을 시작했거나 일반 대화 버퍼 commit이 성공하면 `life_gate_open=false`로 바꾼다.
- 비어 있지 않은 버퍼를 요약하거나 초기화하는 동작도 완료 시 `life_gate_open=false`로 고정한다. 버퍼가 다시 비어도 되돌리지 않는다.
- busy·입력 검증·첨부 파싱 단계에서 거부되거나 일반 대화 commit이 실패해 롤백된 요청은 gate 기회를 소비하지 않는다.
- claim 저장 실패는 생활 기록 호출만 생략하고 같은 요청을 일반 대화로 처리한다. 그 일반 대화 commit이 성공하면 `life_gate_open=false`, commit도 실패하면 true를 유지한다.
- 첫 일반 요청이 임계값 미만, 빈 세계, 기능 비활성화 같은 안전한 생략으로 정상 commit되면 현재 실행의 gate 기회는 끝나지만 durable 기준점은 유지한다.
- 요약 승인이나 대화 초기화로 버퍼가 다시 비어도 `life_gate_open`을 true로 되돌리지 않는다.
- 임계값 미만과 안전한 생략은 durable 기준점을 소비하지 않는다.
- 생성 전에 claim을 시작하고 성공·실패 finalizer에서 claim을 완료하거나 해제한다.
- 시작 시 미완료 claim과 권위 기록 저장소를 조정한다.

### 7.4 프롬프트와 기록 계약

- 새 source 값 두 개를 parser, serializer와 프롬프트 계약에 추가한다.
- 과거 source 값 두 개는 호환 읽기와 최신 기록 재생성을 위해 유지한다.
- `inactive_started_at`의 저장 키는 유지하되 새 source에서는 승인 요약 저장 시각을 뜻한다.
- `사용자가 구간 전체에 없었다`는 기존 문구를 제거하고 병행 가능한 가상 생활 구간으로 표현한다.

### 7.5 설정과 문서

- `최소 비활성 시간`을 `요약 후 최소 시간`에 해당하는 ko/en/ja 문구로 바꾼다.
- 설정 힌트에 승인 요약, 실행 종료, 빈 새 실행의 첫 일반 메시지 조건을 설명한다.
- README와 `docs/life_records.md`의 종료 기준 설명, 백업·복구와 오류 동작을 갱신한다.
- `life_session_state.json`은 계속 사용자 런타임 파일이며 저장소나 릴리스에 포함하지 않는다.

## 8. 오류 처리

- 자동 요약 후보 생성 실패: 확인창을 열지 않고 기존 버퍼와 자동 제안 watermark를 유지한다.
- 요약 저장 실패: 메시지를 제거하거나 기준점을 등록하지 않는다.
- 요약 저장 성공·tracker 등록 실패: 저장된 기억은 보존하되 생활 기록 기준점으로 사용하지 않고 세션 추적을 fail-closed로 둔다.
- tracker 등록 실패 review: 모든 origin에서 저장된 대상 prefix를 요약 완료 처리한다. 일반 수동·자동은 계속하고, 초기화는 완료하며, 종료 review는 종료를 중단한다.
- 자동 검토 취소: 버퍼를 유지하고 다음 자동 제안 watermark만 이동한다.
- 초기화 검토 취소: 저장 없이 초기화한다.
- 정상 종료 상태 저장 실패: 현재 세션 요약을 활성화하지 않는다. 다음 시작에서 유효한 `running` 상태가 남았다면 heartbeat recovery 규칙을 적용한다.
- 생활 기록 claim 저장 실패: LLM을 호출하지 않는다.
- 생활 기록 생성·검증·저장 실패: 일반 답변을 계속하고 기준점을 보존한다.
- 기록 저장 뒤 소비 commit 실패: 다음 시작에서 예상 기록 ID를 확인해 중복 호출 없이 소비 상태를 복구한다.
- claim 해제·소비 commit 실패 또는 권위 기록 읽기 실패: authoritative claim을 보존하고 생활 기록 쓰기를 읽기 전용으로 닫는다.
- 손상된 V2 상태: 이전 기준점을 추정하지 않고 생활 기록 쓰기를 닫으며 일반 채팅과 유효한 기존 기록 열람은 계속한다.

로그에는 요약 ID나 원문, 생활 환경과 기록 내용을 출력하지 않는다. 안전한 상태 코드, 메시지 수, 성공·실패 여부만 남긴다.

## 9. 테스트 설계

### 9.1 요약 검토

- 자동 임계값 도달 시 직접 저장하지 않고 확인창을 표시한다.
- 자동 승인, 취소, 재생성과 검토 중 추가 메시지 보존을 검증한다.
- 자동 취소 뒤 임계값만큼 메시지가 추가되기 전에는 다시 표시하지 않는다.
- 자동 보류 중 수동 요약을 실행할 수 있다.
- 승인 뒤 검토 대상만 버퍼에서 제거하고 남은 메시지에 다음 임계값을 적용한다.
- 수동 승인·취소와 대화 초기화 뒤 watermark 재설정을 검증한다.
- 대화 초기화 승인 시 저장 뒤 초기화하고 취소 시 저장 없이 초기화한다.
- 초기화용 후보 생성·기억 저장 실패는 버퍼를 보존하고, tracker 등록 실패는 초기화 후 read-only로 전환한다.
- 종료 review의 후보 생성·기억 저장 실패와 취소는 종료를 중단하고, 명시적인 요약 없는 종료만 바로 종료한다.
- 승인되지 않은 후보와 저장 실패는 tracker를 갱신하지 않는다.

### 9.2 세션 상태와 마이그레이션

- V1 유효 상태를 기준점 없는 V2로 마이그레이션한다.
- V1 종료 시각과 기존 과거 요약을 소급 기준점으로 사용하지 않는다.
- 승인 요약이 있는 정상 종료와 heartbeat recovery가 요약 저장 시각을 활성화한다.
- 요약 없는 실행·heartbeat·종료가 기존 기준점을 보존한다.
- 같은 실행의 최신 승인 요약이 이전 후보를 교체한다.
- 새 승인 요약이 있는 실행 종료가 이전 미사용 기준점을 교체한다.
- claim A와 새 세션 요약 B가 함께 남은 비정상 종료에서 A 조정 뒤 B를 승격한다.
- A 조정, B 승격과 새 `running` 세션은 중간 저장 없이 하나의 최종 payload로 commit한다.
- 권위 기록 읽기·검증, claim 해제·소비 commit 실패는 원본 claim을 보존하고 read-only로 전환한다.
- summary·active·claim 시각과 활성 기준점의 원본 세션 경계, clock rollback 단조 증가 규칙을 검증한다.
- strict keys, timezone, UUID, 시간 순서, lease, clock rollback과 원자 저장 불변조건을 유지한다.
- 요약 등록과 종료 commit 실패는 fail-closed로 처리한다.

### 9.3 생활 기록 게이트

- 임계값 바로 전에는 생략하고 정확한 경계에서는 생성한다.
- 임계값 전 첫 메시지는 기준점을 소비하지 않는다.
- 같은 실행의 이후 메시지는 시간이 지나도 생성하지 않는다.
- 요약 없이 종료한 뒤 다음 빈 실행에서 기존 기준점을 다시 평가한다.
- 현재 버퍼가 비어 있는 첫 텍스트·첨부 메시지만 생성할 수 있다.
- 버퍼를 요약·초기화로 다시 비워도 같은 실행의 gate가 재활성화되지 않는다.
- 시작 시 비어 있지 않은 버퍼와 비어 있지 않은 버퍼의 요약·초기화가 gate를 영구히 닫는지 검증한다.
- busy·파싱·검증 거부와 commit rollback은 gate를 소비하지 않으며 정상 commit만 소비한다.
- claim 저장 실패 뒤 일반 대화 commit 성공·실패에 따른 gate 상태를 검증한다.
- 도구 명령은 버퍼 조건과 기준점을 소비하지 않는다.
- 기능 비활성화, 빈 세계, read-only 상태와 충돌 작업은 기준점을 소비하지 않는다.
- 새 source 값으로 만든 기록과 기존 source 기록의 조회·재생성을 모두 검증한다.

### 9.4 실패와 멱등성

- claim 실패 시 공급자를 호출하지 않는다.
- claim 실패 뒤 일반 대화 commit이 성공하면 현재 실행의 gate를 닫고, commit도 실패하면 gate를 유지한다.
- 생성·검증·저장 실패 뒤 기준점과 일반 답변을 보존한다.
- 실패한 실행에서 재시도하지 않고 다음 빈 실행에서 재시도한다.
- 성공한 기록은 기준점을 정확히 한 번 소비한다.
- 기록 저장 전·후와 소비 commit 전·후의 중단 복구가 기록을 잃거나 중복 생성하지 않는다.
- 최신 승인 요약이 기존 미사용 기준점을 교체할 때 stale claim과 늦은 callback을 거부한다.

### 9.5 통합 검증

각 구현 단계에서는 직접 관련된 집중 테스트만 실행한다. 자동 요약 review, 세션 상태 V2와 생활 기록 gate를 연결한 통합 지점 및 최종 완료 전에는 전체 테스트를 실행한다. 기존 요약·메모리, 종료 review, 생활 기록 생성·재생성, 앱 shutdown과 ko/en/ja UI 회귀를 포함한다.

## 10. 개인정보와 공개 저장소 안전

- 테스트와 문서에는 합성 날짜, 일반 장소와 중립 문장만 사용한다.
- 실제 대화, 사용자 프로필, 일정, 건강 정보와 프롬프트 원문을 fixture나 예시에 사용하지 않는다.
- `memory.json`, `life_session_state.json`, `life_records.json`과 사용자 `prompts/**`를 커밋하지 않는다.
- 요약 ID, 요약 원문, 생활 기록 원문과 첫 일반 메시지를 로그에 남기지 않는다.
- 커밋 전에 개인정보 후보와 API 키 패턴, 런타임 파일 추적 여부를 검사한다.

## 11. 제외 범위

- 실행 중 메시지의 의미를 분석해 테스트 대화와 실제 대화를 자동 구분하는 기능
- 기존 과거 요약에서 기준점을 소급 생성하는 기능
- 생활 기록 생성 조건을 수동으로 켜고 끄는 별도 버튼
- 저장된 과거 생활 기록의 스키마 키 변경이나 일괄 재작성
- 자동 요약 확인창의 새로운 시각 디자인

## 12. 결정 기록

- 기준 시각: 사용자가 확인하고 저장한 최신 요약의 저장 시각
- 활성화 경계: 해당 요약을 저장한 프로세스 실행의 정상 종료 또는 heartbeat recovery
- 자동 요약: 직접 저장하지 않고 수동 요약과 같은 확인창 사용
- 자동 취소: 현재 버퍼 길이에서 설정 임계값만큼 추가된 뒤 재제안
- 대화 초기화: 승인 시 저장 후 초기화, 취소 시 저장 없이 초기화
- 생성 시점: 빈 새 실행의 첫 일반 메시지 처리 직전
- 임계값 전 메시지: 기준점을 소비하지 않음
- 요약 없는 실행: 기존 기준점을 변경하지 않음
- 새 승인 요약: 실행 종료 시 이전 미사용 기준점을 교체
- 성공 기준: 권위 기록 저장과 durable 소비 상태 완료
- 실패 기준: 일반 답변 계속, 기준점 보존, 다음 빈 실행에서 재시도
- 마이그레이션: V1 종료 시각과 기존 과거 요약을 소급 기준점으로 사용하지 않음
