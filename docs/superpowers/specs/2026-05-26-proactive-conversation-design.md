# ENE 선제 대화 V1 설계

## 목표

ENE가 대화 맥락을 보고 나중에 먼저 말을 걸면 자연스러운 순간을 예약하고, 사용자가 그 전에 새 메시지를 보내지 않았을 때 짧은 선제 발화를 생성한다.

이번 V1은 단순 리마인더가 아니라 사람과 메시지를 주고받는 느낌을 만드는 기능이다. ENE는 사용자가 명시한 약속뿐 아니라, 대화의 여운, 잠깐 끊긴 흐름, 다시 이어 말하면 좋을 작은 계기를 보고 선제 대화 예약을 만들 수 있어야 한다.

## 배경

현재 ENE에는 두 가지 인접 기능이 있다.

- 대화 약속: 사용자가 나중에 하자고 한 일을 정해진 시각에 다시 꺼낸다.
- Away nudge: 사용자가 오래 말하지 않으면 유휴 상태를 보고 말을 건다.

선제 대화는 이 둘과 다르다. 약속처럼 명시적인 해야 할 일을 다루지 않고, away nudge처럼 단순히 오래 조용한 상태만 보지도 않는다. LLM이 현재 대화 흐름에서 "조금 뒤에 에네가 먼저 말을 걸면 자연스러운지"를 판단하고, 그 시점에 사용할 생성 프롬프트를 예약한다.

## 범위

### 포함

- 선제 대화 전용 매니저 `ProactiveConversationManager` 추가
- 사용자 데이터 저장 파일 `proactive_conversations.json` 사용
- LLM 응답 계약에 선제 대화 예약 블록 추가
- 특정 키워드나 고정 상황이 없어도, LLM이 추후 짧게 이어 말하면 자연스럽다고 판단한 일반 선제 대화 예약 허용
- 예약 필드: `trigger_at`, `title`, `generation_prompt`, `source_excerpt`, `reason`, `cooldown_key`
- `cooldown_key`는 LLM 자유 문자열이 아니라 사전 정의된 그룹 값 중 하나를 사용
- 런타임 관리 필드: `id`, `status`, `created_at`, `updated_at`
- 기본 쿨다운 20분
- 같은 사용자 발화 턴에서 최대 1개만 저장
- 예약 시간 전에 사용자가 새 메시지를 보내면 pending 예약 취소
- 예약 시간이 되었고 사용자 응답이 없으면 `generation_prompt`로 ENE 응답 생성
- 응답 생성 중이면 기존 약속 큐와 같은 방식으로 대기 후 실행
- 파서, 매니저, 브리지 실행/취소 흐름 테스트 추가

### 제외

- 선제 발화 문장 스타일이나 생성 프롬프트 템플릿을 코드 enum으로 고정
- 키워드 기반 로컬 추출
- 선제 대화 예약 승인 UI
- 선제 대화 목록 UI
- 반복 선제 대화
- 장기 캠페인형 대화 목표
- 별도 LLM 호출로 예약 후보만 다시 판단하는 구조

## 설계 원칙

- LLM이 자연스러움을 판단하되, 코드는 빈도와 시간 범위를 엄격히 제한한다.
- 저장하는 것은 최종 대사가 아니라 나중에 대사를 만들기 위한 `generation_prompt`다.
- 선제 발화는 한두 문장으로 끝나는 가벼운 대화 시도여야 한다.
- 사용자가 새 메시지를 보내면 사용자의 현재 흐름을 우선하고, 아직 실행되지 않은 선제 대화는 취소한다.
- 사전 정의된 `cooldown_key`로 유사한 선제 발화가 계속 생기는 문제를 막는다.
- 실제 사용자 대화 원문은 테스트와 문서 fixture에 넣지 않고 합성 예시만 쓴다.

## 출력 계약

LLM은 선제 대화가 자연스럽다고 판단할 때만 아래 블록을 응답 끝부분에 추가한다.

```text
[proactive_conversation]
trigger_at=2026-05-26T21:20:00+09:00
title=가벼운 확인
generation_prompt=사용자가 잠시 확인할 일이 있다고 했고 아직 답장이 없다. 부담스럽지 않게 끝났는지 짧게 물어봐.
source_excerpt=잠시 확인하고 돌아온다는 흐름
reason=대화가 잠시 끊겼고 짧은 확인 발화가 자연스러움
cooldown_key=short-followup
[/proactive_conversation]
```

필드 의미는 다음과 같다.

- `trigger_at`: LLM이 현재 시각과 대화 맥락을 보고 정한 실행 시각이다. 반드시 ISO 8601 형식과 `+09:00` 오프셋을 사용한다.
- `title`: 내부 로그와 디버깅에 쓸 짧은 제목이다.
- `generation_prompt`: 실행 시점에 ENE 응답을 생성하기 위해 다시 LLM에 전달할 프롬프트다.
- `source_excerpt`: 실제 원문 복사가 아니라 예약 판단 근거를 짧게 재서술한 문구다.
- `reason`: 왜 지금 이 예약이 자연스러운지에 대한 내부 설명이다.
- `cooldown_key`: 비슷한 예약을 묶는 사전 정의 그룹 키다. 허용 값이 아니면 런타임에서 `global-proactive`로 취급한다.

## 예약 판단 정책

V1은 선제발화 문장 스타일이나 생성 프롬프트 템플릿을 고정하지 않는다. LLM은 대화 흐름을 보고 자유롭게 `generation_prompt`를 작성한다.

일반 선제 대화도 V1 범위에 포함한다. 다만 완전한 난수 발화가 아니라, 현재 대화에서 이어 말할 작은 계기나 여운이 있을 때 "나중에 한 번 말을 걸어볼 프롬프트"를 미리 정해두는 방식이다.

`cooldown_key`는 예외적으로 사전 정의된 값만 사용한다. 이 값은 ENE가 어떤 말을 할지 정하는 타입이 아니라, 비슷한 선제 대화가 너무 자주 예약되지 않도록 묶는 반복 방지 그룹이다.

V1 허용 값은 다음과 같다.

- `short-followup`: 사용자가 잠깐 끊긴 흐름으로 돌아올지 가볍게 확인하는 예약
- `quiet-checkin`: 대화가 조용해진 뒤 ENE의 존재감이 느껴지는 짧은 확인 예약
- `topic-reopen`: 조금 전에 나온 주제나 생각을 짧게 다시 꺼내는 예약
- `task-momentum`: 사용자가 하던 흐름을 부담 없이 다시 이어가게 돕는 예약
- `global-proactive`: 위 그룹이 애매하거나 값이 비었을 때 쓰는 기본 그룹

허용되는 흐름의 예시는 다음과 같다.

- 사용자가 잠시 다른 일을 한다고 말해 대화가 자연스럽게 끊긴 경우
- 사용자가 답을 고민하거나 확인해보겠다고 한 경우
- 대화가 살짝 조용해진 뒤 ENE가 한 번 이어 말하면 관계감이 생기는 경우
- 특정 약속은 아니지만 나중에 짧게 다시 꺼내면 좋은 주제가 생긴 경우

금지되는 흐름은 다음과 같다.

- 사용자가 명확히 대화를 끝내거나 방해받고 싶지 않다고 한 경우
- 민감한 건강, 취업, 가족, 사생활 내용을 근거로 집요하게 파고드는 경우
- 이미 대화 약속이 생성된 같은 턴에서 의미가 겹치는 선제 대화를 추가하는 경우
- 같은 `cooldown_key`의 쿨다운이 아직 끝나지 않은 경우
- 허용되지 않은 `cooldown_key`를 새 그룹처럼 만들어내는 경우
- 현재 응답이 단순 정보 답변이라 추후 이어 말할 이유가 약한 경우

## 시간 가드레일

`trigger_at`은 LLM이 판단한다. 다만 저장 전 런타임이 아래 규칙으로 검증한다.

- 과거 시각이면 저장하지 않는다.
- 현재 시각에서 1분 미만이면 저장하지 않는다.
- 현재 시각에서 60분 초과면 저장하지 않는다.
- 파싱할 수 없는 시각이면 저장하지 않는다.
- 같은 사용자 발화 턴에서 이미 선제 대화가 저장되었으면 추가 저장하지 않는다.
- 예약 시각이 10분 이상 지난 항목은 자동 실행하지 않고 `expired`로 바꾼다.

V1에서 보정 저장은 하지 않는다. 시간이 이상하면 LLM 판단 실패로 보고 예약을 버린다. 이렇게 해야 ENE가 예측하기 어려운 시점에 갑자기 말하는 위험을 줄일 수 있다.

## 쿨다운 정책

기본 쿨다운은 20분이다.

- 같은 `cooldown_key`는 마지막 예약, 실행, 취소 시각 중 가장 최근 시각부터 20분 동안 새로 저장하지 않는다.
- `cooldown_key`가 비어 있거나 허용 값이 아니면 `global-proactive`로 정규화한다.
- V1은 전체 선제 대화도 20분 전역 쿨다운을 공유한다. 즉 서로 다른 `cooldown_key`라도 너무 자주 말 걸지 않는다.
- V1에서는 그룹별 쿨다운 길이를 다르게 두지 않는다. 모든 그룹은 20분을 사용한다.
- 사용자가 새 메시지를 보내 예약이 취소되어도 쿨다운은 남긴다. 이 규칙은 매 턴마다 예약이 다시 생기는 어색함을 막기 위한 것이다.

## 데이터 모델

저장 항목은 다음 구조를 가진다.

```json
{
  "id": "uuid",
  "trigger_at": "2026-05-26T21:20:00+09:00",
  "title": "가벼운 확인",
  "generation_prompt": "사용자가 잠시 확인할 일이 있다고 했고 아직 답장이 없다. 부담스럽지 않게 끝났는지 짧게 물어봐.",
  "source_excerpt": "잠시 확인하고 돌아온다는 흐름",
  "reason": "대화가 잠시 끊겼고 짧은 확인 발화가 자연스러움",
  "cooldown_key": "short-followup",
  "status": "scheduled",
  "created_at": "2026-05-26T21:10:00+09:00",
  "updated_at": "2026-05-26T21:10:00+09:00"
}
```

상태는 V1에서 최소한 다음 값을 사용한다.

- `scheduled`: 아직 실행되지 않은 예약
- `queued`: 현재 응답 생성 중이라 실행 대기 중인 예약
- `triggered`: 실행을 시작한 예약
- `cancelled`: 사용자 새 메시지로 취소된 예약
- `expired`: 실행 가능 시간이 지나 폐기된 예약

## 데이터 흐름

### 저장 흐름

1. 사용자가 메시지를 보낸다.
2. ENE가 기존 응답 파이프라인으로 답변을 생성한다.
3. LLM 응답 파서가 `[proactive_conversation]` 블록을 추출한다.
4. 브리지가 선제 대화 매니저에 저장을 요청한다.
5. 매니저가 시간 가드레일, 전역 쿨다운, `cooldown_key` 쿨다운, 턴당 1개 제한을 검사한다.
6. 통과한 예약만 `proactive_conversations.json`에 저장한다.
7. 저장 실패는 사용자에게 노출하지 않고 로그 수준에서만 남긴다.

### 취소 흐름

1. 사용자가 새 메시지를 보낸다.
2. 브리지는 아직 실행되지 않은 `scheduled` 선제 대화를 취소한다.
3. 취소된 항목의 `status`를 `cancelled`로 바꾸고 `updated_at`을 갱신한다.
4. 같은 `cooldown_key`와 전역 쿨다운은 유지한다.

### 실행 흐름

1. 브리지 타이머가 주기적으로 도래한 선제 대화를 확인한다.
2. 예약 시각이 되었고 아직 사용자 새 메시지가 없으면 실행 대상으로 고른다.
3. 현재 AI 워커가 실행 중이면 `queued`로 바꾸고 큐에 넣는다.
4. 워커가 비어 있으면 `triggered`로 바꾸고 `_start_ai_worker()`를 호출한다.
5. `_start_ai_worker()`에는 `generation_prompt`를 현재 시각과 함께 전달한다.
6. 응답이 완료되면 기존 대화 흐름처럼 conversation buffer에 assistant 메시지로 남는다.

## 기존 기능과의 관계

### 대화 약속

대화 약속은 사용자가 하겠다고 한 일이나 정해진 시간의 후속 대화를 다룬다. 선제 대화는 사용자가 명시적으로 약속하지 않아도 ENE가 나중에 짧게 이어 말할 계기를 다룬다.

같은 턴에서 둘이 동시에 감지되면 대화 약속을 우선한다. 약속이 이미 명시된 상황에서 선제 대화까지 추가하면 같은 맥락을 두 번 말할 위험이 크기 때문이다.

### Away nudge

Away nudge는 마지막 사용자 메시지 이후 긴 유휴 시간과 시스템 입력 상태를 본다. 선제 대화는 LLM이 저장한 특정 실행 시각과 대화 맥락을 본다.

두 기능이 같은 시점에 실행되려 하면 현재 응답 큐 정책을 공유한다. V1에서는 대화 약속, 선제 대화, away nudge 순으로 우선순위를 둔다.

## 테스트 전략

1. 파서 테스트
   - 올바른 `[proactive_conversation]` 블록을 구조화한다.
   - 필수 필드가 없으면 예약을 버린다.
   - 일반 본문에서 블록을 제거하고 사용자에게 보이는 응답을 보존한다.

2. 매니저 테스트
   - 저장/로드 roundtrip을 검증한다.
   - 과거 시각, 너무 가까운 시각, 너무 먼 시각을 거부한다.
   - 같은 `cooldown_key`와 전역 쿨다운을 막는다.
   - 사용자 새 메시지 시 pending 예약을 `cancelled`로 바꾼다.

3. 브리지 테스트
   - 사용자 메시지 전송 시 기존 pending 선제 대화가 취소된다.
   - due 예약이 있으면 `_start_ai_worker()`에 `generation_prompt`가 전달된다.
   - 워커 실행 중이면 큐에 들어가고, 응답 완료 후 drain된다.
   - 같은 턴에서 대화 약속이 저장되면 선제 대화 저장은 생략된다.

4. 회귀 테스트
   - 기존 대화 약속 테스트가 그대로 통과한다.
   - away nudge 테스트가 그대로 통과한다.
   - 전체 `python -m pytest -q`를 통과한다.
