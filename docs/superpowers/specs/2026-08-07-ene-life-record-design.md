# 에네 비활성 생활 기록 V1 설계

## 1. 목표

에네 프로세스가 종료된 뒤 사용자가 다음 실행 세션에서 처음 일반 대화를 시작하면, 그 사이 에네가 가상 생활 환경에서 무엇을 했는지 시간순 기록으로 생성한다. 생성된 최신 기록은 에네의 일반 대화 맥락에 연결하고, 전체 기록은 날짜별로 읽기 전용 탐색할 수 있게 보관한다.

이 기능은 미완성 2D 마을 기능을 다시 구현하지 않는다. 기존 2D 월드 설계의 장소·활동·연속성 개념만 가져와 자유형 텍스트 세계관과 구조화된 생활 기록으로 축소한다.

## 2. V1 성공 기준

- 정상 종료에서는 실제 ENE 프로세스 종료 시각부터, 비정상 종료에서는 마지막 생존 확인 시각부터 다음 실행 후 첫 일반 대화 시각까지의 전체 구간을 기록한다.
- 비활성 구간이 설정된 최소 시간 이상일 때만 기록을 생성한다.
- 첫 일반 답변보다 먼저 기록을 생성하고, 성공한 최신 기록을 그 답변의 맥락에 포함한다.
- 기록 항목 사이에 공백이나 겹침이 없고 전체 시작·종료 시각이 실제 구간과 정확히 일치한다.
- 직전 생활 기록 한 개를 참고해 장소와 상태의 연속성을 유지하되 과거 전체를 누적하지 않는다.
- 우측 상단 `···` 메뉴에서 오늘과 과거 날짜의 기록을 읽기 전용으로 탐색할 수 있다.
- 최신 기록만 사용자가 수동 재생성할 수 있다.
- 생성 또는 저장 실패가 일반 채팅을 막지 않는다.
- 사용자 데이터, 프롬프트 원문, 생활 기록 문장은 진단 로그나 공개 테스트 자료에 남지 않는다.

## 3. 확정 범위

### 3.1 비활성 구간

- 복귀 공백의 확정 시작점은 정상 종료에서는 직전 ENE 프로세스의 `stopped_at`, 비정상 종료에서는 마지막 `last_seen_at`이다.
- 비활성 구간의 끝은 다음 앱 실행 후 사용자가 보낸 첫 일반 대화의 수신 시각이다.
- 앱이 먼저 실행되고 나중에 첫 대화를 받았더라도 종료 시각부터 첫 대화 시각까지를 하나의 복귀 공백으로 다룬다.
- 창 숨김, 최소화, 트레이 상주, 실행 중 무대화는 생활 기록 생성 조건이 아니다. 실행 중 자리 비움은 기존 자리 비움 기능의 책임이다.
- 첫 설치처럼 이전 실행 정보가 없으면 기록을 만들지 않는다.
- `/note`, `/obs`, `/diary` 같은 도구 명령은 첫 일반 대화 상태를 소비하지 않는다.
- 일반 텍스트와 첨부 대화는 모두 첫 일반 대화가 될 수 있다.

### 3.2 설정

- `생활 기록 사용` 기본값은 비활성화다.
- `최소 비활성 시간` 기본값은 60분이다.
- 최소 비활성 시간은 설정에서 분 단위 양의 정수로 바꿀 수 있다.
- 실제 구간이 임계값과 같거나 길 때만 생성한다.
- 조건 미충족 시 새 LLM 호출과 새 기록 저장만 생략한다. 기능이 켜져 있고 기존 최신 성공 기록이 있으면 그 기록의 일반 대화 컨텍스트는 유지한다.

### 3.3 생활 환경

- 생활 환경은 자유형 Markdown 한 파일로 관리한다.
- 사용자 파일 경로는 `prompts/life_world.md`다.
- 설정의 프롬프트 탭에 `생활 환경` 다중 행 편집기를 추가한다.
- 파일 경로, 문자 수, 예상 토큰 수를 표시하고 기존 저장·다시 불러오기 흐름에 연결한다.
- 개인정보 없는 작은 가상 마을 예시를 번들 기본값으로 제공한다.
- 사용자가 생활 환경을 비워 두면 장소를 임의로 발명하지 않고 생성을 건너뛰며 설정 안내를 표시한다.
- 생활 환경을 수정해도 이미 저장된 기록은 자동 변경하지 않는다. 다음 자동 생성 또는 최신 기록 수동 재생성부터 현재 환경을 사용한다.

### 3.4 기록 길이

- 전체 비활성 구간은 빠짐없이 기록한다.
- 기록 항목은 최대 24개다.
- 하루 이하는 30분에서 수시간 단위의 비교적 상세한 활동을 만든다.
- 1일 초과 7일 이하는 수시간에서 하루 단위로 묶는다.
- 7일 초과 구간은 반복 생활을 여러 날 단위로 요약한다.
- 항목 수 제한은 구간을 자르는 제한이 아니라 시간 단위를 넓히는 제한이다.

## 4. 제외 범위

- 2D 마을 창, 월드 렌더링, 캐릭터 이동, 맵 편집기
- 실행 중 장시간 무대화를 생활 기록으로 변환하는 기능
- 사용자 캘린더와 개인 일정
- 전체 대화 기록, 첫 채팅 문장, 장기 기억, 첨부파일, 화면 캡처
- 과거 생활 기록 전체를 생성 프롬프트에 누적하는 기능
- 과거 기록 수정·삭제·개별 재생성
- 생활 기록이 생성될 때 자동으로 별도 채팅 답변을 보내는 기능

## 5. 접근 방식

생활 기록은 일반 답변과 분리된 전용 LLM 호출로 생성한다.

첫 일반 대화에서 다음 두 호출을 순차 실행한다.

1. 생활 기록 생성 호출
2. 최신 생활 기록을 임시 맥락에 포함한 일반 답변 호출

일반 응답의 공급자 중립 스키마에 생활 기록 필드를 추가하지 않는다. 기록 생성 실패와 일반 답변 실패를 분리하고, 기록만 독립 검증·재시도할 수 있게 하기 위해서다.

## 6. 구성 요소

### 6.1 `LifeRecordManager`

- 기능 활성화, 이전 종료 정보, 최소 비활성 시간을 기준으로 생성 자격을 판단한다.
- `life_records.json`을 읽고 원자적으로 저장한다.
- 최신 기록, 대상보다 앞선 직전 기록, 날짜와 겹치는 기록을 조회한다.
- 기록 스키마와 시간 연속성을 검증한다.
- 같은 시간 구간의 중복 저장을 막는다.
- 최신 기록 재생성 시 기존 기록을 성공 전까지 보존하고 성공 후 같은 ID로 교체한다.

### 6.2 `LifeRecordPromptBuilder`

- 현재 `base_system_prompt.md`는 에네의 기본 성격과 관계 지침을 유지하기 위한 system instruction으로 포함한다.
- 일반 채팅용 `sub_prompt`, 응답 계약, 분석 부록과 메모리 컨텍스트는 재사용하지 않는다.
- 생활 기록 전용 작업·출력 계약을 기본 시스템 프롬프트 뒤에 배치하고, 충돌하는 말투·출력 형식 지시보다 우선하도록 명시한다.
- 생활 기록 생성에 필요한 정보만 별도 프롬프트로 조립한다.
- 출력 JSON 계약과 시간 연속성 규칙을 제공한다.
- 현재 생활 환경이 직전 기록과 충돌하면 현재 생활 환경을 우선하도록 지시한다.
- 직전 기록을 복사하지 않고 반복 행동을 피하도록 지시한다.

### 6.3 `LifeRecordWorker`

- 대화 히스토리가 없는 생활 기록 전용 one-shot 호출을 수행한다.
- 공급자가 네이티브 구조화 출력을 지원하면 JSON 스키마를 사용하고, 지원하지 않으면 엄격한 JSON 텍스트 출력으로 폴백한다.
- 생성 결과를 파싱하고 `LifeRecordManager`의 검증을 거친다.
- 첫 검증 실패 시 오류 코드만 추가해 한 번 다시 생성한다.
- 생성 호출은 기존 LLM 대화 히스토리를 변경하지 않는다.

모델은 호스트가 이미 알고 있는 메타데이터를 반환하지 않는다. 모델 출력은 `entries`와 `ending_state`만 포함하고, ID·전체 구간·시간대·기분·생성 시각·revision은 검증 후 호스트가 조립한다.

### 6.4 `AppSessionTracker`

- `life_session_state.json`은 `version`, `session_id`, `status`, `started_at`, `last_seen_at`, `stopped_at`을 가진다.
- 앱 시작 시 파일을 읽고 복귀 공백 후보를 메모리에 먼저 보관한다.
  - 이전 `status`가 `stopped`이고 `stopped_at`이 유효하면 그 시각을 `graceful_exit` 후보로 사용한다.
  - 이전 `status`가 `running`이고 `last_seen_at`이 유효하면 그 시각을 `heartbeat_recovery` 후보로 사용한다.
  - 이전 파일이 없거나 유효 후보가 없으면 복귀 공백 후보를 만들지 않는다.
- 이전 후보를 보관한 직후 새 `session_id`를 만들고 현재 시각으로 `status=running`, `started_at`, `last_seen_at`을 기록하며 `stopped_at`은 비운다. 이 전이로 이전 정상 종료 플래그가 현재 세션 크래시까지 남지 않게 한다.
- 실행 중 1분 간격으로 현재 `session_id`의 `last_seen_at`만 갱신한다.
- 정상 종료 시 하트비트를 멈추고 현재 시각으로 `status=stopped`, `last_seen_at`, `stopped_at`을 한 번에 저장한다.
- 비정상 종료에서는 실제 종료 시각을 알 수 없으므로 복구 시작 시각이 최대 하트비트 간격과 스케줄링 지연만큼 실제 종료보다 이를 수 있음을 허용한다.
- 현재 실행 세션의 첫 일반 대화 처리 여부를 메모리에서 추적한다.

### 6.5 `LifeRecordBridgeMixin`

- 일반 텍스트와 첨부 채팅의 공통 진입점에서 첫 대화 파이프라인을 조정한다.
- 생활 기록 생성 중 사용자 입력과 중복 실행을 막는다.
- 생성 결과를 저장한 후 보류한 일반 답변 작업을 시작한다.
- 날짜별 기록과 최신 기록 상태를 웹 UI에 전달한다.
- 수동 재생성을 실행하고 성공 시 패널과 런타임 컨텍스트를 갱신한다.

## 7. 생성 컨텍스트

생활 기록 생성 호출에는 다음 정보만 포함한다.

1. 현재 `base_system_prompt.md` 전체
   - 일반 대화와 같은 LLM 공급자에 system instruction으로 전달한다.
   - 일반 채팅용 `sub_prompt`, 응답 계약, 분석 부록, 메모리 컨텍스트는 결합하지 않는다.
   - 생활 기록 전용 작업·JSON 계약을 뒤에 덧붙여 충돌 시 생활 기록 계약을 우선한다.
2. 에네 프로필 화이트리스트
   - `core_profile.identity`, `core_profile.relationship_tone`을 저장 순서대로 포함한다.
   - 누적 facts는 `basic`, `preference`, `goal`, `habit`, `relationship_tone` 카테고리만 포함한다.
   - facts는 잠긴 수동 항목, 다른 수동 항목, 자동 항목 순으로 우선하고 각 그룹 안에서는 최신 시각부터 정렬한다.
   - facts 수는 기존 `max_profile_facts_in_context` 설정을 따르며 기본 10개로 제한한다.
   - `core_profile.speaking_style`과 `speaking_style` facts는 행동 선택에 필요하지 않으므로 제외한다.
   - 사용자 프로필 전체는 포함하지 않고 설정에서 해석한 에네·사용자 호출명만 사용한다.
3. 현재 `life_world.md` 전체
4. 정확한 비활성 시작·종료 시각
   - ISO 8601 오프셋 포함 시각
   - 현지 날짜, 요일, IANA 시간대
5. 대상보다 앞선 직전 성공 기록 한 개
   - 자동 생성에서는 현재 최신 기록
   - 수동 재생성에서는 교체 대상 기록 자체를 제외한 바로 앞 기록
6. 에네의 기분 스냅샷
   - 라벨, 긍정, 활력, 친밀, 긴장, 단기 분위기의 제한된 상태
   - 첫 일반 메시지가 기분 상태를 변경하기 전에, 요청 수신 직후 복원된 현재 기분을 캡처한다.
7. 복귀 사실
   - 사용자는 종료 시각부터 끝 시각 직전까지 돌아오지 않았다.
   - 사용자의 복귀를 확인하는 행동은 끝 시각 이전에 발생할 수 없다.
8. 출력 계약과 최대 24개 제한

다음 정보는 생성 컨텍스트에서 명시적으로 제외한다.

- 첫 일반 대화의 실제 문장
- 사용자 캘린더와 개인 일정
- 사용자 프로필 상세
- 전체 대화 기록과 장기 기억
- 첨부파일과 화면 캡처
- 직전 한 개보다 오래된 생활 기록
- 일반 채팅용 `sub_prompt`, 응답 계약과 분석 부록

첫 채팅 내용을 제외해 복귀 뒤의 말이 과거 행동에 영향을 주는 역인과를 막는다.
단, 사용자가 `base_system_prompt.md`에 직접 작성한 내용은 그대로 포함하며 화이트리스트 필터링 대상으로 해석하지 않는다. 이는 새 정보 전송이 아니라 일반 대화와 동일한 기본 프롬프트를 생활 기록 생성에도 적용하기로 한 명시적 제품 결정이다.

## 8. 자동 생성 흐름

1. 앱 시작 시 `AppSessionTracker`가 이전 종료 또는 마지막 생존 시각을 복구한다.
2. 일반 대화가 들어오면 수신 시각을 비활성 구간의 끝으로 고정하고, 메시지 내용이나 첨부에 따른 기분 변경보다 먼저 현재 기분 스냅샷을 캡처한다.
3. 도구 명령이면 생활 기록 상태를 소비하지 않고 기존 명령 흐름으로 보낸다.
4. 해당 앱 세션에서 이미 자동 생성을 판단했으면 기존 일반 대화 흐름으로 보낸다.
5. 기능 비활성화, 이전 시각 부재, 빈 생활 환경, 임계값 미만, 0 이하 구간이면 자동 생성을 시도하지 않은 것으로 기록하고 일반 대화를 진행한다. 기능이 켜져 있고 기존 최신 기록이 있으면 기존 기록 컨텍스트를 유지한다.
6. 생성 조건을 만족하면 사용자 입력을 잠그고 `복귀 기록 정리 중…`을 표시한다.
7. 첫 사용자 메시지와 일반 답변 요청 정보를 보류하고 생활 기록 전용 호출을 실행한다.
8. 검증 실패 시 한 번 재생성한다.
9. 성공하면 기록을 원자적으로 저장하고 패널 데이터를 갱신한다.
10. 성공한 최신 기록을 임시 런타임 맥락으로 포함해 보류한 일반 답변을 생성한다.
11. 실패하면 새 기록을 저장하지 않는다. 기능이 켜져 있고 기존 최신 기록이 있으면 기존 기록을 사용하고, 기존 기록도 없으면 생활 기록 없이 보류한 일반 답변을 생성한다.
12. 일반 답변 단계에서는 기존 `생각 중…` 표시를 사용한다.

같은 앱 세션에서는 자동 생성 자격 판단과 시도를 합쳐 한 번만 수행한다. 실패해도 다음 채팅마다 자동 재시도하지 않는다.

## 9. 일반 대화 컨텍스트

- 기능이 켜져 있고 성공한 저장 기록이 하나 이상 있을 때 최신 생활 기록 한 개만 일반 대화에 포함한다.
- 기능을 끄면 저장 기록을 삭제하지 않지만 일반 대화 컨텍스트에는 포함하지 않는다.
- 기능이 켜진 상태에서 현재 세션이 임계값 미만, 이전 시각 부재, 빈 생활 환경 또는 새 생성 실패인 경우에도 기존 최신 성공 기록은 계속 포함한다.
- 저장된 성공 기록이 없으면 생활 기록 블록을 만들지 않는다.
- 생활 기록은 모든 일반 텍스트·첨부 대화에서 사용할 수 있는 별도 임시 컨텍스트 블록으로 조립한다.
- 생활 기록 블록은 LLM에 전달되지만 SDK 또는 HTTP 대화 히스토리와 화면의 `conversation_buffer`에는 저장하지 않는다.
- 과거 기록은 날짜별 열람에만 사용하고 일반 대화 컨텍스트에는 포함하지 않는다.
- 첫 일반 대화에서 생활 기록 생성과 일반 답변에 사용된 토큰은 한 턴 사용량으로 합산한다.

## 10. 리롤과 메시지 수정

- 첫 답변을 리롤해도 생활 기록은 자동 재생성하지 않는다.
- 리롤은 일반 답변만 롤백한다. 기능이 켜져 있고 최신 생활 기록이 있으면 그 기록을 다시 임시 컨텍스트로 사용하고, 기능이 꺼져 있거나 저장 기록이 없으면 생활 기록 블록을 사용하지 않는다.
- 첫 사용자 메시지를 수정해 다시 보내도 생활 기록은 자동 재생성하지 않는다.
- 생활 패널에서 최신 기록을 수동 재생성한 뒤 리롤하면 교체된 최신 기록을 사용한다.
- 자동 생성에 실패했던 세션에서도 리롤은 자동 재시도를 유발하지 않는다.

## 11. 저장 구조

사용자 데이터 루트에 다음 런타임 파일을 둔다.

- `prompts/life_world.md`: 사용자가 편집하는 생활 환경
- `life_records.json`: 전체 생활 기록
- `life_session_state.json`: 정상 종료·마지막 생존 시각
- `config.json`: 기능 활성화와 최소 비활성 시간

새 런타임 JSON 파일은 `.gitignore`와 커밋 전 개인정보 검사 대상에 포함한다.

`life_records.json`의 최상위 형식은 다음과 같다.

```json
{
  "version": 1,
  "records": []
}
```

### 11.1 모델 출력 계약

모델은 다음 객체만 반환한다. 네이티브 JSON 스키마와 텍스트 JSON 폴백이 같은 계약을 사용한다.

```json
{
  "entries": [
    {
      "started_at": "2099-08-06T23:00:00+09:00",
      "ended_at": "2099-08-07T07:00:00+09:00",
      "place": "집",
      "activity": "에네는 자기 방에서 잠을 잤다."
    }
  ],
  "ending_state": {
    "place": "집",
    "summary": "복귀를 확인하고 집으로 돌아왔다."
  }
}
```

- 최상위 필수 필드는 `entries`, `ending_state` 두 개이고 추가 필드는 허용하지 않는다.
- `entries`는 1개 이상 24개 이하의 배열이다.
- 각 항목은 `started_at`, `ended_at`, `place`, `activity` 문자열만 가지며 모두 필수다.
- `ending_state`는 필수 문자열 `place`, `summary`만 가지며 추가 필드는 허용하지 않는다.
- `place`, `activity`, `ending_state.place`, `ending_state.summary`는 공백 제거 후 비어 있으면 안 된다.
- 모든 시각 문자열은 요청에 제공한 오프셋을 포함한 ISO 8601 형식이어야 한다.
- 호스트는 출력 객체를 검증한 뒤 기록 메타데이터를 조립한다.

### 11.2 호스트 저장 계약

기록 형식은 다음과 같다. 아래 값은 실제 사용자 정보가 아닌 합성 예시다.

```json
{
  "id": "interval-derived-id",
  "inactive_started_at": "2099-08-06T23:00:00+09:00",
  "returned_at": "2099-08-07T10:00:00+09:00",
  "created_at": "2099-08-07T10:00:00+09:00",
  "updated_at": "2099-08-07T10:00:00+09:00",
  "revision": 1,
  "timezone": "Asia/Seoul",
  "inactive_start_source": "graceful_exit",
  "mood_snapshot": {
    "label": "평온",
    "valence": 0.1,
    "energy": 0.0,
    "bond": 0.2,
    "stress": 0.0,
    "short_term_mood": "차분함"
  },
  "entries": [
    {
      "started_at": "2099-08-06T23:00:00+09:00",
      "ended_at": "2099-08-07T07:00:00+09:00",
      "place": "집",
      "activity": "에네는 자기 방에서 잠을 잤다."
    }
  ],
  "ending_state": {
    "place": "집",
    "summary": "복귀를 확인하고 집으로 돌아왔다."
  }
}
```

- `id`는 시작·종료 시각을 UTC, 초 단위, `Z` 표기로 정규화한 두 문자열을 `|`로 연결하고 SHA-256을 계산해 안정적으로 만든다.
- `inactive_start_source`는 `graceful_exit` 또는 `heartbeat_recovery`만 허용한다.
- 수동 재생성은 `id`, `inactive_started_at`, `returned_at`, `created_at`, `timezone`, `inactive_start_source`, `mood_snapshot`을 유지한다.
- 수동 재생성 성공 시 `updated_at`과 `revision`을 갱신하고 생성된 활동과 마지막 상태를 교체한다.

## 12. 기록 검증

저장 전 다음 조건을 모두 검사한다.

- 기록 시작이 확정된 복귀 공백 시작점과 정확히 같다.
- 기록 종료가 고정한 첫 대화 시각과 정확히 같다.
- 항목 수가 1개 이상 24개 이하다.
- 각 항목의 시작이 종료보다 빠르다.
- 첫 항목 시작이 전체 시작과 같다.
- 마지막 항목 종료가 전체 종료와 같다.
- 이전 항목 종료와 다음 항목 시작이 정확히 같다.
- 모든 항목이 전체 구간 안에 있다.
- 각 항목의 장소·활동 설명과 `ending_state`의 장소·요약이 비어 있지 않다.
- `ending_state.place`가 마지막 항목 장소와 같다.
- 동일한 구간 ID가 자동 생성으로 중복 추가되지 않는다.

검증은 절대 시각으로 수행하고 표시는 현지 시간대로 변환한다. 시스템 시계 이동으로 종료가 시작과 같거나 빠르면 생성을 건너뛴다.

## 13. 날짜별 조회

- 패널 기본 날짜는 오늘이다.
- 선택한 현지 날짜의 `[00:00, 다음 날 00:00)` 구간과 겹치는 모든 기록을 찾는다.
- 자정을 넘긴 기록은 양쪽 날짜에서 모두 조회된다.
- 어느 날짜에서 열어도 잘린 일부가 아니라 기록 전체를 표시한다.
- 같은 날짜에 여러 기록이 있으면 최신 기록부터 표시한다.
- 정렬은 `returned_at` 내림차순, 값이 같으면 `created_at` 내림차순, 다시 같으면 `id` 오름차순으로 고정한다.
- 기록은 V1에서 자동 삭제하지 않는다.

## 14. UI

### 14.1 생활 기록 패널

우측 상단 `···` 빠른 메뉴에 `생활` 버튼을 추가한다. 기존 예정·목표 패널과 같은 시각 언어를 사용한다.

패널 구성:

- 제목 `에네의 생활 기록`
- 이전 날짜 버튼
- 날짜 선택 입력
- 다음 날짜 버튼
- 오늘 버튼
- 선택 날짜와 겹치는 기록 카드 목록
- 기록이 없을 때 빈 상태 안내

기록 카드 구성:

- 전체 비활성 시작·종료 구간
- 각 항목의 현지 시작·종료 시각
- 장소
- 활동 설명
- 자정을 넘긴 항목의 날짜 표시
- 최신 기록 카드에만 `재생성` 버튼

삭제와 직접 편집은 V1에서 제공하지 않는다.

### 14.2 설정 UI

동작 설정에 다음 항목을 추가한다.

- `생활 기록 사용` 토글, 기본 비활성화
- `최소 비활성 시간` 분 입력, 기본 60분

프롬프트 설정에 다음 카드를 추가한다.

- `생활 환경` Markdown 편집기
- 실제 사용자 파일 경로
- 문자 수와 예상 토큰 수
- 기존 저장·다시 불러오기 동작

한국어, 영어, 일본어 문자열을 기존 로케일 체계에 추가한다.

## 15. 최신 기록 수동 재생성

1. 최신 기록 카드의 `재생성`을 누른다.
2. API 호출과 기록 교체를 알리는 확인 UI를 표시한다.
3. 일반 답변 생성 또는 다른 재생성이 진행 중이면 실행하지 않는다.
4. 확인하면 채팅 입력과 재생성 버튼을 잠그고 `생활 기록 다시 만드는 중…`을 표시한다.
5. 같은 시작·종료 시각과 최초 생성 당시 `mood_snapshot`을 사용한다.
6. 현재 생활 환경, 현재 에네 프로필, 현재 `base_system_prompt.md`와 생활 기록 전용 우선 계약을 사용한다.
7. 교체 대상 자체가 아니라 그보다 앞선 기록 한 개만 연속성 자료로 사용한다.
8. 첫 채팅, 캘린더, 장기 기억, 일반 채팅용 `sub_prompt`·응답 계약·분석 부록·메모리 컨텍스트는 포함하지 않는다.
9. 검증 실패 시 한 번 재생성한다.
10. 최종 실패하면 기존 기록과 현재 런타임 컨텍스트를 유지한다.
11. 성공하면 같은 ID로 원자 교체하고 `revision`과 `updated_at`을 갱신한다.
12. 패널과 최신 일반 대화 컨텍스트를 즉시 갱신한다.
13. 별도 채팅 답변은 만들지 않는다.

## 16. 오류 처리와 복구

- 첫 생성 검증 실패: 검증 오류 코드만 포함해 한 번 재생성한다.
- 두 번째 생성도 실패: 해당 앱 세션의 자동 생성을 종료하고 일반 답변을 진행한다.
- LLM 호출 실패: 새 기록 없이 일반 답변을 진행한다. 기능이 켜져 있고 기존 최신 성공 기록이 있으면 기존 기록 컨텍스트를 유지한다.
- 저장 실패: 검증됐지만 저장되지 않은 새 결과는 주입하지 않는다. 기능이 켜져 있고 기존 최신 성공 기록이 있으면 기존 기록을 사용하고, 없으면 생활 기록 없이 일반 답변을 진행한다.
- 수동 재생성 실패: 기존 파일과 기존 최신 컨텍스트를 유지한다.
- 손상된 `life_records.json`: 덮어쓰지 않고 읽기 오류 상태로 보존한다.
- 원자 저장 중 앱 종료: 기존 완성 파일 또는 새 완성 파일 중 하나만 남게 한다.
- 생성 도중 앱 종료: 검증·저장 완료되지 않은 결과는 유효 기록으로 취급하지 않는다.
- 같은 구간 중복: 안정적인 ID로 중복 추가를 거부한다.
- 빈 생활 환경: 생성하지 않고 설정 안내를 표시한다.
- 같은 앱 세션 자동 생성 실패: 다음 대화와 리롤에서 자동 재시도하지 않는다.
- 자동 생성 실패·임계값 미만·빈 환경이어도 기능이 켜져 있고 기존 최신 성공 기록이 있으면 기존 일반 대화 컨텍스트를 유지한다.
- 기능이 꺼져 있으면 저장 기록과 관계없이 생활 기록 컨텍스트를 주입하지 않는다.

사용자에게 보이는 실패 안내는 짧은 토스트 또는 패널 상태로 제공하고 일반 대화 실패처럼 표시하지 않는다.

## 17. 개인정보와 로그 정책

- 생활 환경, 에네 프로필 원문, 기분 설명, 생활 기록 활동 문장, 첫 채팅 내용을 진단 로그에 출력하지 않는다.
- 로그에는 요청 종류, 입력 문자 수, 결과 항목 수, 검증 오류 코드, 성공·실패 상태, 토큰 수만 남긴다.
- 테스트 fixture와 문서는 합성 인물·합성 날짜·중립 문장만 사용한다.
- `life_records.json`과 `life_session_state.json`은 런타임 파일로 간주하고 절대 커밋하지 않는다.
- 공개 커밋 전 파일명, 사용자 대화 문장, 프로필·건강·일정·취업 관련 표현, API 키 패턴을 검사한다.

## 18. 테스트 계획

### 18.1 단위 테스트

- 59분은 생략하고 60분은 생성한다.
- 기능 비활성화와 첫 설치는 생성하지 않는다.
- 정상 종료 시각과 비정상 종료 마지막 생존 시각을 복구한다.
- 앱 시작 직후 현재 세션을 `running`으로 전이해 이전 `stopped` 상태가 남지 않는지 확인한다.
- 비정상 종료 복구 시 `inactive_start_source=heartbeat_recovery`를 사용하고 하트비트 근사를 허용한다.
- 손상된 `life_session_state.json`은 이전 후보 없음으로 처리하고 현재 세션의 유효한 `running` 상태로 다시 시작한다.
- 0 이하 시간 구간은 생성하지 않는다.
- 생성 프롬프트에 첫 채팅, 캘린더, 사용자 프로필 상세, 장기 기억이 들어가지 않는다.
- 실제 공급자 payload의 system instruction에 현재 `base_system_prompt.md`가 포함되고, `sub_prompt`·일반 응답 계약·분석 부록·메모리 컨텍스트는 포함되지 않는다.
- 기본 시스템 프롬프트가 JSON과 충돌하는 말투·출력 지시를 포함해도 뒤에 붙는 생활 기록 전용 계약이 우선한다.
- 수동 재생성도 실행 시점의 현재 `base_system_prompt.md`와 같은 우선 계약을 사용하고 일반 채팅용 프롬프트·메모리를 제외한다.
- 생성 프롬프트에 허용된 에네 프로필 필드·fact 카테고리, 호출명, 생활 환경, 시각, 기분, 직전 기록 한 개만 들어간다.
- 에네 프로필 facts의 우선순위·최신순·개수 제한을 확인한다.
- 첫 일반 메시지로 기분이 변경되기 전 스냅샷을 생성에 사용한다.
- 직전 기록이 없을 때 해당 블록을 생략한다.
- 공백, 겹침, 범위 이탈, 역순, 빈 장소·활동, 25개 항목, 잘못된 마지막 장소를 거부한다.
- 안정적인 구간 ID가 중복을 막는다.
- 서로 다른 오프셋 표기가 같은 절대 시작·종료 시각을 나타내면 같은 구간 ID를 만든다.
- UTF-8(BOM 없음)으로 설정과 Markdown을 저장한다.
- 손상된 기존 저장 파일을 덮어쓰지 않는다.
- 자정을 넘긴 기록을 양쪽 날짜에서 조회한다.
- 같은 날짜의 여러 기록을 최신순으로 정렬한다.
- 최신 기록 한 개만 일반 대화 컨텍스트로 만든다.

### 18.2 통합 테스트

- 앱 실행 세션의 첫 일반 텍스트 채팅에서만 자동 생성한다.
- 첨부 채팅도 동일한 첫 대화 흐름을 사용한다.
- 도구 명령은 첫 일반 대화 상태를 소비하지 않는다.
- 생성 성공 후 저장하고 최신 기록을 포함해 일반 답변을 시작한다.
- 생성 실패 후 일반 답변을 정상 시작한다.
- 생성 호출은 기존 LLM 대화 히스토리를 변경하지 않는다.
- 네이티브 구조화 출력과 텍스트 JSON 폴백이 동일한 `entries`·`ending_state` 계약을 사용한다.
- 기능 비활성화 시 기존 최신 기록을 주입하지 않는다.
- 기능 활성화 상태의 임계값 미만·빈 환경·생성 실패에서는 기존 최신 기록을 유지한다.
- 기능 활성화 여부, 기존 기록 유무, 임계값 충족 여부, 생성 성공·실패, 저장 성공·실패, 리롤 여부의 컨텍스트 결과를 상태표 기반으로 검증한다.
- 최신 기록 임시 블록은 대화 히스토리와 `conversation_buffer`에 축적되지 않는다.
- 첫 채팅 토큰 사용량은 생성과 일반 답변을 합산한다.
- 리롤과 첫 메시지 수정은 생활 기록을 자동 재생성하지 않는다.
- 수동 재생성 후 다음 대화와 리롤은 교체된 기록을 사용한다.
- 수동 재생성 실패 시 기존 기록과 컨텍스트를 유지한다.
- 재생성 중 중복 클릭과 채팅 동시 실행을 막는다.

### 18.3 UI 테스트

- `···` 메뉴에 생활 버튼이 존재한다.
- 패널이 오늘 날짜로 열리고 이전·다음·오늘 이동이 동작한다.
- 자정을 넘긴 기록에 날짜를 표시한다.
- 선택 날짜와 겹치는 전체 기록을 렌더링한다.
- 최신 기록에만 재생성 버튼을 표시한다.
- 빈 상태와 실패 상태를 표시한다.
- 동작 설정과 생활 환경 편집기가 저장·재로드된다.
- 한국어·영어·일본어 문자열이 모두 연결된다.

### 18.4 수동 검증

- 합성 종료 시각을 전날 23시, 첫 채팅 시각을 다음 날 10시로 두고 전체 11시간이 빈틈없이 표시되는지 확인한다.
- 첫 답변 전 `복귀 기록 정리 중…`, 일반 답변 중 `생각 중…` 전환을 확인한다.
- 오늘 패널과 전날 패널에서 같은 자정 교차 기록 전체를 확인한다.
- 최신 기록 재생성 성공·실패·취소를 확인한다.
- 기능 비활성 상태에서 기존 채팅 지연과 동작이 달라지지 않는지 확인한다.

## 20. 결정 기록

- 생성 구간: 확정된 복귀 공백 시작점(정상 종료 시각 또는 비정상 종료 마지막 생존 시각)부터 다음 실행 후 첫 일반 대화까지
- 최소 시간: 기본 60분, 설정 가능
- 기능 기본값: 비활성화
- 생성 방식: 별도 생활 기록 호출 후 일반 답변 호출
- 생활 환경: 자유형 Markdown
- 생성 과거 맥락: 직전 기록 한 개만
- 일반 대화 맥락: 최신 성공 기록 한 개만
- 캘린더·개인 일정: 제외
- 장기 구간: 전체를 보존하되 최대 24개 항목으로 상세도 조절
- 기록 탐색: 오늘 기본, 과거 날짜 탐색 포함
- 날짜 조회: 선택 날짜와 겹치는 기록 전체 표시
- 자동 생성: 앱 실행 세션당 첫 일반 대화에서 한 번만 판단
- 리롤·메시지 수정: 기록 자동 재생성 안 함
- 수동 재생성: 최신 기록만, 성공 전 원본 보존
- 재생성 입력: 같은 구간과 당시 기분, 현재 생활 환경과 에네 프로필
- 기본 시스템 프롬프트: 자동 생성과 수동 재생성 모두 실행 시점의 현재 `base_system_prompt.md`를 포함하되 `sub_prompt`·일반 응답 계약·분석 부록·메모리 컨텍스트는 제외하고 생활 기록 전용 계약을 우선
