# 에네 2D 마을 월드 V1 설계

## 목표

에네가 채팅창과 Live2D 오버레이에만 머무는 존재가 아니라, 자기 공간 안에서 스스로 움직이고 머무는 존재처럼 느껴지게 한다.

V1의 핵심은 완성형 RPG가 아니다. 사용자가 `Sunnyside_World` 기반의 작은 마을을 만들고, 에네가 그 마을 안에서 픽셀 아바타로 자연스럽게 생활하는 모습을 검증한다. 평소 행동은 안정적인 알고리즘이 맡고, 사용자가 `/world` 명령을 내릴 때만 에네가 월드 상태를 보고 직접 행동을 계획한다.

## 확정 범위

- 별도 월드 창을 추가한다.
- 기존 Live2D 오버레이와 채팅 UI는 유지한다.
- 월드 창은 ENE 본체를 대체하지 않고, 에네의 활동 공간으로 동작한다.
- `assets/sprites/Sunnyside_World_ASSET_PACK_V2.1` 자산을 사용한다.
- V1 기본 타일셋은 `Sunnyside_World_Assets/Tileset/spr_tileset_sunnysideworld_16px.png`이다.
- 마을 편집기는 선별 팔레트를 사용한다.
- 기본 프리셋을 제공한다.
- 사용자는 타일과 오브젝트를 직접 배치할 수 있다.
- 에네는 마을용 픽셀 아바타로 표시한다.
- 기존 Live2D 에네는 데스크톱 오버레이와 대화 정체성으로 유지한다.
- 평소 이동은 LLM 없이 알고리즘으로 처리한다.
- 특별한 월드 행동은 `/world` 슬래시 명령으로 처리한다.

## 제외 범위

- 전체 타일셋 브라우저
- 자동 타일 연결
- 실내맵
- 계절 전환
- 전투, 퀘스트, 인벤토리, 성장 시스템
- 여러 NPC와 상점 시스템
- 사용자가 에네를 직접 조작하는 플레이어 컨트롤
- 처음부터 완성형 에네 전용 픽셀 아트 제작
- LLM을 계속 호출하는 상시 자율 행동

## 사용자 경험

사용자는 트레이 메뉴나 ENE UI에서 `마을 편집기`를 연다. 편집기는 기존 오버레이와 분리된 일반 창이다. 처음 열면 `생활형 마을 허브`, `농장 앞마당`, `숲 입구` 같은 기본 프리셋 중 하나를 선택할 수 있다.

편집 화면은 왼쪽 선별 팔레트, 중앙 맵 캔버스, 오른쪽 프리셋/속성 패널로 구성한다. 사용자는 바닥, 길, 물, 집/울타리/다리, 나무/작물/장식, 활동 지점을 배치한다. 저장하면 월드 JSON에 기록되고, 월드 창에서 같은 데이터를 사용한다.

월드 창에서는 에네가 마을 안에 픽셀 아바타로 나타난다. 에네는 평소에는 알고리즘에 따라 활동 지점 사이를 이동한다. 예를 들어 광장에 머물다가 연못으로 걸어가고, 집 앞에서 기다리거나 밭 근처에서 작업하는 식이다.

사용자가 `/world 연못 쪽에서 쉬어줘`처럼 명령하면 그때만 에네가 현재 월드 상태와 가능한 행동 목록을 보고 직접 계획을 고른다. 실행 전에는 검증을 거쳐 허용된 목적지와 행동만 수행한다.

## 기술 접근

V1은 기존 ENE의 PyQt + QWebEngine 구조를 따른다. 별도 `WorldWindow`를 추가하고, 그 안에 월드용 웹 런타임을 로드한다. 현재 프로젝트의 Live2D 오버레이도 QWebEngine 기반이므로, 새 창 역시 같은 앱 수명주기와 설정 관리 흐름을 따른다.

웹 월드 자산은 `assets/world/` 아래에 둔다.

- `index.html`: 월드/에디터 진입점
- `style.css`: 월드 창과 에디터 기본 스타일
- `world.js`: 월드 렌더링과 에네 행동 루틴
- `editor.js`: 마을 편집기 조작
- `palette.js`: 선별 팔레트 정의
- `presets/`: 기본 프리셋 JSON
- `maps/`: 사용자가 저장한 월드 JSON

렌더링은 스프라이트를 CSS 배경으로 대충 자르지 않는다. 각 팔레트 항목은 `이미지 경로 + 원본 x/y/w/h 좌표 + 배치 크기 + 충돌 여부 + 레이어`를 가진다. 렌더러는 이 좌표만 정확히 잘라 캔버스 또는 게임 렌더러에 그린다.

## 선별 팔레트 설계

V1은 전체 1024x1024 타일셋을 그대로 보여주지 않는다. 처음부터 전체 타일셋을 노출하면 사용자는 자유를 얻지만, 실제 제작 흐름은 느려진다. V1은 에네 마을에 필요한 묶음만 선별한다.

팔레트 그룹:

- 바닥: 잔디, 잔디 변형, 흙, 길, 물
- 마을: 벽, 지붕, 울타리, 다리, 기본 구조물
- 장식: 나무, 꽃, 작물, 풍차 같은 분위기 요소
- 활동 지점: 에네가 머물거나 행동할 수 있는 마커

각 항목은 내부적으로 다음 정보를 가진다.

```json
{
  "id": "ground.grass.default",
  "label": "잔디",
  "source": "assets/sprites/Sunnyside_World_ASSET_PACK_V2.1/Sunnyside_World_Assets/Tileset/spr_tileset_sunnysideworld_16px.png",
  "src": {"x": 0, "y": 0, "w": 16, "h": 16},
  "draw": {"w": 16, "h": 16},
  "layer": "ground",
  "blocking": false
}
```

## 월드 데이터 설계

월드는 JSON으로 저장한다. 에디터와 런타임이 같은 파일을 읽는다.

주요 필드:

- `version`: 월드 데이터 버전
- `name`: 월드 이름
- `tileSize`: 기본 타일 크기
- `width`, `height`: 맵 크기
- `layers`: ground, object, marker 레이어
- `paletteRefs`: 사용한 팔레트 항목 목록
- `activityPoints`: 에네 행동 지점
- `spawn`: 에네 시작 위치

활동 지점은 단순 좌표가 아니라 의미를 가진다.

```json
{
  "id": "pond_rest",
  "label": "연못 휴식",
  "x": 12,
  "y": 7,
  "tags": ["quiet", "rest", "water"],
  "allowedActions": ["idle", "waiting"],
  "moodWeights": {
    "calm": 1.4,
    "tired": 1.2,
    "energetic": 0.6
  }
}
```

## 에네 아바타 설계

마을 안의 에네는 `Sunnyside_World_Assets/Characters/Human` 기반 픽셀 아바타로 표시한다.

사용할 기본 애니메이션:

- `IDLE/base_idle_strip9.png`
- `WALKING/base_walk_strip8.png`
- `WAITING/base_waiting_strip9.png`
- `DOING/base_doing_strip8.png`

V1에서는 기본 Human 스프라이트를 사용하되, 구조는 나중에 에네 전용 픽셀 스프라이트로 교체할 수 있게 둔다. 즉 행동 엔진은 특정 이미지 파일에 고정되지 않고, `idle`, `walk`, `waiting`, `doing` 같은 애니메이션 키를 참조한다.

기존 Live2D 에네는 계속 데스크톱 오버레이와 대화 정체성의 중심이다. 마을 픽셀 에네는 월드 안에서의 몸이다. 두 표현은 서로 경쟁하지 않고 역할을 나눈다.

## 평소 이동 알고리즘

평소에는 LLM을 호출하지 않는다. 월드 행동 엔진이 다음 목적지와 행동을 고른다.

입력:

- 현재 위치
- 현재 활동 지점
- 최근 방문 지점
- 각 활동 지점의 태그와 가중치
- 현재 mood 상태
- 최근 사용자 대화 상태
- 시간 기반 쿨다운

기본 흐름:

1. 현재 상태를 읽는다.
2. 갈 수 있는 활동 지점 목록을 만든다.
3. 최근 방문한 지점은 가중치를 낮춘다.
4. mood와 태그가 맞는 지점은 가중치를 높인다.
5. 하나의 목적지를 선택한다.
6. 격자 경로로 이동한다.
7. 도착하면 해당 지점의 허용 행동 중 하나를 실행한다.
8. 일정 시간이 지나면 다음 선택으로 넘어간다.

V1 경로 이동은 단순 격자 기반으로 시작한다. 장애물과 충돌 타일은 피하되, 복잡한 동적 길찾기는 나중에 확장한다.

## `/world` 명령 설계

`/world`는 월드 행동 전용 슬래시 명령이다. 기존 `/note`, `/obs`, `/diary`처럼 일반 채팅보다 먼저 감지한다.

예시:

- `/world 연못 쪽에서 쉬어줘`
- `/world 집 앞에서 나 기다려줘`
- `/world 오늘은 밭 근처에서 뭔가 하고 있어줘`

처리 흐름:

1. Bridge가 `/world` 명령을 감지한다.
2. 현재 월드 상태를 수집한다.
3. 가능한 활동 지점과 허용 행동 목록을 만든다.
4. LLM에 제한된 행동 계획을 요청한다.
5. 계획을 검증한다.
6. 유효하면 월드 런타임에 행동 명령을 보낸다.
7. 유효하지 않으면 안전한 대체 행동을 선택하거나 사용자에게 설명한다.

LLM은 자유 텍스트 행동을 직접 실행하지 않는다. 반드시 허용된 스키마 안에서만 계획을 반환해야 한다.

예상 계획 형식:

```json
{
  "targetActivityPointId": "pond_rest",
  "action": "waiting",
  "reason": "사용자가 쉬어달라고 했고, 연못 휴식 지점이 조용한 행동에 적합함"
}
```

## 구성 요소

### `WorldWindow`

PyQt의 새 일반 창이다. ENE 앱 수명주기 안에서 생성되며, 사용자가 열고 닫을 수 있다. 창을 닫아도 ENE 앱은 종료되지 않는다.

### `WorldBridge`

Python과 월드 웹 런타임 사이의 연결이다.

V1 역할:

- 현재 mood 요약 전달
- 월드 JSON 로드/저장 요청 처리
- `/world` 명령 결과를 월드 런타임에 전달
- 월드 런타임의 현재 상태 요청 처리

### 월드 런타임

마을 표시와 에네 이동을 담당한다.

- 월드 JSON 로드
- 선별 팔레트 기반 렌더링
- 에네 픽셀 아바타 애니메이션
- 평소 이동 알고리즘
- 명령 기반 행동 실행

### 마을 편집기

사용자가 월드를 만드는 별도 편집 UI다.

- 선별 팔레트
- 프리셋 적용
- 타일 배치
- 오브젝트 배치
- 활동 지점 배치
- 저장/불러오기

## 오류 처리

- 월드 HTML이 없으면 창 안에 오류 메시지를 표시한다.
- Sunnyside 자산이 없으면 어떤 파일이 누락됐는지 표시한다.
- 월드 JSON이 깨졌으면 기본 프리셋으로 폴백할 수 있게 한다.
- 팔레트 source rectangle이 이미지 범위를 벗어나면 해당 항목을 비활성화한다.
- `/world` 명령 계획이 유효하지 않으면 실행하지 않는다.
- 존재하지 않는 활동 지점을 요청하면 가장 가까운 대체 지점을 제안한다.
- LLM 호출 실패 시 평소 이동 알고리즘을 계속 유지한다.

## 테스트 및 검증

### 자동 테스트

- `WorldWindow`가 올바른 HTML 경로를 계산하는지 확인한다.
- 월드 창 생성이 기존 ENE 앱 초기화와 충돌하지 않는지 확인한다.
- `WorldBridge`가 월드 JSON을 읽고 저장하는지 확인한다.
- 선별 팔레트 항목의 source rectangle이 이미지 범위 안에 있는지 확인한다.
- 기본 프리셋 JSON이 스키마를 만족하는지 확인한다.
- `/world` 명령 파서가 일반 채팅과 명령을 구분하는지 확인한다.
- `/world` 계획 검증이 허용되지 않은 활동과 지점을 거부하는지 확인한다.

### 수동 검증

- ENE 실행 후 기존 Live2D 오버레이와 채팅이 정상 동작한다.
- 월드 창을 열 수 있다.
- 마을 편집기를 열 수 있다.
- 기본 프리셋을 적용할 수 있다.
- 선별 팔레트로 타일을 배치할 수 있다.
- 활동 지점을 배치할 수 있다.
- 저장 후 다시 열었을 때 같은 마을이 복원된다.
- 월드 창에서 에네 픽셀 아바타가 보인다.
- 에네가 평소 알고리즘에 따라 활동 지점 사이를 이동한다.
- `/world` 명령으로 에네의 월드 행동을 요청할 수 있다.
- `/world` 실패 시 기존 채팅과 평소 이동이 깨지지 않는다.

- 마을 크기: `생활형 마을 허브` 방향

- 평소 이동: 알고리즘 기반
- 특별 행동: `/world` 명령에서만 에네 사고 모드 사용
