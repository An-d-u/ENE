# LLM 요청 실패 후 리롤·수정 복구 검증

## 적용 범위

- 오류 안내를 실패한 요청의 표시 ID에 연결해 기존 리롤로 재시도한다.
- 실패한 요청의 사용자 메시지도 수정 후 다시 요청할 수 있다.
- 오류 안내는 표시용 기록에만 포함하고, LLM 내부 대화·기억·성공 응답 ID에는 포함하지 않는다.
- 실패 요청에는 삭제할 답변이 없으므로 기존 성공 대화를 되돌리지 않고 해당 사용자 입력 이전의 내부 문맥으로 재구성한다.
- 재시도 성공 시 오류 안내를 동일 표시 ID의 답변으로 교체한다. 재실패 시 원래 입력·안내·재시도 대상을 복원한다.
- 이미 정상 답변이 있는 리롤·수정이 실패하면 원래 답변을 보존하고 기존 요청 실패 알림만 표시한다. 새 오류 말풍선을 추가하지 않으며, 다음 성공은 같은 답변 ID를 교체한다.
- 기존 세션·대상 버전·중복 요청·처리 중 검사와 초기화 경계는 유지한다.

전체 검사에서 제외된 항목은 Windows 심볼릭 링크 생성 권한 검사와 격리 작업 폴더에 설치하지 않은 선택적 Core 검사다. Core는 원래 실행 폴더에서 별도로 검증했다. 검사 기준을 완화하거나 새 건너뛰기 조건을 추가하지 않았다.

회귀 검사는 첫 요청 실패, 이전 성공 뒤 실패, 리롤·수정, 연속 실패 뒤 성공, 복구 후 재리롤, TTS 지연 표시, 첨부 보존, 시작 실패, 오래된 요청, 처리 중 재시도, 초기화 및 지연 콜백을 포함한다. 실제 PC 채팅 JavaScript 런타임에 브리지 이벤트를 전달해 리롤이 최신 오류 안내를 가리키는지도 확인했다.

## 정상 답변 재생성 실패의 추가 검증

초기 패치에서도 이미 정상 답변이 있는 재생성의 실패는 일반 메시지 신호로 오류 안내를 추가했다. 원래 답변은 복원되고 다음 성공도 동일 ID를 교체하지만, 별도로 추가된 오류 말풍선은 남는 문제가 재현됐다.

이 경로도 기존 요청 상태 알림으로 처리하도록 보완했다. 테스트 환경은 `runtime_bridge.js`까지 실행하며, 공개 표시 이벤트뿐 아니라 일반 오류 신호와 실제 알림 DOM을 함께 검사한다. 리롤/수정 및 TTS 지연 표시의 네 조합에서 연속 실패 두 번과 연속 성공 두 번을 실행한다.

- 보완 전: 추가 검사 4개가 중복 오류 말풍선을 검출해 실패했다.
- 보완 후: 관련 검사 108개가 통과했다. 단계마다 같은 답변 ID 하나와 리롤 버튼 하나를 유지하며, 실패 알림은 두 번 표시됐다.
- 보완 후 전체 검사 4,155개가 통과했다. 변경 범위의 표시·복원·실패 상태·내부 문맥 경계를 직접 검토했으며, 파일 형식과 개인정보 후보 검사도 통과했다.
- 정상 답변 두 개가 남는 현상 자체는 합성 재현에서 관찰되지 않았다. 대신 성공 이후에도 오류 말풍선이 남는 현상을 확인하고 수정했다.

## 로컬 확인 방법과 제한

수정이 실행 브랜치에 반영된 뒤 ENE를 완전히 재시작한다. 이후 요청 실패가 발생하면 오류 안내의 리롤 또는 마지막 사용자 메시지 수정을 사용한다. 성공하면 같은 위치에 답변이 표시되어야 하며, 다시 실패해도 복구 대상을 유지해야 한다.

- 이번 수정은 ENE의 실패 복구 처리다. 외부 제공자의 `ServerError` 발생 원인을 해결하거나 확정한 것은 아니다.
- 이미 실행 중인 구버전 화면의 오류 안내를 소급 변환하지 않는다.
- 실제 제공자 오류를 유발하는 수동 시험, APK 재빌드·설치, 휴대폰 시험은 수행하지 않았다.
- Core·모델·APK·실제 사용자 대화·설정은 수정하거나 커밋하지 않았다.
- main 병합·원격 push·릴리스 생성은 별도 승인 대상이다.
