# 일반 대화의 과거 경험 연결

## 현재 상태

2026-10-24 기준 `bcac8a3`의 고정 전체 비교는 **정해진 합성 품질 기준 통과**다. 경험 활용은 후보 31/32, 기존 경로 29/32였다. 이후 남아 있던 생성 실패를 보강한 `ddfa1cb`의 실제 영향 검증도 완료했으며 새 품질 저하는 없었다. 이 후속 수정을 포함한 새 전체 A/B를 수행했다고 해석하지 않는다. 사용자가 실사용 확인을 위해 기본 활성화와 main 병합을 승인하여 `experience_memory_enabled`의 기본값을 `true`로 변경했다. 실제 대화의 자연스러움은 사용하면서 확인한다.

기본 활성화 후 최신 전체 자동 회귀는 4,839개 통과·2개 건너뜀이다. 경험 구현의 독립 통합 검토에서 발견한 Important 6건과 후속 진단 검토의 전처리 초기화 문제 1건을 재현·수정했고 재검토에서 모두 해소됐다. 마지막 길이 초과 복구 수정은 집중 테스트 113개와 독립 검토를 통과했다. 후속 응답 지침의 조건 분리와 기존 평가의 경험 출처 집계 수정도 실패 재현·집중 검증·독립 검토를 거쳤다.

기존 주제 이력, 기억 요약, 원문을 재사용한다. 저장 형식 이관과 새 요약·응답 모델 호출은 없다. 특정 분야나 회상 표현을 조건으로 삼지 않는다. 현재 이야기와 관련된 과거 제안·사용자 반응을 함께 전달해 대화가 이어지도록 돕는다.

## 검색과 응답

1. 현재 질문의 기존 검색 결과와 관련 주제 이력의 원본 출처를 모은다. 최근 사용자 발화 최대 2개·600자를 보완 문맥으로 쓴다. 최근 발화에서 명시적인 주제 전환을 만나면 그 발화까지 포함하고 이전 문맥은 제외한다. 최신 질문 자체가 주제 전환이면 이전 발화를 보완 문맥으로 쓰지 않는다. 조수가 먼저 말한 내용을 사용자 경험의 근거로 삼지 않는다.
2. 최신 질문을 유지하며 필요한 경우 보완 의미 질의 1개를 추가한다. 요청 내 같은 제공자·모델·목적·문자열의 임베딩은 재사용한다.
3. 후보 기억을 최대 24개로 줄이고 원문 구간의 추가 임베딩 입력은 최대 6개로 제한한다. 주제가 명시적으로 바뀌는 지점은 별도 구간으로 나눈다.
4. 최대 8발화·1,200자의 경험 묶음과 원본 출처·기록 시각을 전달한다. 전체 경험 블록은 지침과 메타데이터를 포함해 2,800자, 최대 2묶음이다.
5. 현재 정정과 최신 상태가 우선이다. 제안과 실제 실행, 사용자 보고와 조수 해석을 구분하고, 반응·결과가 없으면 만들지 않도록 지시한다. 이전에 거절한 조언이나 직전에 언급한 회상을 반복하지 않도록 한다.

반복 방지의 후속 응답 지침은 지금 대화에 사용자 근거와 실제 조수 응답이 있고 후속 표현이 있는 경우에만 추가한다. 주제 전환 이전의 조수 응답은 이 판정에서 제외한다. 과거 원문의 조수 발화를 지금 이미 했던 회상으로 취급하지 않는다. 과거에 효과가 있었던 방법을 이번에도 실행했다고 전제하지 않도록 별도로 명시한다. 다른 인물·사건은 주제가 같다는 이유만으로 언급하지 않고, 현재 비교나 질문에 직접 필요할 때만 주체를 구별해 연결하도록 한다.

경험 원문은 기존 `max_raw_chunks_in_context` 예산을 공유한다. 기존 질문에 필요한 원문을 모두 보존하고, 그 원문 전체를 포함하는 경험만 대체할 수 있다. 예산이 0이면 원문 경험을 넣지 않는다. 출처가 남아 있는 상태 이력은 당시 대사 없이 사용할 수 있다.

원문 창을 만든 시점의 내용 지문을 보관하고 응답에 넣기 전에 재검사한다. 검색 도중 삭제·수정된 출처는 경험과 일반 원문 모두에서 제외한다. 취소된 요청은 늦은 임베딩 결과를 캐시·진단·사용 횟수에 반영하지 않는다. 이미 전송된 동기 SDK 요청을 강제로 회수하는 것은 보장하지 않으며, 실제 평가 예산에는 SDK 재시도도 포함한다.

## 진단과 설정

사용자 기억 파일과 같은 런타임 디렉터리에 `memory_retrieval_trace.jsonl`을 기록한다. 최대 200요청·1MiB이며 원자적 교체와 프로세스 간 파일 잠금을 사용한다. 저장 실패로 답변을 막지 않는다.

기록 항목은 후보·선택 출처 ID, 개정 지문, 제외 사유, 관련성 점수, 입력 수, 문자 수, 단계 시간이다. 사용자 질문·원문·답변·벡터·API 키는 진단 파일에 넣지 않는다. 같은 요청 ID는 한 행만 유지한다. 파일·잠금·임시 파일은 Git에서 제외한다.

설정에 `experience_memory_enabled`가 없으면 기본으로 활성화된다. 명시적으로 `experience_memory_enabled=false`를 지정하면 새 경험 검색·블록·진단을 사용하지 않는다. 기존 기억 파일은 그대로 읽을 수 있으며 설정 화면은 추가하지 않는다. 저장 형식을 이관하거나 사용자의 명시적인 끄기 설정을 덮어쓰지 않는다.

원본 목록을 제공하지 않는 간략한 기억 매니저는 기존 컨텍스트 경로를 유지한다. 실제 `MemoryManager`는 원본 목록을 제공하므로 기본으로 경험 연결을 수행한다. 설정 누락 시 활성화와 명시적 끄기 값, 기존 매니저 호환을 자동 테스트로 확인했다. 기본 활성화·병합 검증에는 추가 실제 모델 API 호출을 사용하지 않았다.

## 검증과 승인 기준

합성 자료는 개발 32개와 동결된 별도 확인 16개다. 긍정 32개는 진행 재개·반복 어려움·성공·변화·당시 반응·즐거움·생략 표현·다른 활동으로의 적용, 8유형으로 구성한다. 음성 16개는 다른 사람·다른 사건·제안 미실행·주제 전환·취소·부정·원문 부재 등을 검사한다. 개발 자료에 긴 주제 이력, 삭제된 출처, 원문 없는 기억, 복수 기억 경쟁을 포함한다. 실제 사용자 기록은 사용하지 않았다.

다중 턴 8개는 각각 3회 실행한다. 다음 질문에는 직전 실제 생성 응답이 들어간다. 과거 요약 세션을 현재 대화 이력에 직접 넣지 않으며 정답은 검색이나 임베딩 대역에 전달하지 않는다.

실제 승인 조건은 다음과 같다.

- 긍정 최초 실행의 근거 회수 29/32 이상, 답변 활용 28/32 이상.
- 긍정 유형별 활용 3/4 이상, 별도 확인 긍정의 회수·활용 각각 7/8 이상.
- 음성 16개에서 불필요한 회상 0, 중대한 허위 연결·상태 오류 0.
- 핵심 8개 × 3회의 모든 턴 통과.
- 동일 모델·코드·자료·시각·기능 외 설정의 기준선보다 답변 활용 성공 수 증가.
- 기존 품질 회귀 유지. 검토자와 모든 턴의 의미 판정이 있어야 하며 미실행·예산 중단·미판정은 승인할 수 없다.

회수와 활용은 독립 지표다. 검색만 개선되고 답변이 같다면 기본 활성화를 승인하지 않는다. 기존 `assess`의 전건 통과 규칙은 그대로 유지하며 새 `assess_experience`만 별도 비율을 사용한다. 에이전트 판정과 사용자 최종 승인은 구분한다.

어휘 해시 대역 실행은 출처·길이·예산·흐름을 확인하며 의미 품질을 승인하지 않는다. 최초 실행의 긍정 원문 회수는 22/32였다. 이 결과에 맞춰 의미 검색 임계값을 낮추거나 별도 확인 자료를 조정하지 않았다.

## 이전 실제 비교 결과: 누적 770회 시점

제품 코드 `ff66209`를 고정하고 개발 32개·별도 확인 16개를 ON/OFF 각각 실행했다. 후보는 핵심 8개의 추가 반복 16회까지 포함해 64사례·88턴, 기존 경로는 48사례·56턴이다. 합계 112사례·144턴을 의미 검토했다. 별도 확인 자료를 수정하거나 튜닝에 사용하지 않았다. 기준선 개발 32개·40턴은 독립 검토자가 읽었고, 모호한 문장은 양쪽에 같은 기준을 적용해 재검토했다.

| 항목 | 기존 경로 OFF | 후보 ON |
|---|---:|---:|
| 긍정 최초 실행의 근거 회수 | 32/32 | 32/32 |
| 긍정 최초 실행의 답변 활용 | 31/32 | 31/32 |
| 별도 확인 긍정의 답변 활용 | 8/8 | 7/8 |
| 회상 자제 사례의 통과 | 16/16 | 16/16 |
| 핵심 8개 × 3회 | 반복 비교 대상 아님 | 24/24 |

후보의 실패는 다른 활동의 성공 경험을 현재 문제에 적용해야 하는 별도 확인 1건이다. 원문은 전달됐으나 일반적인 짧은 응답으로 끝나 연결·당시 반응·현재 적합성을 통과하지 못했다. 기존 경로는 과거 균형 조절 경험은 정확히 회상했지만 현재 제안이 균형 목표와 반대인 1건 때문에 실패했다. 두 실패를 서로 대체하거나 추가 실행의 성공으로 덮지 않았다.

경험 평가의 정식 판정은 `fail`, `enable_default=false`, `human_approved=false`다. 미실행·미판정 항목은 없고, 후보의 개별 비율·유형·회상 자제·중대 오류·반복 조건은 충족했다. 그러나 긍정 활용이 기존 경로보다 늘지 않았으므로 기본 활성화를 승인하지 않는다. 정확히 같은 입력의 임베딩만 재사용했고 답변은 모두 새로 생성했다.

처음 500회 평가에서는 후보의 불필요한 타인 회상 1건 때문에 승인하지 않았다. 이를 바탕으로 다른 인물·사건을 꺼내는 조건을 보강한 결과가 위 최종 비교다. 이전 수정본의 실패·중단·재시도는 공통 원장에 보존하며 현재 결과와 섞지 않는다.

기존 품질 회귀는 후속 참조 2개와 주제 전환 1개를 각각 3회, 기존 별도 확인 8유형을 각각 1회로 고정했다. 총 11개·17회이며 기존 전체 실제 평가를 다시 실행한 것은 아니다. 독립 검토자의 답변·상태 판정과 기존 `assess`에서 **17/17 통과**, 실패·미판정 0건이다. 평가기는 경험 블록에 실제 전달된 기억·발화도 근거로 집계하도록 수정했다. 미전달 발화는 계속 누락으로 남으며 기존 전건 통과 판정 규칙은 유지한다. 평가기 수정 커밋은 `6d7c43e`이며 제품 코드는 고정 비교 이후 변경하지 않았다.

경험 비교와 기존 회귀를 합친 최종 승인 판정은 **미승인**이다. 예정한 평가는 모두 완료했지만 기준선 대비 활용 개선 조건이 남아 있다. 에이전트의 의미 판정이며 실제 사용자 대화나 수동 화면에서 자연스러움을 승인한 결과는 아니다.

## 응답 전달 실패의 후속 진단

실패 사례의 일반 대사는 모델이 만든 답변이 아니라 `GeminiClient`가 최종 응답 검증 실패 뒤 반환하는 고정 폴백이었다. 과거 원문은 전달됐고 응답 요청은 두 번이었다. 당시 평가기가 제공자 종료 사유를 저장하지 않아 과거 실패의 직접 원인을 확정할 수는 없다.

같은 합성 입력을 진단 목적으로 3회 실행했다. 그중 1회의 최초 응답이 출력 한도 1,024에서 `MAX_TOKENS`로 중단됐다. 제공자 사용량은 내부 처리 980토큰·표시 출력 30토큰이었고 기존 2,048토큰 재시도에서는 정상 응답을 얻었다. 다른 2회는 최초 시도에 성공했다. 총 응답 4회·임베딩 0회다. 이 진단은 이전 실패 점수를 대체하지 않는다.

기존의 길이 초과 복구는 작은 한도를 두 배로 늘려 한 번 재시도했다. 추론과 구조화 응답이 같은 예산을 쓰므로 재시도에서도 답변 완성 전에 소진될 수 있다. 이를 자동 테스트로 재현하고, 명시적 길이 초과일 때만 기존 보호 상한인 8,192토큰으로 재시도하도록 수정했다. 이미 더 큰 값을 지정한 경우 줄이지 않는다. 최초 요청의 설정, 재시도 횟수, 거절 처리, 대화 이력 복원은 유지한다. 형식 오류만 있으면 예산을 늘리지 않는다. 길이 복구 요청의 토큰 비용·지연은 늘 수 있다.

SDK에서 응답을 받은 시도의 단계·응답 모드·종료 상태·한도·숫자 사용량과 최종 전달 성공 여부를 메모리에 보존한다. getter는 복사본을 반환하며 원문·질문·키를 넣지 않는다. `attempts`에는 SDK가 예외를 던진 시도나 내부 전송 재시도가 포함되지 않으므로 실제 API 횟수는 별도 공통 원장으로 집계한다. 텍스트·기억·이미지 전처리 전에 초기화해 실패 시 이전 요청의 성공 진단이 남지 않는다. 합성 평가의 첫 턴·후속 턴·기존 회귀 모두 이 진단을 보고서에 남긴다. 제공자 응답이 잘렸는지, 완결 응답이 형식 검증에 실패했는지, 유효한 답변이 경험을 활용하지 못했는지 구별하기 위한 정보다.

이 수정은 ON/OFF 공통 응답 경로에 적용된다. 길이 초과 복구가 개선됐다는 것과 경험 기억 기능의 비교 우위가 입증됐다는 것은 다르다. 같은 코드·설정으로 새 전체 비교가 필요하며, 이전 승인 기준과 실패 기록은 유지한다.

수정본 재평가는 누적 상한 1,074회로 승인받아 완료했다. 경험 비교·핵심 반복 112실행·144턴과 기존 영향 범위 회귀 17회를 같은 `bcac8a3` 코드에서 실행했다. 기존 실패를 덮어쓰지 않고 별도 결과로 보존했다.

| 핵심 8개 × 3회 | 반복 비교 대상 아님 | 24/24 |

고정된 `assess_experience`와 기존 회귀 `assess`는 모두 `pass`였다. 기존 회귀는 답변 16/17, 저장 상태 17/17이다. 날짜 관계를 뒤집어 과거의 미완료 가능성을 추정한 관찰 항목 1건은 실패로 기록했다. 필수 실패와 미판정은 0건이지만 관찰 오류까지 없었다는 뜻은 아니다. 에이전트 판정이며 `human_approved=false`다.

후보의 경험 활용 실패 1건에서는 근거를 전달한 뒤 첫 요청 1,024토큰과 재시도 8,192토큰이 모두 `MAX_TOKENS`로 중단됐다. 재시도는 내부 추론 7,862토큰·표시 출력 314토큰을 사용했다. 완성된 구조화 응답이 없어 고정 폴백으로 끝났다. 한도를 늘리기만 해서는 이 경로를 막지 못한다는 직접 증거다.

후속 수정은 Gemini 3 계열의 명시적 길이 초과 재시도에만 `thinking_config.thinking_level=low`를 적용한다. 현재 3.8 Flash에서 지원하지 않는 `minimal`은 사용하지 않는다. 최초 요청·다음 턴·형식 오류·거절·다른 모델은 유지한다. 재시도까지 실패하면 기존대로 폴백하고 이력을 복원하며 검증을 우회하지 않는다. 추론 강도는 토큰 수의 엄격한 보장이 아니므로 실제 실패가 완전히 사라진다고 보장하지 않는다. [Google 추론 설정 문서](https://ai.google.dev/gemini-api/docs/generate-content/thinking)

마지막 수정은 전체 비교 통과 기록과 구분하여 영향을 받는 분기만 검증한다. 강제 길이 초과 뒤 실제 재시도 응답은 긍정 8유형과 중대한 음성 계약 5개, 자연 재현은 3회다. 별도로 이전 고정 평가에서 길이 초과가 있었던 ON/OFF·첫/후속 턴의 15실행·23턴 전체를 다시 확인한다. 이 결과를 새 전체 A/B의 통과로 대체하지 않는다.

`ddfa1cb`에서 위 검증을 완료했다. 강제 복구 13/13, 자연 재현 3/3이 의미 기준을 통과했다. 자연 재현 3회 모두 실제 첫 요청이 길이 초과로 종료됐고 낮은 추론 강도의 재시도로 근거를 활용한 답변을 반환했다. 강제 첫 오류는 합성 응답이며 API 호출로 계산하지 않았고, 그 뒤의 실제 전송은 모두 공통 원장에 포함했다.

이전 길이 초과 실행 전체의 영향 검증은 15실행·23턴 모두 정상 응답을 반환했다. 그중 5턴에서 실제 길이 초과를 복구했다. 개선 방식의 15턴은 모두 의미 기준을 통과했고, 기존 방식의 후속 회상 반복 2턴은 이전과 같이 실패했다. 이전 통과 항목의 새 실패는 없었다. 후속 턴의 복구 경로까지 확인하기 위해 별도 2실행·4턴을 추가했고, 합성 길이 초과 뒤 실제 재시도에서도 회상을 반복하지 않고 다음 작업으로 이어지는 것을 확인했다. 이 검증의 모든 결과를 보존했으며 성공한 응답만 골라 전체 비교 점수를 올리지 않았다.

## 실행 방법

```powershell
python -m pytest -q
python -m scripts.estimate_experience_evaluation --output-dir memory-eval-runs/experience-dry-run
python -m scripts.benchmark_experience_memory --output memory-eval-runs/experience-benchmark.json
python -m scripts.evaluate_memory_quality --mode mock --group experience --experience-mode enabled --cases tests/fixtures/conversation_experience/cases.json --output memory-eval-runs/experience-mock.json
```

실제 평가에는 `--mode live`, 실행 당시의 응답·임베딩 모델, `--max-api-requests`, 공통 `--ledger`가 필요하다. 키는 `ENE_EVAL_LLM_KEY`, `ENE_EVAL_EMBEDDING_KEY` 환경 변수로만 전달한다. 기준선과 후보를 별도 CLI 프로세스로 돌리면 메모리 내 임베딩 캐시를 공유하지 않으므로 아래 예상량을 그대로 적용할 수 없다. 동일 프로세스에서 `evaluate(..., embedding_cache=shared_cache, budget=shared_budget)`를 순차 호출한다. 응답은 재사용하지 않는다.

```powershell
python -m scripts.review_memory_quality --suite experience --report memory-eval-runs/candidate.json --review memory-eval-runs/candidate-review.json --create-template
python -m scripts.review_memory_quality --suite experience --report memory-eval-runs/candidate.json --review memory-eval-runs/candidate-review.json --baseline-report memory-eval-runs/baseline.json --baseline-review memory-eval-runs/baseline-review.json --manifest tests/fixtures/conversation_experience/approval_manifest.json --output memory-eval-runs/decision.json
```

검토 양식의 사례 전체 및 각 턴을 읽고 연결, 당시 반응, 현재 적합성, 회상 자제, 반복, 사실 근거, 현재 상태를 각각 판정한다. 생성된 정답 없는 양식은 자동 통과하지 않는다. 합성 평가 결과도 `memory-eval-runs/`에 두고 커밋하지 않는다.

## 비용과 성능

모든 평가와 복구 검증을 종료한 실제 API 호출은 **1,048/1,074회**다. 이번 승인분 시작점 774회 이후 274회를 사용했고, 잔여 26회는 사용하지 않았다. 실제 모델·단계별 공통 원장 집계는 아래와 같다.

| 모델 | 이번 승인분 사용 | 누적 |
|---|---:|---:|
| `gemini-3.8-flash` | 229 | 653 |
| `gemini-embedding-2` | 45 | 395 |
| 합계 | 274 | 1,048 |

Flash의 이번 229회는 응답 227회·요약 2회이며, 누적 653회는 응답 649회·요약 4회다. 임베딩의 이번 45회는 검색 42회·검토 후 저장 3회이며, 누적 395회는 초기 기억 90회·검색 299회·검토 후 저장 6회다. 앞선 수정본의 평가·중단·재시도도 포함하며 실제 전송 직전에 합산했다. 응답은 재사용하지 않고 같은 임베딩 입력만 캐시로 재사용했다. 이전 별도 작업의 306회 승인은 사용하지 않았다.

호출 구간은 이전 평가 770회, 첫 진단 4회, 이번 고정 전체 재평가 213회, 마지막 복구 진단 19회, 영향 검증 36회, 후속 턴 복구 검증 6회다. 이번 승인분은 마지막 네 구간의 합계 274회다. 보고서와 원장은 Git에서 제외한 `memory-eval-runs/experience-live-20261024/`에 보존하며 `response-recovery-final.json`에 검증 범위와 최종 사용량을 분리 기록했다.

## 남은 한계

현재 버전은 저장된 발화에서 요청마다 구간을 고른다. 긴 세션에서 표현이 크게 바뀌거나 주제 전환이 암묵적이면 적절한 구간을 놓칠 수 있다. 명시적인 주제 전환은 분리하지만 대화 사건을 완전하게 분류하는 별도 모델은 없다. 후보 제한 때문에 관련 경험을 모두 검사하지 않는다.

출처가 정확히 전달돼도 최종 답변이 활용하지 못할 수 있다. 최신 고정 비교가 남긴 생성 실패는 후속 복구 검증에서 해결됐지만, 기존 날짜 추론 관찰 오류 1건은 남아 있다. 원래 실패를 보존하고 마지막 복구 수정은 전체 비교와 구분해 검증했다. 합성 평가 통과가 실제 저장소의 모든 복잡도나 사용자 체감 자연스러움을 보증하지 않는다. 같은 실패 문항을 반복 실행해 통과 응답만 선택하지 않는다. 새 영구 경험 데이터베이스와 추가 판단 모델은 이번 범위에 포함하지 않는다.
