# 메모리 상태 갱신과 회상

## 목적

현재 유효한 사용자 정보와 과거 경험을 구분한다. 새 대화가 이전 정보를 정정하면 현재 상태를 갱신하되 이전 값과 출처를 남긴다. 구체적인 과거 내용은 원문으로 확인하고, 요약 이후에도 최근 대화의 흐름을 유지한다.

OpenAI의 공개된 메모리 합성 개념에서 영감을 얻었지만, 이 문서는 ENE의 구현을 설명한다. 외부 서비스의 내부 저장 구조를 재현한 것은 아니다.

## 저장과 호환성

- 장기 기억은 기존 `MemoryEntry`에 요약과 발화자·시각·대화 ID·순서가 있는 원문을 저장한다.
- 사용자 프로필은 기존 `facts`, `basic_info`, `preferences`를 유지한다. 사실에 `id`, `subject`, `state`, `effective_at`, `source_memory_id`, `history`를 추가한다.
- 기존 사실의 ID는 분류·기록 시각·내용에서 결정적으로 생성한다. 파일을 읽는 것만으로 기존 데이터를 다시 쓰지 않는다.
- 주제 기억은 기존 대상별 상태와 이력에 `effective_at`을 추가한다.
- 새 버전은 추가 필드가 없는 기존 파일을 읽는다. 새 필드가 저장된 파일을 이전 버전 앱에서 읽는 역방향 호환성까지 보장하지는 않는다.
- 사용자 런타임 JSON은 소스 저장소에 커밋하지 않는다. 구현·검증 중 실제 프로필이나 대화를 일괄 재작성하지 않는다.

## 사용자 프로필 갱신

기존 요약 출력에 선택적 `[PROFILE_UPDATES]` JSON 배열을 추가한다. 파서는 기존 반환 형태를 유지하고 `memory_meta.profile_updates`에 변경안을 전달한다.

변경안의 필드는 다음과 같다.

| 필드 | 의미 |
|---|---|
| `category`, `content` | 검토 화면의 사용자 사실과 일치하는 분류·내용 |
| `subject` | 같은 사실을 식별하는 안정적인 대상명 |
| `replaces` | 교체할 기존 사실 ID. 신규라면 빈 값 |
| `state` | `active`, `completed`, `cancelled`, `paused` |
| `assertion` | `current`, `historical`, `uncertain` |
| `effective_at` | 명시된 효력 발생 시각. 없으면 원문 배치의 관찰 시각 |
| `evidence` | 이번 사용자 원문에서 확인할 짧은 근거 구절 |

자동 변경은 현재 진술로 분류되고 실제 사용자 원문에서 근거가 확인되어야 한다. 조수의 발언만 근거로 한 변경, 과거 회상, 불확실한 진술, 현재 상태보다 오래된 효력 시각, 미래 시각은 적용하지 않는다. 날짜 경과만으로 완료를 추정하지 않는다.

교체 대상 ID가 사라졌다면 뒤늦은 요약이 삭제된 사실을 다시 만들지 않는다. 동일 내용·상태의 재처리는 이력을 늘리지 않는다. 더 최근에 같은 상태를 확인한 경우에는 효력 시각과 출처를 갱신하여 그보다 오래된 변경이 뒤늦게 적용되지 않게 한다. 명시적으로 연결되지 않은 비슷한 문장을 길이만으로 덮어쓰지 않는다.

기존 값과 출처는 `history`에 보존한다. 해당 사실에서 생성된 선호·기본 정보는 변경 시 함께 정리하고, 무관한 수동 값은 유지한다. 사용자와 ENE의 프로필 저장소는 별도로 유지한다.

변경 메타데이터가 없는 구형 자동 요약은 원문·요약을 저장하되 사용자 프로필을 자동 변경하지 않는다. 잘못된 JSON 변경안도 빈 변경안으로 처리한다. 수동 검토한 구형 사실은 기존 추가 경로를 사용할 수 있다.

## 수동 검토와 설정 편집

수동 요약은 체크된 사실만 반영한다. 편집한 사실은 해당 행의 기존 대상 연결을 유지하되 사용자가 검토한 경로에서만 수동 정정으로 적용한다. 새 변경안이 포함된 요약은 행별 상태 선택도 반영한다. 원래의 숨겨진 변경안이 편집 내용을 덮어쓰지 않는다.

설정 화면의 불러오기와 저장은 추가 메타데이터를 유지한다. 사실을 편집하면 이전 값을 이력에 남기고, 상태도 직접 선택할 수 있다. 편집·삭제 시 연결된 선호와 기본 정보도 함께 정리하며 별도 수동 값은 보존한다.

기존 ‘프로필 정리’ 기능은 변경하지 않은 사실의 메타데이터를 보존한다. 같은 ID의 문장을 다듬는 경우에도 상태와 대상 연결을 유지하고 이전 문장을 이력에 남긴다. 여러 사실을 하나로 합치는 경우에는 기존 ID를 유지할 대표 항목을 요약 모델이 선택하므로 결과 검토가 필요하다.

## 주제 기억

자동 요약에서도 사용자 근거가 확인된 현재 상태 후보를 저장한다. 수동 검토 후보는 기존 확인 절차를 유지한다. 기존 `keyword`, `subject`, `type`을 재사용하도록 추출하며, 같은 대상의 이전 상태는 이력으로 이동한다. 효력 시각이 더 오래된 후보는 무시하고, 같은 상태를 재확인하면 이력 추가 없이 최신 확인 시각과 출처만 반영한다.

## 원문 회상

기존 활성화·유사도 검색 후보 안의 원문을 찾는 경로를 유지한다. 여기에 질문의 강한 단서가 원문에 나타나는 구간을 로컬에서 추가로 찾는다. 질문 끝의 일부 한국어 조사를 정규화하고 영문·숫자가 섞인 식별자를 강한 단서로 취급한다. 첫 검색 후보가 비어도 원문 회상은 가능하다.

추가 후보는 요청한 원문 개수의 세 배로 제한한 뒤 기존 순위화에 넣는다. 전체 원문을 임베딩 서비스로 보내지 않는다. 질문과의 단어 일치나 의미 유사도가 부족한 구간은 제외한다. 최종 컨텍스트에는 출처 기억 ID와 원문 시각을 표시한다.

답변 지침은 사용자 정정·검증된 최신 상태를 우선하도록 하고, 과거 원문은 당시 기록으로 해석하도록 한다. 과거를 묻는 질문에는 그 시점의 기록을 사용한다.

중요·관련·최근 기억에 같은 기억 ID가 중복되면 요약은 한 번만 넣는다. 같은 기억의 원문은 세부 근거 역할이 있으므로 별도로 회수할 수 있다.

## 요약 후 대화 연속성

요약된 메시지는 저장 대기 버퍼에서 제거한다. 최근 최대 여섯 발화는 별도 대화 컨텍스트에 남겨 재요약을 피하면서 다음 답변에 사용한다. 앞부분이 조수 발화로 시작하면 사용자 발화부터 남긴다.

요약 중 들어온 새 메시지는 보존한다. 응답 후 히스토리 재구성이나 리롤 폴백에서도 최근 요약 대화를 포함한다. 명시적인 대화 초기화 시에는 이 최근 대화도 지운다.

수동 요약 생성·검토 중에는 자동 요약을 시작하지 않는다. 처리 중인 자동 요약도 중복 실행하지 않는다. 원문 버퍼가 바뀐 뒤 도착한 오래된 결과는 현재 대화에 저장하지 않는다.

## 검증과 유지보수

가상 데이터로 다음을 검증한다.

- 짧은 정정문과 계획 취소 반영, 이전 이력과 파생 선호의 일관성
- 과거 회상·조수 발언·잘못된 근거·구형 자동 추출에 의한 프로필 변경 차단
- 선택 해제·수동 편집·설정 저장과 메타데이터 보존
- 오래된 주제 상태와 반복 저장에 의한 상태 역전·이력 중복 차단
- 첫 검색 후보 밖의 원문 회상, 무관한 원문 제외, 추가 임베딩 후보 제한
- 요약 중 새 메시지 및 요약 후 후속 응답·리롤의 대화 연속성

집중 검증은 `tests/test_profile_updates.py`, `tests/test_memory_state_summary.py`, `tests/test_memory_state_integration.py`, `tests/test_profile_metadata_editor.py`와 기존 메모리·요약·브리지 테스트를 함께 실행한다. 공통 동작 수정 이후에는 전체 `python -m pytest -q -p no:cacheprovider`도 실행한다.

2026-09-22 Windows·Python 3.12.10 환경에서 전체 테스트 4,109개 통과, 1개 건너뜀을 확인했다. 변경 Python 파일의 Ruff 기본 검사(`E9,F63,F7,F82`)와 공백·UTF-8 검사도 통과했다. 실제 외부 모델을 호출한 대화 품질 검증은 별도로 필요하다.

## 현재 한계와 다음 개선

- 현재 진술인지, 같은 대상인지 판별하는 의미 분석은 요약 모델에 의존한다. 원문 구절 검증은 출처의 존재를 확인하며 의미 해석의 정확성까지 증명하지는 않는다.
- 원문 보완 검색은 단어 단서를 사용하므로 표기가 크게 다른 질문은 놓칠 수 있다. 실제 품질 평가 후 검색 확장을 판단한다.
- 기존 프로필을 한 번에 자동 재분류하는 작업이나 별도의 주기적 합성 서비스는 도입하지 않는다. 새 요약부터 갱신 규칙을 적용한다.
- 다음 단계에서는 변경 이력을 직접 찾아보고 복원하는 화면, 실제 모델별 평가, 원문 검색 색인을 검토할 수 있다.
