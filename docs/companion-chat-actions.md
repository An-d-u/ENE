# 휴대폰에서 마지막 대화 수정·리롤

이 기능은 PC ENE와 Android 동반 앱 양쪽이 `chat_actions_v1`을 지원할 때 사용할 수 있다. APK만 업데이트하지 말고 같은 기능이 들어 있는 PC 코드도 적용한 뒤 ENE를 재시작한다. 기존 등록·대화·Core·모델은 지우지 않는다.

## 사용 범위

- 마지막 공개 사용자 메시지에는 **수정**, 해당 ENE 답변에는 **리롤**이 표시된다. PC에서 보낸 메시지와 휴대폰에서 보낸 메시지 모두 대상이다.
- 수정은 공개 텍스트만 바꾸고 PC의 기존 첨부를 유지한다. 휴대폰에서 첨부를 교체하지 않는다.
- 과거 대화, 선제 대화, 파일 명령, 재실행 입력이 없는 복원 기록은 대상이 아니다. 모바일 편집 한도는 UTF-8 16,384바이트다. 큰 PC 원문은 PC에서 수정한다.
- 처리 중에는 새 메시지·수정·리롤을 동시에 접수하지 않는다. 버튼은 같은 대상에 비활성 상태로 남고 사유를 안내한다.
- 성공하면 동일한 공개 메시지 ID를 교체한다. 실패하면 기존 쌍과 내부 재시도 문맥을 복원한다. 오류 안내를 새 답변 옆에 중복해서 추가하지 않는다.
- 수락된 조작만 이전 음성을 중단한다. 거절·중복 요청은 재생을 중단하지 않으며 실패 복원 후 이전 음성을 자동 재생하지 않는다.

## 끊김과 초안

편집 초안은 일반 입력창과 분리된 앱 메모리에만 있다. 실패한 초안은 다시 열 수 있지만 앱 프로세스 종료·등록 해제·새 페어링 완료 시에는 보존하지 않는다. 다른 대화나 다른 대상에 자동 적용하지 않는다.

연결이 끊기면 같은 요청 ID로 처리 상태만 조회한다. 수정·리롤을 자동 재전송하지 않는다. 결과가 불명확하면 새 대화 전체를 확인한 뒤 사용자가 직접 판단한다. PC 실행 ID 또는 대화가 바뀌면 이전 요청을 넘겨 실행하지 않는다.

완료 알림만으로 버튼을 활성화하지 않는다. 완료 뒤 새로 캡처하여 전송한 대화와 `query_id`·`snapshot_id`·revision·event 순서가 일치해야 확인 잠금을 해제한다. 음성·캐릭터는 별도 기능이며, 같은 모델에서 대화만 바뀌었다고 모델을 다시 다운로드하지 않는다.

## 유지보수와 검증

통신 명세는 [chat_actions 계약](../contracts/companion/v1/chat_actions.md)이다. PC와 APP의 계약 JSON은 같은 바이트를 유지한다. 기본 프로토콜 버전은 1이고, 구형 앱에는 새 확장을 보내지 않는다. 구형 PC에 연결한 신형 앱은 기존 전송을 유지하며 업데이트 안내를 표시한다.

주요 회귀는 `tests/test_companion_chat_actions*.py`다. 실제 Qt 소유권·루프백 TLS/WSS·원장 중복 방지·실패 복원·음성 격리를 합성 AI/TTS로 검사한다. 실제 provider를 호출하거나 실제 사용자 대화를 fixture로 쓰지 않는다.

실제 Android 설치·LAN 인수·회전·글자 확대·접근성·장시간 연결 시험은 별도다. Live2D 출시 허가 확인도 이 기능 구현의 완료 범위가 아니다. 완성 APK·Core·SDK·모델의 공개 업로드는 하지 않는다.

로컬 검증: Python 3.11·3.12 각각 전체 4,385개 통과, 기존 Windows 심볼릭 링크 권한 제한 1개 제외. `ruff check . --select E9,F63,F7,F82` 통과. Android 전체 JVM 346개 통과, lint 오류 0(기존 경고 4개), 개발·계측 APK 빌드 완료. 실제 기기·외부 provider 시험이나 원격 CI 통과를 의미하지 않는다.
