# 기억 품질 1단계

이번 변경은 프로필 교체 승인, 관련 프로필 선별, 생략된 후속 질문의 기억 검색을 개선한다. 저장 파일을 일괄 변환하거나 새 모델·데이터베이스를 추가하지 않는다.

실제 모델 평가 중 Gemini 임베딩 배치 입력이 하나의 벡터로 합쳐지는 기존 문제도 수정했다. 각 문장을 별도 `Content`로 보내고 입력·벡터 개수가 일치하는지 검사한다. 이는 [Google의 입력별 임베딩 계약](https://ai.google.dev/gemini-api/docs/embeddings)에 따른다. 과거에 합산 벡터가 저장됐을 가능성은 이번 코드 수정만으로 복구되지 않는다. 기존 사용자 저장소의 재임베딩은 별도의 데이터 점검과 호출 예산으로 진행해야 한다.

## 동작

- 검토 서버가 제안마다 식별자와 기존 사실의 지문을 보관한다. 대상 이름을 바꾸려면 별도의 정정 동의가 필요하다. 모델 제안의 일반 승인은 수동 편집으로 취급하지 않는다.
- 기존 사실이 검토 도중 변경되거나 삭제되면 해당 행의 승인을 해제한다. 임베딩을 기다린 뒤 저장하기 직전에도 다시 확인한다.
- 요약, 사용자 프로필, ENE 프로필, 주제, 생활 기록 등록을 나눠 저장한다. 부분 실패 후에는 저장한 요약을 재사용하고 실패 단계만 다시 저장한다. 생활 기록 매니저가 원래 없거나 사용 불가능하면 해당 단계는 건너뛴다. 앱 재시작을 넘는 트랜잭션 복구는 지원하지 않는다.
- 답변에는 현재 질문과 관련된 사용자 사실을, 요약에는 이번 사용자 원문과 관련된 기존 사실을 우선 넣는다. 완료·보류·취소 상태도 필요하면 포함한다. 사용자 사실 설정값 `0`은 기존처럼 무제한이다.
- 최근 사용자 발화에 대상이 하나로 확인되고 최신 질문이 좁은 회상 표현에 해당할 때만 보완 검색을 한 번 한다. 여러 대상, 주제 전환, 인용·부정·가정, 조수만 제시한 대상에는 보완하지 않는다. 대상 없는 새 사용자 발화가 끼면 연결을 단정하지 않는다.
- 보완 기억의 원문과 기존 어휘 폴백 원문을 합쳐 추가 임베딩 전에 `max_raw_chunks_in_context × 3`개로 제한한다. 원래 주 검색 후보의 원문 처리 방식은 유지한다.
- 후보 검색에서는 사용 횟수를 늘리지 않는다. 최종 컨텍스트에 선택된 검색 기억과 원문의 ID 합집합만 기록한다. 같은 요청의 자동 재시도는 중복 집계하지 않고 새 리롤은 새 요청으로 취급한다.

구형 빈 대상명도 자동으로 다른 대상과 합치지 않는다. 검토 화면에서 대상 연결을 확인해야 한다. 구조화된 사용자 근거가 없는 모델 행은 자동 승격하지 않으며, 실제 사용자의 편집 또는 직접 추가와 구분한다.

## 평가 실행

모든 사례는 가상의 물건·작업으로 구성했다. 기본 자료 40개와 알고리즘 조정에 사용하지 않는 확인 자료 8개가 있다. 실제 대화, 프로필, 사용자 프롬프트를 복사하지 않는다.

```powershell
python -m scripts.evaluate_memory_quality --mode mock --cases tests/fixtures/memory_quality/cases.json --output memory-eval-runs/phase1-mock.json
python -m scripts.evaluate_memory_quality --mode mock --cases tests/fixtures/memory_quality/holdout.json --output memory-eval-runs/holdout-mock.json
```

`mock`은 외부 HTTP와 소켓 연결을 막고 임시 저장소·기본 프롬프트를 사용한다. 임베딩 대역은 정답을 읽지 않는 어휘 해시다. 요약 대역은 원문 보존만 시험한다. 따라서 mock의 근거 회수 성공은 모델의 요약·정정·답변 품질 성공을 뜻하지 않는다.

실제 실행에는 `ENE_EVAL_LLM_KEY`, `ENE_EVAL_EMBEDDING_KEY` 환경 변수를 현재 프로세스에 제공한다. 키를 명령줄 인자나 보고서에 넣지 않는다. 제공자와 모델은 ENE 설정에서 확인한 값을 명시한다.

```powershell
python -m scripts.evaluate_memory_quality --mode live --cases tests/fixtures/memory_quality/cases.json --output memory-eval-runs/live.json --provider gemini --model <ENE의-응답-모델> --embedding-provider gemini --embedding-model <ENE의-임베딩-모델> --max-api-requests 200 --ledger memory-eval-runs/api-ledger.json
```

예산은 요청 직전에 기록하며 요약·응답·임베딩 및 SDK 재시도를 모두 센다. 같은 작업에서 여러 번 실행할 때는 같은 ledger를 순차적으로 사용한다. 프로세스 간 동시 실행은 지원하지 않는다. 상한 이후 요청은 보내지 않는다. 보고서의 `api_requests`와 `calls_by_model`은 ledger 누적 값이고 `run_api_requests`는 이번 실행 값이다. 이는 전송 시도 수이며 결제된 토큰 수가 아니다.

`--group`으로 평가군을 선택할 수 있고 `--repeat-critical 3`으로 관찰 사례를 제외한 사례를 반복할 수 있다. 실제 호출 예산 안에서 완료된 범위를 별도로 기록한다. 종료 코드 `0`은 실행·근거·금지 상태 변경 검사가 통과했다는 뜻이며, 답변 품질 승인까지 뜻하지 않는다. `2`는 실행 오류, `3`은 근거 누락·금지 변경·예산 소진이다.

## 보고서 판독

보고서는 Git 커밋, 자료 해시, 기본 프롬프트 해시, 평가 설정, 모델별 호출 수를 기록한다. `run_index`로 반복을 구분한다. 기본 설정은 평가용으로 고정하며 실제 앱의 개인 설정 전체를 복사하지 않는다.

- `raw_summary_outputs`: 모델 원본 요약 출력.
- `review_actions`: 사전 정의된 승인 동작의 실행·제안 누락·모호성.
- `storage`: 저장 결과와 단계별 상태. 검토 대상이 바뀐 경우의 차단도 확인한다.
- `state_grade`: 금지 덮어쓰기 검사와 정정 검사. 자연어 내용이 완전히 일치하지 않으면 `review_required`로 남겨 의미를 확인한다.
- `trace`: 선택 사실·기억·원문 구간, 활성화 후보, 임베딩 전 원문 후보, 제외 이유, 검색 호출 수. 원문과 벡터를 추적 객체에 넣지 않는다.
- `missing_evidence`: 사전 지정된 필수 근거의 누락.
- `answer`, `answer_grade`: 답변과 판정 상태. 자동 실행만으로 답변을 통과 처리하지 않으며 기본값은 `ungraded`다.

원본 제안, 승인 개입, 최종 저장 상태, 실제 답변을 구분해서 검토한다. 근거가 없는 답변, 다른 대상 덮어쓰기, 정상 정정의 불필요한 차단은 성공으로 집계하지 않는다. 정확한 과거 효력 구간을 묻는 시간 사례는 이번 단계의 관찰 항목이다.

결과 JSON과 화면 미리보기는 Git 제외 대상인 `memory-eval-runs/`에 둔다. 공유 시에도 실제 데이터나 키가 없는지 확인한다.

## 한계와 되돌리기

후속 질문 판정은 한국어·영어·일본어의 제한된 표현만 지원한다. 확인할 수 없는 생략 표현은 원래 검색으로 돌아간다. 전체 입력 토큰 상한, 시간 이력 재설계, 의미 중복 제거, 별도 검증 모델은 이번 범위가 아니다.

기본 프롬프트를 이용한 합성 평가는 개인화된 실사용 대화 전체를 대표하지 않는다. 모델 응답이 확률적이므로 단일 실행만으로 전반적인 품질 향상을 확정하지 않는다. 고정 시각 자료를 사용하지만 제품의 현재 시각 기반 가중치는 실행 시계에 영향을 받는다.

원래 코드로 돌아가려면 기억 품질 변경 커밋을 역순으로 검토해 되돌린다. 저장 데이터의 일괄 이관은 없지만, 이미 사용자가 승인해 저장한 정정까지 자동 취소되지는 않는다. 런타임 파일을 Git에 추가하거나 과거 코드로 덮어쓰지 않는다.
