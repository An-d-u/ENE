# 휴대폰 카메라 공유 계약

`camera_v1`은 페어링된 안드로이드 앱과 PC ENE가 함께 지원할 때 협상한다. 앱 채팅에서 사용자가 공유를 켜야 카메라를 연다. QR 연결, 앱의 카메라 권한, 수동 사진 첨부는 각각 독립적이다.

## 메시지와 이미지 전송

모든 제어 메시지에 기존 확장 규약의 등록 세대, 서버 실행 ID, 연결 세대, 대화 ID가 필요하다. PC는 인증된 전송 경로에서 보낸 기기를 판별한다. 앱은 연결 후 두 모드를 끈 상태로 첫 조회를 한다.

| 메시지 | 방향 | 본문 |
|---|---|---|
| `camera_share` | 앱 → PC | 공유 설정을 바꿀 때 증가하는 `generation`, 렌즈 `front` 또는 `back`, 두 모드 `question`, `observe` |
| `camera_state` | PC → 앱 | 같은 `generation`, 이미지 처리 가능 여부 `available`, 현재 관찰 권한 `observe_allowed`, 수신 모델 `model`과 원격 여부 `remote` |
| `camera_question` | 앱 → PC | `generation`, 일반 질문의 `request_id`와 `text`, 이번 요청 전용 `frame` |
| `camera_observation` | 앱 → PC | `generation`, 사용자가 관찰을 켠 휴대폰에서 로컬 변화가 감지된 장면 `frame` |

이미지는 `input_reserve`에 `purpose=camera`와 공유 세대를 지정해 예약하고 연결에 귀속된 HTTPS 업로드로 보낸다. `frame`에는 업로드 ID, SHA-256, 바이트 수, MIME만 담는다. 최대 크기는 1 MiB이고 JPEG의 긴 변은 1,280픽셀, 짧은 변은 720픽셀 이하다. 모델 전송 직전에도 동의와 연결의 유효성을 확인한다. 원본 프레임은 한 번만 쓰며 이미지 첨부 이력, 썸네일, 재전송 큐에 넣지 않는다. 보이는 답변 텍스트에는 기존 대화 기록 정책이 적용된다.

## 관찰 대상

PC 질문에는 선택한 PC 창, 앱 질문에는 그 휴대폰에서 선택한 카메라만 사용할 수 있다. 해당 기기에서 화면을 가져오지 못하면 일반 질문은 텍스트만 처리한다. 수동 사진이 있으면 기존 사진 첨부 흐름을 쓴다.

자동 관찰은 마지막으로 질문을 수락한 기기를 따른다. 해당 기기의 자동 관찰이 꺼져 있으면 다른 기기로 넘기지 않는다. 대화에 아직 질문이 없고 한쪽만 자동 관찰을 켰으면 그쪽에서 시작한다. 양쪽 모두 켰으면 첫 질문을 기다린다. 앱이 백그라운드로 들어가거나 연결이 끊기면 앱의 공유를 종료한다. 렌즈를 바꾸면 이전 렌즈의 이미지를 폐기한다.

## 공유 관찰 간격

PC와 앱은 `observation_intervals_v1`을 별도로 협상한다. 카메라 권한이나 공유를 켜지 않아도 페어링된 연결에서 이 설정을 조회하고 바꿀 수 있다. PC는 마지막으로 저장한 값을 보관한다.

- `observation_intervals_get`은 앱이 `query_id`로 현재값을 요청한다. `observation_intervals_set`은 같은 요청 식별 방식으로 `sample_seconds`와 `request_seconds`를 함께 제출한다. 각각 1~86,400 사이의 정수다.
- `observation_intervals_state`는 두 현재값, 저장 성공 여부 `saved`, 변경 순서 `revision`을 전달한다. 조회·저장 응답에는 해당 `query_id`가 있고, PC에서 먼저 보낸 변경 알림에는 없다. 저장에 실패하면 이전 확정값을 반환한다.
- 변화 확인은 기본 30초, 자동 판단용 모델 호출의 최소 간격은 기본 300초(5분)다. 설정 변경은 마지막 확인·호출 시각을 기준으로 다음 기회에 적용한다. 동일한 장면이나 사용자 대화 중에는 모델 호출을 건너뛸 수 있다. 직접 보낸 질문은 이 타이머를 기다리지 않는다.
